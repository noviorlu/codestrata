## 2026-09-30（用对比回答「codestrata 扫 gsplat 比扫 flask 多走了哪些代码」）

- **严重** 界面上答不出这个问题。模块图上 4 条跑到的边全是「两边都有」；点开边只列跨模块的函数和两边次数
  （`scan → cut` 的 `unit_dir` 125 对 24），模块内部的函数根本不出现，而差别恰恰都在里面：gsplat 那次多跑了 6 个函数
  （`scan` 里的 `canon`、`collect_docs` 里的 `paths_to_pkgs`、xref 的 `_strs` / `_u16` 等），flask 那次有 2 个 gsplat 没跑到。
  最后是写 Python 脚本直接对两个 `counts.json.gz` 做差才拿到答案。对比的数据（`cmp`）里只有节点和边，没有逐函数的 B 次数。
- **中** 按函数记录，长函数里的分支看不见：挂 C++/CUDA 附属文件的逻辑写在 `scan()` 里面，没有自己的函数，所以「扫 gsplat
  多走的路」里完全看不到它。函数粒度对长函数是盲的。
- **中** 小仓库的图很难看：codestrata 自己 20 个模块全在一个包里，排成细长的一竖列，两边大片空白，边全挤在中间。
- **中** 横幅上「未归到命名符号的调用 10527」这个数很大、没解释（生成器表达式、lambda 算在这里）；对 scan 这种大量用
  推导式的代码，它占了一半的调用。
- **低** `--phase` 切阶段时，触发的那个进程会停 0.1 s（`trace._PAUSE`，好让别的进程先跟着切）。有理由，但用户文档没写，
  而且确实改变了被录程序的时序：写浏览器测试时，loop 阶段开头 0.1 s 里一次调用都没有，差点当成 bug。
- **低** codestrata 自己的索引是旧的（4 个文件在上次 scan 之后改过），要看 run 详情才发现，没有提示「该重新 scan 了」。
- **低** `runs show` 把整条 PATH 原样打印（VS Code 扩展、`.kimi-code`、`.lmstudio` 之类的本机目录），又长又暴露本机环境。

## 2026-09-29（开发者自评 + 外部评价）

- **严重** 读 hot 图时我自己都要回想「调用方是最近的仓库内帧」：从框架事件循环回调进来的调用，看起来像是直接调用。界面上没有任何提示。
- **严重** 对比两个 run 只有三种颜色，要回答「两次差在哪」还得一条条点边看，没有清单。
- **中** 时间轴上 serving 只占整条的 4%（启动约 100 s），不点阶段按钮放大，几乎拖不动。
- **中** 读代码类功能越做越多（跳转定义、查找栏、搜索、JS 高亮器），但用户手边本来就有编辑器，这部分是在做一个更差的 VS Code。
- **中** 本仓库的解读每改一次代码就要花大量 token 刷新行号和哈希，写出来的东西人读不下去。
- **低** 开发过程中起了十几个 serve 进程从不清理；临时目录堆了几百个文件。
- **低** run 里有几个字段写了但没有任何代码读：`schema`、`sizes`（而且 `run.json` 那一项取在最后一次写入之前，值是错的）、
  `sha_of`、`sha_late`、`captured`、`git.dirty`、spans 索引里的 `pairing`。要么用起来，要么别写（见 `docs/design/run-format.md`）。
