## 是什么
`graph --link github --out 目录` 的导出器（M8.2）：导出一个静态站点目录，源码不内嵌，页面运行时按提交号从 GitHub 取（jsDelivr，不行再 raw.githubusercontent.com），在浏览器里用 `codestrata/web/hl.js` 高亮；codestrata 自己算出来的东西（每个文件的大纲和 Ctrl+点击的跳转、全仓的引用倒排、边详情、搜索索引、本地版本的原文）放在旁边的 data/<版本>/ 里按需取。公开入口只有 `export_site`，只被 `__main__` 的 `cmd_graph` 在 --link 分支里调用（__main__.py:137，`site` 在分支里才 import，__main__.py:141）；其余是 git / GitHub 的几个小工具（`github_origin`、`_differs`、`_reachable`、`_url`、`_git`）、一个文件的元数据（`_file_meta`）、输出目录的守卫（`_check_out` / `_clear`），以及前后端共用的桶号哈希 `fnv1a`。

**为什么要有它。** 单文件导出（`render.export`）把源码塞进 HTML，受单文件宿主（artifact 这类）16 MB 的上限，`export_payload` 的总预算是 1400 万（按 JSON 的字符数算，payload.py:1161）：vllm-omni 1600 多个文件只装得下两百多个（site.py:3）。而扫的仓库基本都在 GitHub 上：jsDelivr 和 raw 都允许跨域取，按提交号钉住的地址内容不会变，源码不必自己带；剩下的数据拆成小文件按需取，也就没有体积上限了，GitHub Pages（或者 Hexo 站点的 source/ 下）直接放。设计稿 M8.2 记的规模是 vllm-omni 的 index.html 约 2.8 MB。

输出目录（site.py:9 起的 docstring）：
```
<out>/
  index.html            图、解读、输入包、run 这些小的仍然内嵌；EMB.link 说从哪取源码、数据在哪
  .codestrata-site      标记：再导出到这里时认得出是自己的目录
  data/<提交号前 10 位>-<8 位十六进制摘要>/
    f/<序号>.json       每个文件：语言、行数（按扫描器的口径）、大纲、xref（Ctrl+点击的 token + 目标表）；
                        本地版本标 local，--public 没带原文的再标 unpublished
    src/<序号>.txt      本地版本的原文：GitHub 上那个提交里没有、或内容不一样的文件
    refs/<桶>.json      引用倒排：目标串 → {w: 定义位置, r: [[文件序号, 行, 列, 种类], …]}，按 FNV-1a 分桶
    attrs/<桶>.json     「同名的 .xxx」：成员名 → {same: 仓库里同名的成员几个, r: [[文件序号, 行, 起, 止, 种类], …]}
    edges.json          边详情（第一次点边时取）
    search.json         搜索索引（第一次搜时取）
```
序号是文件在 EMB.link.files 里的下标。EMB.link（site.py:311）另外带 owner / name / sha、prefix（扫的是子目录时它在 git 仓库里的相对路径）、code（取源码的地址模板，按顺序试）、blob（「GitHub ↗」的模板）、data（数据目录）、local / unpublished / stale 三组序号，以及 refBuckets / attrBuckets 两个桶数。

## 为什么这样切
三个已有模块的分工都没变，这个模式只在各自边上加了一点：
- `payload` 仍出图、解读、输入包、边详情、搜索索引这些数据，serve 和两种导出共用。为这个模式只加了一个开关 code=False（payload.py:1162）：不带符号片段、全文和共用的跳转目标表，也不跑按预算挑全文的那一段（payload.py:1228）。但有两样是 site 自己照着 payload 的形状另拼的，不是调 payload 拿的：每个文件的元数据（`_file_meta` 照 `file_view` 的形状，site.py:161），以及引用倒排的分桶（数据来自同一个 `xref.invert`；same 在这里照 `payload.refs` 的数法数好，合并、排序由 ds.js 在页面上照 `payload.refs` 再做一遍）。那边改了形状，这里要跟着改。
- `render` 仍只管「把前端和一份 payload 拼成一个 HTML」：hl.js 现在所有导出都带（render.py:30；边详情的代码片段也要它高亮），render 不知道 GitHub，也不知道目录。
- 这里收下所有和 git、GitHub、目录布局有关的东西：起 git 子进程、联网试取、写一棵目录树、认输出目录是不是自己的。这些放进 payload（serve 每个请求都要走的纯数据层）或 render（字符串拼装）都不合适。依赖方向因此是 site → payload / render / highlight，依赖它的只有 `__main__`。

前端照同样的切法：数据的布局只有 ds.js 的 linkedDs（codestrata/web/ds.js:189）知道。页面启动时看到 EMB.link，就把它的几个方法盖到 embedded 数据源上（codestrata/web/ds.js:145）：hasFile、file、source、outline、edge、searchIndex、refs，外加 linked 标记和 blobUrl；图、解读、run、输入包照旧读内嵌的。UI 代码只多认了几个字段：文件的 mismatch / local / unpublished、引用结果的 more、ds.linked / ds.blobUrl（见下文「前端」）。

## 关键算法
### 导出流程
`export_site` 按下面的顺序做：
1. **先看输出目录**（site.py:206）：`_check_out` 拒绝「不是空目录、又没有 .codestrata-site 标记」的 --out，也拒绝不是目录的。放在最前面，因为大仓库算一遍要几分钟，不能算完才说目录不对（site.py:184）。在这之前 `cmd_graph` 已经拦下了没给 --out、或者 --out 以 .html 结尾的（__main__.py:139）。
2. **GitHub 来源**（site.py:207）：`github_origin` 从 origin 解析出 owner / name，取 HEAD 的提交号、扫描目录在 git 仓库里的前缀，以及 staged / dirty / ignored 几个集合（见「本地版本」）。不是 git 仓库、origin 不在 github.com 上的，都是 `SystemExit`（site.py:66、site.py:78）。
3. **payload**：`export_payload(..., code=False)`（site.py:209）。
4. **文件表**（site.py:211）：index 的 files、aux（包目录里的 C / C++ / CUDA 文件）、docs 里挂的文档，三者取并集后排序。读不出来的（scan 之后删了）`_file_meta` 返回 None，不进文件表，页面上就不会以为它能打开（site.py:214）。`every` 的下标就是序号。
5. **本地版本**（site.py:229）：`local` = 没被 git 跟踪的 ∪ git status 列出来的 ∪ 内容和暂存区的 blob 不一样的（`_differs`）；`held` = 加了 --public 时 local 里被 .gitignore 忽略的（site.py:231）。
6. **试取**（site.py:233），见「试取 GitHub」。
7. **--public**（site.py:241）：`publicize` 对 payload 做一遍（M8.1，见 payload 的解读）。edges / search 在这之后才从 payload 里拿出去（site.py:243），所以它们也是公开过的。
8. **逐个文件**（site.py:249）：拿掉 `_text`；xref 标了 stale 的序号记进 stale（site.py:252）；本地版本标 local，没带原文的再标 unpublished，带的把原文放进 src。
9. **引用倒排和「同名」**（site.py:262 起），见「分桶」。
10. **本地原文里的主目录**（site.py:295），见「--public」。
11. **版本**（site.py:308），然后拼 EMB.link（site.py:311）。
12. **写出**：`_clear`（site.py:317）再核一次目录、先写标记，再删掉整个 data/ 和 index.html；接着逐个写数据文件（JSON 用紧凑分隔符），最后 `render.export` 写 index.html（site.py:337）。
13. **--public 兜底**（site.py:340）：所有写出去的文件再搜一遍主目录，搜到就把 data/ 和 index.html 删掉、`SystemExit`。

返回一份摘要，`cmd_graph` 打印页面和 data 的大小、桶数、源码从哪取、试取结果、带上的本地文件和没带的（__main__.py:147 起）。

### 钉提交号
取源码的地址里用提交号，不用分支名（site.py:27）：f/<序号>.json 里的行号、xref 的列号、大纲都是扫描时算的，只对得上扫描时的内容，分支却会往前走。按提交号钉住的地址内容也不会再变。这个提交号其实是导出时 `git rev-parse HEAD` 取的（site.py:79），不是 scan 时记下的：scan 和导出之间 HEAD 没动（通常的用法）时两者是一回事。scan 之后改过的文件另有两道防线：xref 按文件指纹判 stale（`xref_for`，payload.py:932），不给跳转；内容和 HEAD 不一样的走本地版本。

地址模板默认是 `CODE_BASES` 的两条（site.py:47）：jsDelivr 在前，raw.githubusercontent.com 在后。--code-base 可以换（可重复，按顺序试，__main__.py:645）。`_url`（site.py:130）拼上前缀和路径、逐段做 URL 编码；前端的 url()（codestrata/web/ds.js:223）同样逐段 encodeURIComponent。「GitHub ↗」用 `BLOB` 模板（site.py:49），末尾加 #L<行>。

### 本地版本：按 blob 哈希比，不只看 git status
页面默认从 GitHub 取源码，所以要找出「GitHub 上那个提交里的样子 ≠ 扫描时的样子」的文件，把它们的原文随页面带上（src/<序号>.txt）。`github_origin` 收集这几样（都换成相对扫描目录的路径，扫描目录以外的丢掉）：
- staged（site.py:86）：`git ls-files -s -z`，路径 → (文件模式, blob 哈希)。tracked 就是它的键。
- ignored（site.py:94）：`git ls-files -o -i --exclude-standard`，没被跟踪、而且被 .gitignore 忽略的。
- dirty（site.py:97）：`git status --porcelain=v1 -z --untracked-files=all` 列出来的。改名 / 复制的条目，-z 格式下原路径单独跟在后面一项，跳过（site.py:104）。

git status 看不出来的有两种，由 `_differs` 补上：
- **软链接**（模式 120000，site.py:118）：GitHub 上给的是链接指向的路径，不是源码；本地读到的（`read_bytes` 跟着链接走）是目标文件的内容。直接算本地版本。
- **skip-worktree / assume-unchanged**：git status 不报这种文件的本地改动。`git hash-object --no-filters --stdin-paths`（site.py:121）一次算出文件表里所有已跟踪、不是软链接的文件的 blob 哈希，再和 staged 里的比。加 --no-filters 是为了不走 clean 过滤（行尾转换之类），算的是磁盘上的原始字节。

注意 `ls-files -s` 给的是暂存区里的 blob，不是 HEAD 的，注释和 docstring 里写的「HEAD」不准。已经暂存、还没提交的改动，暂存区和工作区是一样的，`_differs` 看不出来；但 git status 会把它列出来，所以进了 dirty。两者合起来才等于「和 HEAD 比」。设计稿的变异检查记了一条：去掉模式检查时，软链接也会被哈希比对兜住，模式检查只是多加的一道。

### --public：被忽略的只带名字，本地原文里的主目录要换
- `held`（site.py:231）：加了 --public 时，本地版本里被 .gitignore 忽略的文件（可能是本地配置、密钥，site.py:18）不带原文。f/<序号>.json 照写，标 unpublished（site.py:257），不写 src；页面上打开它只说明「公开页没带」（codestrata/web/viewer.js:131）。文件名、符号名、xref 照带：这些是静态结构的一部分，图上本来就有（tests/test_runs.py:908 的注释）。不加 --public 时照样带上原文（自己看）。
- 被跟踪、GitHub 上本来就有的文件，原文不经过这里，页面直接从 GitHub 取；只有随页面带上的本地原文需要换主目录。做法（site.py:293 起）：含主目录的文件，先把每行 `html.escape`，连同这个文件的 xref.toks 包成一个假 payload 交给 `publicize`（site.py:300），由它的 code() 按「去掉标签、反转义」算列号、挪 toks（payload.py:1111）。先转义，是为了原文里的 < 不被当成标签去掉（site.py:294）。换完再反转义写回原文，挪过的 toks 写回 f/<序号>.json。test_site_export_public_local_home 断言：在换过之后的文本上，toks 的列号仍然正好指着 compute（tests/test_runs.py:861）。
- f/、refs/、attrs/ 下的数据不过 `publicize`，里面只有相对路径、名字和行列号；万一漏了什么，靠最后那道兜底：所有写出的文件都搜一遍主目录（site.py:340），用的正则尾巴和 `publicize` 一样（`(?![\w-]|\.[\w-])`）。

### 分桶：refs/ 和 attrs/
引用倒排和 serve 的 /api/refs 是同一份数据：`xref.invert`（经 `_inverted` 缓存，site.py:267）给出「目标号 → 引用它的地方」。每个目标写一行 {w, r}（site.py:273）：w 是定义位置 [文件, 行]，路径不换成序号；r 里的文件换成序号，不在文件表里的保留路径，前端的 fname() 两种都认（codestrata/web/ds.js:248）。**没被引用、但有定义位置的目标也写**（site.py:272 的 `lst or wh[tid]`）：引用栏最上面一条是定义本身，点一个谁都没用到的函数也要能给出这一行。test_site_export_edges 用 lonely.py 的 nobody_calls_me 断言它是 {"w": [...], "r": []}（tests/test_runs.py:898）。
- 桶数 = 整张表的 JSON 长度除以 `BUCKET_BYTES`（20 万，site.py:51），向上取整（site.py:275）；每次点击取一个桶，平均每桶不到 20 万字符（估算用的是带空格的 `json.dumps`、按字符数，写出时用紧凑分隔符，会小一些）。桶号 = `fnv1a`(目标串) % 桶数。
- **空桶也写**（site.py:276）：页面按桶号直接取，桶文件不存在就是 404，而 404 在前端的意思是「数据换了一版，要刷新」（见下文），不能拿来表示「这个桶里没东西」。测试断言 refs/ 下正好是 0 到 refBuckets−1 这些文件（tests/test_runs.py:893）。
- `fnv1a`（site.py:54）是 32 位 FNV-1a，按 UTF-8 字节算；前端的 fnv()（codestrata/web/ds.js:243）用 TextEncoder、Math.imul 和 >>>0 实现同一个算法。
- attrs（site.py:279 起）：xref 的 attrs（接收者类型拿不准的 `.xxx`）按成员名分桶，分法相同。每条带 same，即仓库里叫这个名字的成员有几个，数法和 `payload.refs` 一样（payload.py:1012）；区别是 serve 在查到某个名字时现数，这里一次把所有名字都数好。

### 按序号命名、按版本分目录、标记文件
- **用序号，不用路径**（site.py:24）：Hexo 会丢掉 source/ 下以 _ 开头的文件，__init__.py 的数据块会在部署时悄悄消失；路径里的特殊字符也省得转义。test_site_export 断言 data/ 下没有以 _ 开头的文件（tests/test_runs.py:828）。
- **版本目录**（site.py:308）：名字是提交号前 10 位加一个 FNV-1a 摘要。摘要的输入是提交号、文件表、带了原文的序号，以及 payload（已去掉 edges / search、按键排序）的 JSON 的前 200 万个字符。同样的输入导出两次得到同一个名字，文件表一变名字就变。`_clear` 每次删掉整个 data/（site.py:196），所以重新部署、版本名变了之后，还开着的旧页面取数据会 404，前端据此提示刷新（codestrata/web/ds.js:219），而不是拿新数据的序号去对旧页面的文件表、悄悄显示成别的文件（site.py:21）。前端另有一道：f/<序号>.json 里的 file 和页面文件表对不上，就报「数据和页面对不上」（codestrata/web/ds.js:280）。
- **标记文件**：`_clear` 先写 .codestrata-site，再删东西（site.py:195），这样这次中途断了，下次还认得出是自己的目录。它只删 data/ 和 index.html，同一目录里的其它文件不动。test_site_export 覆盖了几种情况：再导出到同一目录照常覆盖；别人的非空目录拒绝、里面的文件还在；--out 给 .html 拒绝（tests/test_runs.py:829 起）。

### 行数按扫描器的口径
`_file_meta`（site.py:161）的形状和 `file_view` 一样，只是不带 lines，由页面取回源码后自己高亮。文本用 `read_bytes` 再按 UTF-8 解码（坏字节换成 U+FFFD，site.py:165），不走 `read_text` 的通用换行：\r\n、单独的 \r 原样留在 src/<序号>.txt 里，页面拿到的本地版本和从 GitHub 取回来的一样是原始换行，由页面自己切行。n_lines 却按扫描器的口径数（site.py:176）：\r\n 和单独的 \r 都算换行。浏览器那边只按 \n 切（hl.js 把 \r\n 当作一个换行，\r 最后补回 token 里，codestrata/web/hl.js:280），所以含单独 \r 的文件，两边数出来的行数不一样，页面会判「和扫描时不一样」、不给跳转。这正是想要的结果：xref 的行号是扫描器把 \r 也当换行算出来的，照浏览器的切法，\r 之后的每一行都会错一行（site.py:174）。test_site_export_edges 用 b"x = 1\ry = 2\n…" 断言 n_lines 是 5（浏览器按 \n 切出 4 行是那一行的注释，没有断言，tests/test_runs.py:901）。

大纲：Python / Triton 用 index 的符号表（ast，含方法），其余用 `highlight.outline` 的词法大纲（site.py:169）。xref 直接取 `xref_for` 的结果：每个文件带着自己用到的目标表，不像单文件导出那样挪进共用表（payload.py:1202，那是为了省单文件的额度），因为这里 f/ 下的每个文件是单独取的。

### 试取 GitHub
提交没推上去的话，页面上会全是 404，所以导出时先试取一个文件（site.py:233）：挑文件表里第一个既不是本地版本、又不是空文件的（site.py:235），按顺序对每个地址模板发 GET，带 Range: bytes=0-0（site.py:146），超时 15 秒。
- 任何一个模板取到了，返回 True；416（范围不对，但文件在）也算取到（site.py:151）。
- 所有模板都是 404，返回 False，接着 `SystemExit`「这个提交推上去了吗？」（site.py:239）。
- 其它情况（没网、500、超时）返回 None：照样导出，`cmd_graph` 打一行警告（__main__.py:150）。
- 相对地址的模板（测试时指向站点自己的镜像）试不了，不算 404（site.py:142）。

--no-remote-check 整个跳过这一步（__main__.py:648）。test_site_export_edges 用一个本地 HTTP 服务模拟 GitHub，测了这几种分类（tests/test_runs.py:931 起）。

### 前端：ds.js 的 linkedDs 和 hl.js
**取源码**（text，codestrata/web/ds.js:227）：held 的直接拒绝并说明原因；local 的取 data/src/<序号>.txt；其余按 K.code 的顺序一个个试，前一个失败才试下一个，全部失败时把每个地址的错误一起报出来（codestrata/web/ds.js:239）。每个文件只取一次（once：失败了从缓存里删掉，下次重试，codestrata/web/ds.js:197）。源码请求走一个限流器（codestrata/web/ds.js:201）：同时最多 6 个，每个 20 秒超时（AbortController），因为引用列表一次可能要取上百个文件的原文。限流和计时都只管到响应头：fetch 一返回就让出名额、清掉计时器（codestrata/web/ds.js:212），接下来读正文不占名额、也不计时。data/ 下的 JSON（dj，codestrata/web/ds.js:215）不走限流器，同样只取一次；失败时把错误换成人话：用 file:// 打开的页面，浏览器不许按需取数据（codestrata/web/ds.js:218）；404 说明数据换了一版，要刷新（codestrata/web/ds.js:219）。

**全文**（file，codestrata/web/ds.js:275）：f/<序号>.json 加上原文，交给 hlLines 高亮；hl.js 没跑起来时退回只转义、不高亮（codestrata/web/ds.js:258）。**行数和 n_lines 对不上时**（codestrata/web/ds.js:284）：记下 mismatch，n_lines 换成取回来的行数，xref 换成 stale，viewer 在标题栏写「GitHub 上的这个文件和扫描时不一样：没给 Ctrl+点击」（codestrata/web/viewer.js:172）。本地版本标「本地版本」，不给「GitHub ↗」（codestrata/web/viewer.js:176）；「GitHub ↗」在按下时换成当前看到的那一行（codestrata/web/viewer.js:197）。不在文件表里的文件，viewer 说「不在扫描范围里」，而不是单文件导出那句「体积上限」（codestrata/web/viewer.js:124）。

**符号片段**（source(key, where)，codestrata/web/ds.js:296）：和 serve 的 /api/symbol 一样，从定义那一行起取 40 行，跳转只留这几行里的。EMB.pkgSyms 里只有包的顶层符号；方法、嵌套函数靠调用方给的 where（文件和行），到 f/<序号>.json 的大纲里找，找不到就用 where 的行号（codestrata/web/ds.js:301）。panel.js 为此把 where 传了进来（codestrata/web/panel.js:508）。source 给了 null、退回全文窗口时，这一步取文件失败会显示「读取失败」和原因（codestrata/web/panel.js:512，这次加的）。但链接模式下取 f/<序号>.json 或 GitHub 原文失败，多半是 source 自己 reject：走到原有的那个 catch，片段位置直接清空（codestrata/web/panel.js:546），不会停在「读取源码…」，也不说原因。另外 where.f 不在文件表里时 source 给 null、file 也给 null，面板说的仍是单文件导出那句「导出版的体积有上限，没带上这个文件」，链接模式没有改这句。

**引用**（refs，codestrata/web/ds.js:322）：取目标所在的桶，按和 serve 的 /api/refs 一样的规则合并（同一行的几处合成一条，调用在前）、排序；scan 之后改过的文件上的行标 stale。调用次数只在看的是主 run 时给（codestrata/web/ds.js:339），和边详情一样。桶里没有原文，所以列表先返回（原文是空的），定义那一行和前 200 行（TEXTS，codestrata/web/ds.js:270）的原文放进 res.more 里去取（codestrata/web/ds.js:360），每个文件取一次；viewer 等 more 完成后再画一遍（codestrata/web/viewer.js:311）。这样一个被一百多个文件用到的名字，不用等一百多个文件都下完才显示。类成员还会再取对应的 attrs 桶，列出「同名的 .xxx」；这一组取不到，不影响上面的引用（codestrata/web/ds.js:357）。

**边和搜索**：edges.json、search.json 在第一次用到时取。edges.json 和单文件导出内嵌的是同一份：切面上的边、只在 runtime 出现的边，以及图例里「仅类型」的边（payload.py:1224），所以打开那个开关后点得开。边详情仍走 edgeFrom（codestrata/web/ds.js:148），和单文件导出共用「换了 run / 只看静态图时拿掉调用明细」的处理；这次把它和 embeddedRefs（codestrata/web/ds.js:162）从 embedded 数据源里抽成了独立函数。

**hl.js**（codestrata/web/hl.js:1）是 `highlight` 模块（Pygments）的 JS 版：照抄 Pygments 的 Python 和 C / C++ 词法状态表（Triton 用 Python 那张，CUDA 用 C++ 那张，codestrata/web/hl.js:187；当前 Pygments 2.21 的 CudaLexer 也是 CppLexer 的子类），每个状态拼成一条粘连的大正则；匹配循环照搬 RegexLexer（codestrata/web/hl.js:192）；再做 `highlight._tokens` 里的 Triton / CUDA 重标和词法器自带的 C 类型重标（codestrata/web/hl.js:238）。detect / label 和 `highlight.detect` 规则相同（codestrata/web/hl.js:265）；lines 的输出和 `highlight.to_lines` 同形：第 N 个元素就是第 N 行，跨行的 token 在换行处闭合、下一行重开（codestrata/web/hl.js:275）。保真第一：token 文本原样取自源码，Pygments 去掉的 BOM 和 \r 最后原样补回（codestrata/web/hl.js:282、codestrata/web/hl.js:293）。连续空匹配到第 64 次就当没匹配，防止死循环（codestrata/web/hl.js:197）。hl.js 的正则字面量里用了后行断言（比如 codestrata/web/hl.js:10、codestrata/web/hl.js:262），不支持后行断言的浏览器（Safari 16.4 之前）解析这段脚本时就会整段报错。所以 `render.export` 把它单独放在一个 script 里（render.py:28 的注释）：和别的 JS 放在一起，出错时整页都没了；分开的话只是没有高亮。最初只有 payload 带 link 时才带它；后来边详情的代码片段也在浏览器里高亮，现在所有导出都带（render.py:30）。

### 怎么验的
- test_site_export（tests/test_runs.py:792）：git_repo（tests/test_runs.py:774）把 fresh() 的仓库做成 git 仓库，origin 设成 github.com/acme/fakesvc。改一个已跟踪的文件、加一个没跟踪的文件，scan、trace 之后用 --link github --no-remote-check 导出，然后查这些：EMB 里没有 files / sources / xrefTargets / edges / search（tests/test_runs.py:809）；link 的 owner / name / sha / prefix 正确，数据目录以提交号前 10 位开头；work.py 的 n_lines、语言、xref、大纲；local 正好是那两个文件（tests/test_runs.py:819），callee.py 的 src 里有本地改的那一行，work.py 没有 src；compute 的目标在 `fnv1a` 算出的桶里，引用里有 extra.py；data/ 下没有 _ 开头的文件。最后是几种目录和仓库：带标记的目录、别人的目录、.html、origin 不是 GitHub、根本不是 git 仓库。
- test_site_export_public_local_home（tests/test_runs.py:844）：本地原文里的主目录换成 ~，toks 的列号跟着挪，输出目录下每个文件都不含主目录。
- test_site_export_edges（tests/test_runs.py:868）：空桶、没被引用的定义、stale、含单独 \r 的文件的行数、软链接和 skip-worktree 算本地版本、--public 不带被忽略的文件（密钥的值不出现在任何输出里，tests/test_runs.py:909）、不加 --public 时照带，以及 `_reachable` 的五种情况。
- `tests/hl_parity.py`：hl.js 和 Pygments 对拍，需要 node。默认语料是 vllm-omni 包加 codestrata 自己（tests/hl_parity.py:34），外加一组手写的边角用例（CRLF、BOM、单独 \r、没闭合的字符串、emoji……，tests/hl_parity.py:38）。默认语料的 vllm-omni 路径写死成本机的绝对路径，换台机器要自己给目录。它查四项，任何一项不过退出码都非 0：文本保真必须 100%（每行去掉标签、反转义后和源码那一行一字不差，转义写法和 html.escape 一样）；行数等于 \n 的个数加一，也等于 `to_lines` 的行数；detect / label 和 Python 版一致；类名一致率 Python / Triton ≥ 95%、C / C++ / CUDA ≥ 85%（tests/hl_parity.py:36）。边角用例只卡保真，一致率只报不卡。不依赖 pytest，单独跑。

## 局限
- 只认 origin，也只认 github.com（`_GH_RE`，site.py:50）：GitHub Enterprise、GitLab、别的 remote 名都会被拒。提交必须推到 origin 上。
- 私有仓库：页面取源码不带任何凭据，jsDelivr 和 raw 都取不到私有仓库的文件。按代码推，导出时的试取会失败（如果全是 404，提示的是「没推上去」）；这一点没有实测。
- 页面要联网，而且要放在 http(s) 上：用 file:// 打开时浏览器不许按需取 data/，页面只给一句提示（codestrata/web/ds.js:218）。jsDelivr 和 raw 都取不到时看不了源码（随页面带上的本地版本除外），图和解读照常。
- 「和扫描时一样」只按行数核对：GitHub 上的内容行数相同、只是某一行不同的，照样给跳转。正常情况下不会遇到（提交号钉住了，不一样的都当本地版本带上了）。但 `_differs` 调 hash-object 失败时（返回码非 0）会静默跳过（site.py:123），这时 skip-worktree 文件的本地改动就会被当成「和 GitHub 一样」，只剩行数这一道防线。
- 提交号是导出时的 HEAD。如果 scan 之后换了分支、或提交了新改动再导出：内容变了的文件，xref 会按指纹判成 stale、不给跳转，但 Python 文件的大纲来自 index 的符号表，不会跟着判，行号可能偏（serve 的全文窗口也一样）。要准的话，导出前重新 scan。
- 版本摘要只覆盖提交号、文件表、带原文的序号，以及 payload 的前 200 万个字符（site.py:308）。如果重新导出时只有 f/、refs/、src/ 的内容变了（比如重新 scan 后 xref 变了，或者本地文件改了内容），目录名可能不变，还开着的旧页面就会读到新数据。序号和文件的对应关系有文件表保证，不会显示成别的文件。
- 只试取一个文件。一个候选都没有时（全是本地版本或空文件）就不试，但摘要里的 probe 仍是 "skipped"，`cmd_graph` 会打「没去试取（--no-remote-check）」（__main__.py:149），说法不对。
- --per-pkg 在这个模式下不起作用：code=False 时 `export_payload` 不取符号片段（payload.py:1215）。
- 引用列表最多只给 200 行（外加定义那一行）取原文（codestrata/web/ds.js:270），而且是按文件取整个文件：一个用得很广的名字，第一次打开时可能要下载上百个文件。原文是整批一起出来的：res.more 是这一批（定义、前 200 行，以及「同名」那组的前 200 行）的 Promise.all（codestrata/web/ds.js:360），viewer 只在它完成时重画一次（codestrata/web/viewer.js:311），所以其中一个文件慢，所有行都要等它（或者等它超时）。
- git 子模块里的文件：父仓库的 ls-files 不列它们，按代码它们都会被当成「没被跟踪」，随页面带上原文。加了 --public 大概也照带：父仓库的 `ls-files -o -i` 不进子模块，这些文件进不了 ignored。这两点都是读代码推的，没有测试。
- 浏览器解析不了 hl.js 时没有高亮（退回纯文本，其余照常）。高亮和服务端的差别见「不确定」。

## 不确定
- 设计稿 M8.2 写的是 hl.js「在 vllm_omni + codestrata 与 2.2 万个 C/C++/CUDA/Python 文件上逐字符、逐 token 类与 Pygments 一致」，README 写的是「和服务端 Pygments 逐字符一致」。但 `tests/hl_parity.py` 卡的是文本保真 100%、行数和 detect / label 一致，外加类名一致率 ≥ 95% / ≥ 85%，并不要求类名 100% 一致，实际跑出来的一致率仓库里也没有记录。逐字符（文本）一致有测试门槛兜着；逐 token 类完全一致，我确认不了。
- site.py 的注释说 staged 是「HEAD 里的 blob」（设计稿也写「按 blob 哈希和 HEAD 比对」），而 `git ls-files -s` 给的其实是暂存区的。按上文的分析，加上 dirty 之后结果和「与 HEAD 比」等价，但没有专门测「暂存了、还没提交」这种情况的测试。
- 为什么 jsDelivr 排在 raw 前面，代码和设计稿都没写。
- 浏览器验收的具体内容（测了哪些页面、哪些交互），设计稿里只有「前端 3 处在浏览器里抓到」这一句，仓库里也没有脚本，我没法核对。
