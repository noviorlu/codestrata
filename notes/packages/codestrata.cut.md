## 是什么
决定图上显示哪一层：scan 记下的是文件级的单元和目录树，这个模块在目录树上取一个**切面**（哪些目录展开、哪些收起），把单元汇总成切面上的节点和节点间的边，并按规模算出默认切面。它还给切面上短名撞了的节点起能分开的名字（`disambiguate`）。

## 为什么这样切
scan 早先在扫描时就按「二级包」聚合，粒度一旦定下来，图上就没法再往里看；大小悬殊的仓库也没有一个合适的固定深度——vllm-omni 里 version 只有 1 个文件，diffusion 有 580 个（cut.py:1 的 docstring）。把「显示哪一层」从扫描里拿出来之后，数据只有一份（单元级），切面只是一组展开着的目录名（`open`），展开 / 收起就是改这个集合、重新汇总，不用重扫。

它是叶子（不 import 任何内部模块），只吃 index 里的 `packages`（单元）、`edges`、`files`、`dirs`。`scan` 用它建目录树和默认切面，`payload` 用它汇总图、挂文件、给撞名的节点起别名，`seq` 和 `__main__` 用 `view` 把单元折到节点上，`notes` 用它确定一个解读目标底下有哪些文件，`serve` 用它判断一个名字是不是合法的节点。

撞名的判断放在这里而不是 layout 或前端：它要知道节点 id 在目录树里的完整路径、单根仓库的根包名、本层文件节点和它的目录是同一个名字——这些都是切面的知识；算一次放进 payload 的 `alias`，图上的标签、详情面板、抽屉标题读同一份，三处写的名字才一样。

## 读法
1. 模块 docstring 和顶上的五个常量（cut.py:17 起）——节点的三种形态、`open` 的含义、自动拆分的阈值
2. `dir_tree` —— 目录树的形状：每个目录的父目录、子目录、直接放在里面的单元
3. `node_of` + `_files_individually`（cut.py:63、cut.py:76）—— 一个单元在某个切面上落在哪个节点，整个模块的核心规则
4. `view`（cut.py:149）—— 在切面上汇总节点和边、重算高度
5. `disambiguate`（cut.py:176）—— 撞名的节点补几段父目录
6. `default_open`（cut.py:207）—— 默认切面怎么算
7. `units_of` / `node_files` / `parent_of` / `open_for` / `dir_node` —— 给别的模块用的查询

## 关键算法
### 三种节点和一条归属规则
- 收起的目录：id 就是目录的点分名（`vllm_omni.engine`），代表整棵子树；
- 本层文件：展开的目录里直接放着的文件多于 `FILE_LIMIT`（12）个、并且这个目录还有子目录时，这些文件合成一个节点，id 是 `<目录>.*`，它还能再展开到单个文件；
- 单个文件：id 是单元名。

`node_of` 从根往下走，第一个没展开的祖先目录就是这个单元的节点；全都展开了，就看它所在目录的直接文件是各自成节点还是合成「本层」。没有子目录的目录直接摊开到文件（cut.py:79）——否则展开它只会变出一个「本层」节点，等于没展开：vllm-omni 的 stage_input_processors 是 36 个平铺的文件，早先就点不开。

### 高度在切面上重算
`view` 把单元间的边折到节点上，节点内部的边丢掉，再按 `(出 − 入) / (出 + 入)` 算节点的高度。它只读 `edges`：scan 另记的 `type_edges`（只在 `if TYPE_CHECKING:` 里的 import）不是依赖，不进高度，由 payload 单独折到切面上。同一个目录收起时和展开后，它底下的东西高度可以差很多：vllm-omni 的 engine 展开后，本层文件在 +0.46，engine.duplex 却在 −0.41——收起时这个差别被平均掉了。

### 撞名：补到分得开为止
图上的名字只写点分名的最后一段，框里的节点还只写相对于框的部分。展开多了，同一张图上会出现两个 `app`（flask.app 和 flask.sansio.app）、两个 `kernels/`（vllm 的 kernels 和 model_executor.kernels）；框头离得远，只看节点分不出来。`disambiguate` 拿切面上画得出来的节点和所有框（payload 传进来的是 `visible` 加 `frames`），按最后一段分组，组里有两个以上的，从最后两段开始往前加，加到这一组里两两不同为止（cut.py:194）；路径本来就只有一段的，就还是那一段——所以浅的那个照旧叫 `app`，深的叫 `sansio.app`。没撞的不在结果里，照旧只写最后一段。

两条细节：
- 本层文件节点 `x.y.*` 和它的目录 `x.y` 算同一个名字（cut.py:188）。目录展开后自己成了框，本层文件节点就在这个框里；不合并的话，每个本层文件节点都会和自己的框「撞名」。它在框里照旧写「本层文件」，由 layout 保证。
- 单根仓库的根包名不算一段：图上的名字本来就去掉了根前缀，补上根名只会让 `pkg.app` 和 `pkg.sansio.app` 多一段没用的字。

别名跟着切面走：收起 sansio 以后只剩一个 app，就不再补。

### 默认切面：按规模贪心拆
`default_open` 从「只展开根目录」开始，反复在图上找代码量超过全仓 `SPLIT_FRAC`（10%）的节点，把其中最大的拆开，直到没有可拆的或节点数到 `MAX_NODES`（80）。两条例外：
- 拆开后会多出超过 `MAX_CHILDREN`（20）个节点的不拆（cut.py:231）——宽而平的目录通常是一族同类实现（vllm-omni 的 model_executor.models 有 44 个模型子目录，展开会变成 50 个节点），一下多出几十个节点没法读，内部结构交给详情面板的文件树；
- 节点少于 `MIN_NODES`（4）的小仓库不看比例，先把最大的拆开（cut.py:233），否则「所有代码都在一个子包里」的仓库只有一个节点。

vllm-omni 上它拆了 diffusion（41%，拆成 19 块）和 model_executor（29%，拆成 7 块），得到 58 个节点。给了 `depth` 就退回固定深度；`expand` 在结果上额外展开指定目录，并把它的祖先都展开（cut.py:247）——展开一个深处的目录而祖先收着，这个展开不会生效。

### 收起由前端算，规则来自 `parent_of`
`parent_of`（cut.py:138）回答「收起这个节点时要收起哪个展开着的东西」：本层文件节点收回它的目录；目录收回父目录；单个文件看它所在目录的直接文件平时是不是合成「本层」，是就收回那个本层节点，否则收回目录。`payload` 把它作为每个节点的 `parent` 发给前端，前端据此改 `open`：收回一个目录时，连同它下面所有展开的东西一起去掉，收回本层节点只去掉它自己。

### 让任意节点可见：`open_for`
`notes.prompt_pack` 要给展开出来的节点出输入包，得先有一个它可见的切面：`open_for`（cut.py:253）把目标的祖先全部展开、目标自己收起；目标是一个平时合在「本层」里的文件时，再把那个本层节点展开。邻居和高度都在这个切面上算。

## 不确定 / 局限
- 阈值（10%、20、80、12）是在 codestrata 和 vllm-omni 两个仓库上调出来的，没有在更多仓库上验证过。
- 自动拆分只看代码行数，不看依赖结构：一个行数不多但依赖关系很复杂的目录不会被自动拆开。
- 撞名按整个切面算：hot 视图只画跑到的节点，和它撞名的那个没画出来，名字也照样补过——这样两张图、面板里同一个节点叫同一个名字。
