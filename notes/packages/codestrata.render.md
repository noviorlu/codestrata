## 是什么
单文件导出：把 `codestrata/web/` 下的前端（`web/index.html` + `web/app.css` + 7 个 JS）和一份数据内联成一个 HTML，只读、离线、可以直接发给别人。只有一个函数 `export`，只被 `__main__` 的 `cmd_graph` 调用。M5 给前端加了第 7 个文件 `web/seq.js`（时序图），导出版也照样带上它，但导出版本身没有时序图（见「局限」）。M7（对比两个 run、一次导出多个 run）没有加新的 JS 文件，`render.py` 本身也没改：多出来的数据（EMB.hotBy、EMB.cmp）由 `export_payload` 组装，这里照旧整份 JSON 塞进去；新的行为全在前端的 ds / app / graph / panel 里，下面主要讲它们。M8（复刻命令、阶段表）同样没动 `render.py` 和脚本清单：要显示的东西都在 run 的 meta 里（导出里别的 run 靠 `_meta_brief` 带上），前端改的是 app.js（帮助里的显示、运行按钮旁的「复刻」、阶段按钮的悬停），外加 index.html 里那个按钮和 app.css 里几条样式，见「复刻和阶段表」。

## 为什么这样切
和 `serve` 用的是**同一套前端文件**，唯一的差别是数据源：serve 时前端 fetch /api/*，导出时读内嵌的 window.CS_EMBEDDED。切换由 `web/ds.js` 完成，UI 代码本身不感知（render.py:1）。数据怎么组装是 `payload` 的事（`export_payload`），这里只管打包——所以它不依赖任何内部模块。两种模式在「能做什么」上的差别也都收在 `web/ds.js` 里，不给导出版另写一套 UI：
- M4：serve 能在页面里换叠在图上的 run，导出版原本固定叠导出时那一个（一个「能不能换」的开关 canSwitchRun）。M7 起导出时可以带多个 run（graph --hot A --hot B），导出版也能换，但只在带上的那几个之间换（codestrata/web/ds.js:46）。于是 canSwitchRun 不再等于「是不是 serve」：凡是要认出导出版的地方——阶段按钮、「图」开关、对比按钮、「时序图看不了」的说明——改看 runs() 返回的 embedded 标记或 CS.ds.mode（codestrata/web/app.js:486、codestrata/web/app.js:502），不再借 canSwitchRun。不改的话，带了多个 run 的导出会冒出「模块图 | 时序图」开关（录过事件的 run 上「时序图」还能点，点了只得到一句错误），还有指向没带上的阶段的阶段按钮；
- M5：时序图只在 serve 里有。导出版的 ds 也有 seq / seqOverview / seqFind 三个入口，但一调就返回一个说明「导出的单文件没有带时序图；请用 codestrata serve」的错误（codestrata/web/ds.js:60）；工具栏上根本不出「模块图 | 时序图」，地址里带着 view=seq 打开也会退回模块图并弹类似的说明。所以时序图这块代码在导出版里是死的，但带上它只多 19 KB，换来 app.js 不用分两种写法；
- M7：对比。serve 里能在页面上选另一个 run 来比；导出版的对比是导出时 --compare 定好的，只显示、不能换（见下面「对比」「多 run 导出」）。

代价是**脚本清单要手工维护两份**：`web/index.html` 末尾的一串 script 标签给 serve 用，`SCRIPTS` 给导出用（render.py:17）。M5 两边都加了 seq.js，现在两份一致；没有测试核对这两份清单。漏了的后果看是哪个文件：
- `web/search.js` 漏了不会报错——`web/app.js` 里是「有搜索模块才初始化」，搜索栏和右上角的「搜索」按钮在 HTML 里默认都是隐藏的，导出版就只是悄悄没有搜索。
- `web/seq.js` 漏了就会报错：app.js 切视图时直接调 CS.seq.hide / show，不先看有没有这个模块（codestrata/web/app.js:525）。serve 里一点「时序图」就抛错；导出版平时走不到，但地址里带着 view=seq 打开时，启动会在这里抛错，整页显示「加载失败」。

## 读法
要读懂 `export`，得先知道它打包的前端长什么样（图上看不到，前端不是 Python）。整页是一个应用：上面一条（标题、统计、「?」；下一行是 运行 / 复刻 / 阶段 / 对比 / 图 / 边 / 视图 开关），图铺满剩下的全部空间、在自己的框里上下左右滚；其余都**浮在图上、半透明**：右上角的搜索栏、图下沿的详情栏，两个都能收起、拖边框改大小（记在浏览器里）。「图」那一组（模块图 | 时序图）只在 serve 里、叠着一个 run 时出现；模块图和时序图**共用同一个图框**，同一时刻只显示一张。

- `web/ds.js` —— 数据源层，整个前端只通过它拿数据。live 走 /api/*；embedded 读内嵌 JSON，另外补了导出版才需要的：判断某个文件带没带全文、在内嵌文件里自己找引用、把共用目标表里的 xref 目标补回每个文件。**当前叠哪个 run 也放在这一层**：CS.ds.run 存「完整 id@阶段」（空 = 只看静态图），live 的图、边详情、引用、输入包四种请求都自动带上 run=（codestrata/web/ds.js:129）——叠加会影响的就这四样，其余模块照旧调 ds，不知道有 run 这回事。时序图的三个请求（seq、seqOverview、seqFind，codestrata/web/ds.js:135）也用这个 run。M7 加了 CS.ds.cmp（对比的 run，同样存「完整 id@阶段」），只在 run 非空时跟着图和边详情两种请求带上 cmp=（codestrata/web/ds.js:125）——引用、输入包、时序图和对比无关，不带。请求失败时，错误信息优先用服务端返回体里的 error（「这个 run 没有录时序事件」「这个 run 里没有 a → b 的调用」），没有才退回「url → 状态码」（codestrata/web/ds.js:13）——时序图出错时整块显示的就是这句话，所以它得是人话。embedded 这边：canSwitchRun 看导出时带没带别的 run（codestrata/web/ds.js:46），只带一个的导出 run 一直是空；runs() 用内嵌的 hotMeta 加上 hotBy 里各 run 的简要 meta 拼列表，每行多一个 ref（「id@阶段」），整份标上 embedded（codestrata/web/ds.js:47），让启动走同一条路；graph() 按 CS.ds.run 在主 run、hotBy 里别的 run、静态图三者之间换（codestrata/web/ds.js:29），edge() 在换到别的 run、或者选了静态图时把调用明细拿掉（codestrata/web/ds.js:77），见下面「多 run 导出」
- `web/graph.js` —— SVG 绘图：泳道、框、节点、边、「＋ / −」展开收起。缩放：图左上角的 ＋ / － / 100%，或按住 Ctrl（Mac 上 ⌘）滚滚轮，以鼠标所在点为中心（触控板捏合在浏览器里也是 Ctrl+滚轮，顺带支持）；「✥」移动模式下按在哪都能拖图，拖完那次 click 在捕获阶段拦掉，不会误选节点。选中时只把看不见的节点滚到「可见区域」中间——详情栏盖住的那截不算可见。M5 加了一个 hidden()：模块图被时序图盖住时，滚动、缩放、聚焦都不做（见下面「两张图共用一个图框」）。M7 加了对比的三种颜色（见「对比」）
- `web/viewer.js` —— 全文窗口（逐行高亮 + 大纲）。Ctrl+点击名字跳到定义，旁边打开一栏：定义在最上面，下面是所有引用（按文件分组，调用 / 引用 / import）；点定义本身只开这一栏。跳转有「← 返回」栈，和编辑器的「转到定义 / 返回」一样。名字指向哪由 scan 时的交叉引用给出，这里只把能点的名字包一层 span
- `web/panel.js` —— 详情栏的左右两半：左边模块 / 边的机器事实（文件树、源码片段——片段里也能 Ctrl+点击），右边解读。搜索栏定位到某个文件 / 函数时，由它在文件树里展开并标出那一行。对比时次数写成「A n / B m」，边详情多出 B 的调用方和「只有 B 调到」一组（见「对比」）
- `web/search.js` —— 搜索栏：名字索引一次拿全，在前端打分排序，不来回请求。按**名字本身**找（函数看自己的名字、文件看文件名、模块看最后一段），词里带 `.` 或 `/` 才看路径——早先连路径一起匹配，搜目录名时出来的全是那个目录下的函数。点结果先在图上展开到所在模块并选中，再在详情栏里展开到它；`/` 或 Ctrl+K 随时回到搜索框；框里有字时图上包含命中的节点一直高亮，换切面后重新套
- `web/seq.js` —— 时序图（M5）：一个 run 里跨节点的调用按时间排开。生命线 = (进程, 当前切面上的节点)，消息 = 两个节点之间的一次调用。上面一条固定不动（窗口信息、时间刷、生命线头），下面一张 SVG 一行一条。数据来自 /api/seq：按切面映射、同一节点内部的调用不画、放不下时把重复片段折成 loop 行、自动收窄时间窗，这些都是服务端 `seq` 模块现算的，前端只负责画行和把点击翻译成新的请求
- `web/app.js` —— 启动，串起上面六个：切面（展开 / 收起、连点时只认最后一次、重画后尽量保留选中）、叠哪个 run（运行按钮、阶段按钮、URL hash，见下面「换 run」）、和哪个 run 对比（对比按钮，见「对比」）、两张图的切换和选中同步（见「两张图共用一个图框」）、详情栏、拖边框改大小的通用逻辑、「?」帮助。帮助里收着怎么读图、怎么操作，以及 hot 图的来历：复刻命令和各阶段怎么切的（M8，见「复刻和阶段表」）、case 命令、被 trace 的进程**按命令合并**（跑到仓库代码多的在前）、case 脚本的内容（录制时没存的标明是现在的内容）。统计那一行只留一个 hot 标记，点它打开帮助

`SCRIPTS` 的顺序就是依赖顺序：ds 被所有人用，viewer 定义了 panel 要用的 Ctrl+点击逻辑，seq 加载时只定义 CS.seq、用到 graph / app / ds 都在运行时，app 必须最后——见下面的 fragment 模式，它可能一加载就同步启动。

## 关键算法
### 拼装
读 `web/index.html`，把 stylesheet 链接换成内联的 `<style>`，用正则删掉所有外链 script 标签，再把「内嵌数据 + 按 `SCRIPTS` 顺序拼好的 JS」追加到末尾（render.py:31）。因为 script 标签是按正则整批删掉、再按 `SCRIPTS` 重拼的，index.html 里的顺序对导出版不起作用，两份清单各管各的。

### `</` 要转义
内嵌数据里的源码片段可能含 `</script>`，原样塞进 `<script>` 会提前结束脚本。`json.dumps` 之后把 `</` 换成 `<\/`（render.py:26）——在 JS 字符串里两者等价。

### fragment 模式
`fragment=True` 去掉 doctype 和 meta 外壳（render.py:36），给自己会包外壳的宿主（比如 artifact 页面）用。也因为这种宿主会在 DOMContentLoaded 之后才执行内联脚本，`web/app.js` 的启动写成了「已经加载完就直接启动」。

### 换 run（M4，只在 serve 里）
目标是不重启 serve 就能在「静态图 ↔ 这次 run ↔ 那次 run」之间来回切。
- **先定 run 再取图**（codestrata/web/app.js:324）：URL hash 里的 `#run=<id>@<phase>` → /api/runs 返回的 default（也就是 `serve --hot` 给的）→ 只看静态图。按 id 或 case 名在列表里找；找不到、或者还不能加载（没有计数：还在录或中断了），就退回静态图并弹一个浮层提示，而不是整页加载失败。两种情况说法不同（「找不到了（删了？）」/「还没有计数，还在录或要 runs merge」），因为该做的事不一样。提示不写进工具栏的进度那一行：图画好后 refreshStatus 的解读统计一回来就把那一行盖掉，所以改成图画完后弹浮层（codestrata/web/app.js:62）。/api/runs 本身失败时也照样把「已知 run」集合设成空（codestrata/web/app.js:354）——否则之后刷新列表时查这个集合会抛错、被 catch 吞掉，run 列表就一直是空的。地址里的 cmp= 也在这一步核（见「对比」）。
- **hash 里存解析好的完整 id**（codestrata/web/app.js:736）：图回来后按 hotMeta 把「run_id@阶段」写回 CS.ds.run 和 hash。case 名会随着重录指到新的 run，存 case 名的话刷新一下看到的就换了一个 run。
- **运行按钮**：显示 case 和录制时间，弹出的列表第一行是「静态图」，下面按 case 分组。每行：时间（悬停看完整 id）、tags、git 短哈希、活跃进程数、各阶段的函数数、录了时序事件的加「时序」标记、「⚠ 录制后改过 N 个文件」和「录制时安装包和仓库有 N 个文件不一致」；status 不是 ok 的行变淡并列出 problems；没有计数的行不能点，悬停提示去 runs merge。按钮右边叠着 run 时多一个「复刻」（见「复刻和阶段表」）。
- **阶段按钮**：当前 run 有两个以上阶段才出现（「全部」+ 各阶段）。从列表选一个 run 时，有 serving 阶段就先选它（codestrata/web/app.js:358）——启动阶段的初始化调用会淹没请求本身。M8 起按钮的悬停对 --phase 切出来的阶段多写一句从哪个函数开始（见「复刻和阶段表」）。
- **切换本身**（codestrata/web/app.js:362）：先让时序图作废在路上的请求、扔掉上一个 run 的时序数据和记下的那条消息、把时间窗退回新 run 的阶段起点（codestrata/web/app.js:364），再改 CS.ds.run（对比的 run 跟着调，见「对比」）、写 hash，然后拿当前切面调 setCut。于是换 run 就是「同一个切面再取一次图」：_cutSeq 丢掉晚回来的旧响应（codestrata/web/app.js:835），连着点几个 run 只认最后一个；keepSelection 让选中的节点 / 边换完还选着。换不过去（run 刚被删、还没有计数，setCut 返回 false）时把 CS.ds.run、CS.ds.cmp 和 hash 一起退回原来那个，并用浮层提示原因（codestrata/web/app.js:378）——不退的话，图还是旧的，之后取边详情、引用、输入包带的却是那个换不过去的 run。但如果这期间已经有更新的请求（_cutSeq 变了），就不退，免得盖掉后来的选择。设计里原本打算把 setCut 推广成 load({open, run, view})，run 放进 ds、view 用单独的 setView 之后就用不着了。
- **新录的 run**：窗口重新获得焦点时刷新列表（codestrata/web/app.js:624），有新的只在按钮上加个点，不自动切过去——正在看的图不该自己变；打开列表时点就消了。
- **换回静态图**：「只看跑到的」自动关掉（codestrata/web/app.js:578），不然节点会被全藏起来；这个开关连同帮助里的 hot 横幅一起藏掉。

导出版走同一段代码。只带一个 run 的导出，按钮是灰的（悬停说明要换请用 serve），也不监听焦点；带了多个 run 的，按钮能点，列表里只有导出时带上的那几行（见「多 run 导出」），焦点监听也照样挂上，但内嵌的列表不会变，等于不起作用。两种都不出阶段按钮（codestrata/web/app.js:596）。

### 对比（M7）
目标：在同一张模块图上看两个 run 走的路哪里一样、哪里分开。A = 当前叠的 run，B = 对比的 run。数字是服务端现算的（`graph_payload` 的 cmp 块：节点、边上各带 [A, B] 两个次数；`edge_compare` 给边详情每项加 calls_b），前端只管选 B、上色、写数字。
- **选 B**（codestrata/web/app.js:390）：工具栏的「对比」按钮只在叠着一个 run、列表里不止一个 run 时出现（codestrata/web/app.js:400）——静态图上没有「A」可比。弹出的列表第一行「不对比」，下面是除 A 以外、能加载的 run（codestrata/web/app.js:438），A 自己的其它阶段也不列。每行写的阶段就是 B 会用的阶段：**跟着 A 走**，A 看全部就比全部；A 看某个阶段、B 也有同名阶段就比它，没有就比 B 的全部（codestrata/web/app.js:453）。两个 run 的阶段切法不一定一样，按名字对齐是唯一不用猜的办法；对不上时退到「全部」，而不是不让比。
- **两个下拉不同时开**：点对比按钮先关运行列表，打开运行列表也先关对比列表（codestrata/web/app.js:640）。Esc 关掉对比列表、焦点还给按钮，监听挂在捕获阶段并拦住传播（codestrata/web/app.js:425）——否则同一下 Esc 还会被当成「取消选中」。按钮每次重画工具栏都重建，所以「点外面关闭」和 Esc 这两个 document 级的监听只挂一次，每次按 id 现找元素，不抓旧按钮。
- **选中之后**（codestrata/web/app.js:458）：改 CS.ds.cmp、写 hash，然后同一个切面再取一次图——和换 run 同一条路，连着点几次只认最后一次。取不到（setCut 返回 false）而且期间没有更新的请求时，把 cmp 和 hash 退回去、按钮重画。
- **换 A 时 B 怎么办**（codestrata/web/app.js:367）：A 换成静态图、或者换成 B 那个 run 本身，就不再对比（不能和自己比）；否则 B 按上面的规则换成和新 A 同名的阶段。在阶段按钮上换 A 的阶段时 B 也跟着换——A 看 serving、B 看全部，比出来的差别大半是阶段不同造成的。换不过去时 cmp 跟着 run 一起退回（codestrata/web/app.js:380）。
- **hash**：cmp= 跟在 run= 后面写进地址，没有 run 就不写（codestrata/web/app.js:319）。启动时先核一遍（codestrata/web/app.js:343）：找不到、还没有计数、和 A 是同一个 run 的同一个阶段，都不带上，图画完后弹浮层说「不能用来对比」或「找不到了」，并把它从地址里去掉（codestrata/web/app.js:63）。服务端还有一道：cmp= 找不到或者就是 A 时不 404，只叠 A、在返回里带 cmpError，前端收到就清掉 cmp、弹这句话（codestrata/web/app.js:739）。两道都要：前端的列表可能是旧的、case 名最终怎么解析只有服务端说了算；前端这道则能在发请求之前就说清是哪种情况。
- **记完整 id**：图回来后用 cmp.ref_b 把 CS.ds.cmp 换成「完整 id@阶段」再写 hash（codestrata/web/app.js:738），理由和 run 一样：case 名重录之后会指到别的 run，甚至指到 A 自己。
- **三种颜色**：只有 A 跑到是橙色（沿用 --hot），只有 B 跑到是紫色（新 token --hotb、--hotb-bg，明暗两套，codestrata/web/app.css:5），两边都跑到是前景色（--ink），两边都没跑到照旧退到背景。画的时候每条边带 E.ab（[A, B]）和 E.side（a / b / both，codestrata/web/graph.js:144），paint 按 E.side 选类名 warm / warmb / both 和箭头（codestrata/web/graph.js:402）；箭头是独立的 marker、不跟着线变色，所以多备了 ahb、ahf 两个（codestrata/web/graph.js:73）。节点同理（codestrata/web/graph.js:180）。
- **粗细和「跑到了」取两边的较大值**（codestrata/web/graph.js:123）：线宽、「只看跑到的」都按 max(A, B)，和服务端按 A∪B 排的 graphHot 一致。「只看跑到的」原来直接查 hot.packages（只有 A），现在 graph 另存一份 hitPk（codestrata/web/graph.js:128）给 vis() 查（codestrata/web/graph.js:381），否则只有 B 跑到的节点会在按 A∪B 排好的图上被藏掉、留下空位。
- **数字**：节点第二行写「A/B」（两边都没跑到就不写，codestrata/web/graph.js:187），边的悬停写「runtime 调用 A x / B y」。详情栏里，模块写「runtime A n / B m 次」（codestrata/web/panel.js:151）；依赖列表里每条边的小按钮按 E.ab 上色、动态边写「A/B 次」（codestrata/web/panel.js:140）——对比时 E.hits 是两边的较大值，拿它上色、写数，会把只有 B 跑到的说成 A 的。边详情抬头多一句「对比的 run：m 次」（codestrata/web/panel.js:534），每一项写「A n / B m」（codestrata/web/panel.js:38），下面多几行紫色的「B」，列出 B 里谁调了它（codestrata/web/panel.js:46）；还多一组「只有对比的 run（B）调到」（codestrata/web/panel.js:563），收 A 的明细里根本没有、只有 B 调到的符号——放进 A 的「动态分派」一组就成了「这次调到了」。
- **图例**：帮助里的横幅上面多一条对比横幅（codestrata/web/app.js:742）：A、B 各是哪个 case@阶段，三种颜色各是什么意思；两个 run 一个录了时序事件、一个没录时加一句「录事件本身有开销，调用次数和时长不完全可比」。横幅收在帮助里，图上也得能看到颜色，所以边的开关那一行把「runtime」的说明换成三种颜色，后面跟一个三色小图例（codestrata/web/app.js:794）。
- **「只在 runtime」的开关照样出**（codestrata/web/app.js:782）：条数、悬停说明按两个 run 任一跑到算——服务端对比时的 runtimeOnlyEdges 就是 A∪B 里静态图没有的边（payload.py:178）。早先对比这一支只放了「runtime」一个开关，可 graph 里控制这类边的 state.dyn 不会跟着重置：进对比之前把它关掉了的话，这类边在对比时一直藏着，页面上没有开关能再打开，条数也不显示。而只有 B 走到的动态分派边，正是对比要看的分歧。开关上画的线还是橙色虚线，只表示「虚线 = 只在 runtime」，边本身按 E.side 上三种颜色。
- **CSS 的顺序**：.e.warmb / .e.both 写在 .e.warm 之后、.e.dim / .e.hi 之前（codestrata/web/app.css:108）；.nd.warmb / .nd.both 写在 .nd.sel 之前（codestrata/web/app.css:127）。同优先级后者覆盖：写反了，选中别的节点时紫色、前景色的边不会淡化，选中的紫色节点也换不成蓝框——就是 warm 以前踩过的坑（那两处的注释写着）。其余对比用的样式（按钮、横幅、图例）放在文件末尾，和 dim / sel 不抢同一个属性。

### 多 run 导出（M7）
graph --hot A --hot B [--compare]：第一个是主 run，全量嵌入；其余放在 EMB.hotBy["id@阶段"] 里，只带导出切面上的节点、边次数和简要的 meta（`_meta_brief`）；--compare 再为前两个带上 cmp 块、边详情带 calls_b。前端这边：
- **列表按 ref 认**：runs() 每行带 ref（codestrata/web/ds.js:50）。同一个 run 的两个阶段可以分别导出成两行，按 id 认就分不开，所以导出版的运行列表拿「id@阶段」当键、当前那一行也按它标（codestrata/web/app.js:659），时间后面写上阶段；点一行就换到它的 ref，不再按「有 serving 先选 serving」猜阶段（codestrata/web/app.js:696）——猜出来的组合多半没带。
- **静态图照样能选**（codestrata/web/ds.js:35）：选了「静态图」，graph() 把 hot、hotMeta、graphHot、runtimeOnlyEdges、cmp 都置空再返回。只带一个 run 的导出里 CS.ds.run 一直是空的（不能换），「run 空」在那里不等于静态图，所以这一支还要看 canSwitchRun，否则那种导出永远显示成静态图。边详情同样处理（codestrata/web/ds.js:79）：edge() 按同一个条件认出「选了静态图」，走和下面「换到别的 run」同一段剥法——只留有静态引用的项、改成「静态」、次数清零，说明写「现在只看静态图，这里只列静态引用」（codestrata/web/ds.js:85）。内嵌的边详情是按主 run（带了 --compare 的还有 B）算好的，原样返回的话，图上不叠 runtime，点开边却写着调用次数，甚至「A n / B m」；serve 的静态图边详情本来就没有 runtime，这样两边说法一致。说明照样由面板写进抬头，不写成笼统的「没有 runtime 数据」。
- **换到别的 run**（codestrata/web/ds.js:38）：hot 换成 hotBy 里的次数（没有逐函数、逐文件的次数），graphHot 为空（「只看跑到的」在总图上隐藏，不另排版），cmp 丢掉——对比块是主 run 对 B 算的，叠到别的 run 上颜色全错。边详情（codestrata/web/ds.js:77）：内嵌的调用明细只有主 run 的，拿来当这个 run 的会说错，所以只留有静态引用的项、全部改成「静态」、次数清零，附一句说明（codestrata/web/ds.js:86）；面板在没有 runtime 数据时把这句写进抬头（codestrata/web/panel.js:535），而不是笼统的「没有 runtime 数据」，免得看的人以为这个 run 没跑到这条边。
- **对比只读**（codestrata/web/app.js:395）：叠着主 run、带了 cmp 时，工具栏上「对比」的位置是一个不能点的紫色标签（B 的 case · 时间），悬停说要换请用 serve；换到别的 run 上它就没了（cmp 已经丢掉）。启动时不核地址里的 cmp=，图回来也不把 cmp.ref_b 写回 CS.ds.cmp——导出版的对比是定死的，CS.ds.cmp 一直是空，地址里写什么都不起作用。
- 阶段按钮、「图」开关在导出版里一律不出：阶段按钮会指向没带上的「id@阶段」组合；时序图本来就不嵌。

### 复刻和阶段表（M8，帮助里「这次跑了什么」）
目标：看着一张 hot 图，能原样再录一次，也看得出各阶段是从哪儿切开的。命令和这几项都是服务端拼好的（`runs.load` 的 meta：rerun、rerun_exact、rerun_redacted、rerun_env、env_inherited、phase_at、phase_log），前端只显示、复制，不自己拼。给网页和导出的 rerun 一律是隐去过的版本（runs.py:790）：新 run 整条原始命令过 `_redact_argv`（runs.py:1000）；老 run 按参数拼的，拼出来的 codestrata 那一段和 case 命令那一段也都过 `_redact_argv`（runs.py:1026），所以老 run 的 case 命令里的 `--api-key X` 同样隐去。帮助里的 case 命令（meta.cmd）和进程表每一行的 argv 也在 `runs.load` 里隐去过（runs.py:771、runs.py:781）；serve 的时序图不经过 `runs.load`，由 `seq.build` 自己把进程的 argv 过同一个函数再交给页面（seq.py:431），生命线上面的进程名和悬停里的命令也是隐去过的。隐去的是 --env 里名字像密钥的值、--api-key X / --hf-token=X 这种名字像密钥的选项的值、URL 里的账号密码，都换成 <已隐去>；完整的在 `runs show` 里。导出里别的 run、对比的 B 用 `_meta_brief` 带上同样这几项（payload.py:90），所以在导出里换到别的 run，帮助里照样有它的复刻命令和阶段表。
- **复刻块**（codestrata/web/app.js:219）：排在「这次跑了什么」最上面，一条命令加「复制」。老 run 没存原始命令（rerun_exact 为假）时注明是按参数拼的、codestrata 按 PATH 找、仓库路径是录制时的绝对路径（codestrata/web/app.js:224）；隐去过东西（rerun_redacted）时写一句：命令里像密钥的值（--env 里的、--api-key 这类选项的）和 URL 里的账号密码已隐去、写成 <已隐去>，下面的 case 命令和进程表也一样，完整的用 `codestrata runs <repo> show <id>` 看（codestrata/web/app.js:226）。录制时继承的环境变量（env_inherited）放在一个默认收起的 details 里，逐行 K=V，有 rerun_env 时再给一个「连环境变量一起」的复制（codestrata/web/app.js:229）——这些变量不在命令里，但被 trace 的命令会继承它们，复刻时要一样。
- **复制**（codestrata/web/app.js:284）：帮助里 hot 这一段每次图回来都整块重写 innerHTML，所以不逐个给按钮挂监听，而是在 #hotbanner 上挂一次事件委托，按按钮的 data-copy（rerun / rerun_env）从最近一次 runHtml 存下的 meta（this._runMeta，codestrata/web/app.js:217）里取字符串——拷的是 meta 里的字符串本身（网页上也是隐去过的那版），不是 pre 里转义过的 HTML。copyText（codestrata/web/app.js:10）：安全上下文里有 Clipboard API 就用它，没有或被拒时退回「选中一个临时 textarea 再 execCommand('copy')」；结果写在按钮上（「已复制」/「复制不了，请手动选中」），1.6 秒后复原。
- **「复刻」按钮**（codestrata/web/app.js:585）：在运行按钮右边，叠着 run、meta 里有 rerun 时出现，静态图上藏着；不看 canSwitchRun，导出版也有。点它打开帮助、把复刻块滚进视野、边框闪一下（codestrata/web/app.js:299）：先摘掉 flash 类、读一次 offsetWidth 让浏览器重排再加回去，连着点也每次都闪（动画在 codestrata/web/app.css:511）。按钮带 data-help（codestrata/web/index.html:45），「点别处关掉帮助」的监听放过带这个属性的元素（codestrata/web/app.js:204），帮助开着时按下它不会先被关掉。
- **阶段表**（codestrata/web/app.js:259）：接在复刻块下面、case 命令上面（codestrata/web/app.js:236）。phase_log 不到两条、也没有 --phase 时不出（codestrata/web/app.js:265）。每行是 phase_log 的一条 [名字, t_us, 来源]，时刻写成秒，没有时刻的写「—」；来源决定第三列（codestrata/web/app.js:267）：start 写「录制开始」，hook 写「第一次进入 qualname 文件:行」（按名字到 phase_at 里找，找不到只写 --phase），sh 写「case 脚本写 PHASE」。老 run 的条目没有来源：名字是 start 的当 start，其余一律当脚本写的。sh 那行的名字在 phase_at 里也有、而且 phase_log 里没有这个名字的 hook 条目时，加一句「同名的 --phase 没起作用」（codestrata/web/app.js:274）——这一段是脚本切的，不是从那个函数开始的。hook 条目事先按名字收进 byHook（codestrata/web/app.js:264），所以这和录制时 cmd_trace 打的同一句警告（__main__.py:295）是同一个条件：按阶段名算，有 sh 条目、没有 hook 条目才算（__main__.py:293）。同一个名字先被 --phase 切过、后来脚本又写一次时，网页和 CLI 都不标，两边说法一致。phase_at 里有、phase_log 里一次都没出现的，补一行「没切到：qualname 这次没被调用」（codestrata/web/app.js:277；行带 idle 类，变淡的只有 qualname）。按名字查的三张表（at、fired、byHook）都用 Object.create(null)（codestrata/web/app.js:262）：阶段名可以叫 constructor，普通对象上 X['constructor'] 是 Object 的构造函数、永远为真——at 会以为有同名的 --phase，byHook 会以为有 hook 条目，fired 会以为已经切到，叫 constructor 的阶段在这几处就都判错了。
- **阶段按钮的悬停**（codestrata/web/app.js:603）：这个阶段确实是 --phase 切出来的（phase_at 里有它、phase_log 里有它的 hook 条目）才多一句「；从第一次进入 qualname 开始」，被脚本同名抢先的不写。阶段按钮只在 serve 里出，导出版看阶段怎么切只能看帮助里的表。

### 两张图共用一个图框（M5，只在 serve 里）
设计上两张图共享两样东西：**切面**（open）和**选中**（CS.graph.state 里的 sel / selEdge）。时序图不另存一份，全部借模块图的，于是抽屉、搜索、hash 都不用知道有第二张图。
- **切换**（codestrata/web/app.js:517）：模块图的 svg 设成 display:none、藏起缩放按钮，时序图的容器在同一个图框里显示出来。「时序图」按钮只有当前 run 在 /api/runs 里标了录过事件时才能点；灰着时的悬停说明分两种（codestrata/web/app.js:490）：/api/runs 标了 events_error（录了事件，但整理成 span 时失败了）就提示用 runs merge 重来，否则才说录的时候要加 --events——两种情况该做的事不一样，前者重录一遍是白录。地址里带着 view=seq 却切不过去时，退回模块图并用浮层说清原因（codestrata/web/app.js:502）：导出版（按 CS.ds.mode 认，见上面「为什么这样切」）、还没选 run、这个 run 的事件整理失败、这个 run 没录事件，说法和按钮上的一致；地址里的 run 已经找不到时不再重复提示（启动时已经提示过一次）。
- **hash**：view=seq 跟在 run= 后面写进地址（codestrata/web/app.js:318），启动时模块图画完后再读（codestrata/web/app.js:76）——要先知道叠的是哪个 run、它有没有事件。
- **各记各的滚动位置**（codestrata/web/app.js:514）：两张图共用一个会滚的框，切走时记下这张图的滚动位置，切回来时回到原处。时序图要等数据回来、画好之后才能恢复（codestrata/web/app.js:523），之前框的高度还不对；要跳到某条消息时不恢复，交给「滚到选中的那条」。
- **graph.js 的 hidden()**（codestrata/web/graph.js:325）：svg 藏着时，所有 getBoundingClientRect 量出来都是 0，graph 会以为节点在可见区域之外、把共用的图框滚过去——在时序图里点一下、搜一个名字，时序图就被滚走了。所以 reveal / focus / showEl / setZoom 在图藏着时一律直接返回。Ctrl+滚轮的监听挂在图框上，照样拦下浏览器的默认缩放，于是在时序图里 Ctrl+滚轮什么也不做。
- **时序图上点 → 模块图的选中**：点生命线头 = CS.graph.pick 这个节点（再点一次取消），点消息 = CS.graph.pickEdge 这条边（codestrata/web/app.js:559），抽屉、面板走的都是原来的路。不强行打开抽屉（codestrata/web/app.js:552）：抽屉会盖住刚点的那一行，它的标题栏一直看得见，要看详情自己点开。
- **别处的选中 → 时序图的高亮**：选中还会从很多地方变（Esc、点空白、搜索、抽屉里的链接、换切面后保留选中），与其每处都通知时序图，不如在启动时把 graph 的四个回调各包一层（codestrata/web/app.js:65）：先跑原来的回调，当前是时序图、手上也有时序数据时按新的选中重画一遍（codestrata/web/app.js:72）。
- **抽屉标题写消息**：点消息时 CS.seq.picked 记下这一行，时序图里选中的边正好是它时，抽屉副标题换成这条消息本身（codestrata/web/app.js:181）：两端的函数、从第几秒开始、用时（或「到进程结束都没返回」）、连续几次合成一行、async 挂起几次、pid 和线程、被调函数的 文件:行。切视图后按当前视图重写一次标题。记下的这条在同一层包装里清掉（codestrata/web/app.js:70）：选中换成了别的节点、别的边，或者取消选中，它就不再是「刚点的那条」，不清的话之后再选回这条边，副标题写的还是很久以前点的那一次；唯独选的还是同一条边时留着——点消息本身就是先记下再 pickEdge，切回模块图时也会对同一条边再 pickEdge 一次，这两处一清就白记了。换 run 时 reset 也把它清掉。
- **「在时序图里看」**（codestrata/web/app.js:182）：模块图上选中一条边、当前 run 录了事件时，抽屉标题栏里多一个按钮。按下去调 seqFind 找这条边在当前切面上第一次被调用的时刻（服务端先在 run 选的阶段里找），从那一刻前 1 µs 开始取时间窗，切到时序图后把第一条高亮的消息（或包着它的 loop 行）滚到时序图固定表头之下、抽屉之上（codestrata/web/seq.js:85）。
- **切面、run 跟着走**（codestrata/web/app.js:853）：setCut 成功后如果正在看时序图，用同一个时间窗按新切面重取——在时序图的目录生命线上点 ＋ 展开，模块图和时序图一起细到子模块；新 run 没录事件就退回模块图。

### 时序图的画法（`web/seq.js`）
- **请求**：每次取图都把当前切面和记下的时间窗参数（t0、t1、max、fold）一起发出去；每次 show 递增一个序号，晚回来的旧响应直接丢掉（codestrata/web/seq.js:54）。时间刷的概览按 run 缓存（codestrata/web/seq.js:50），换了 run 就重取，旧 run 的概览晚回来也不会被当成新的。请求失败时除了把错误写进容器，还把手上的数据清掉（codestrata/web/seq.js:63），换 run 的 reset 也清（codestrata/web/seq.js:80）；render 没数据就直接返回（codestrata/web/seq.js:98）。否则之后选中一变（比如按 Esc），包在 graph 回调外面的那层就会拿上一次的数据重画、盖掉错误提示——失败的若是刚换过去的 run，画出来的就是旧 run 的时序。
- **固定表头**：第一行是窗口信息，写成「起点 + 宽度」——很密的一段不到 1 ms，写成「1.440s – 1.440s」看起来像是空的；然后是「起点」「下一屏 ▸」两个按钮和计数（多少行、多少条消息、节点内部几次没画、import 时的模块顶层执行几次没画、有进程的事件录到上限的警告）。按钮放在左边，因为右上角浮着搜索栏；表头里的窗口信息和时间刷还按搜索栏的实际宽度缩短（codestrata/web/seq.js:110）。第三行是生命线头：上排是进程（跨它的几条生命线，悬停看完整命令，像密钥的值隐去过，见「复刻和阶段表」），下排是节点按钮，名字去掉仓库唯一的顶层包名；目录节点后面带「/」，能展开时右边有个 ＋（codestrata/web/seq.js:181）。
- **行**：一行一件事，按时间先后排、不按比例画，左边一列是相对窗口起点的时刻。四种行：消息（橙色箭头，async 的是虚线、到进程结束都没返回的换成过期色，标签是被调函数和用时）、loop（虚线框横跨涉及的生命线，写「↻ ×次数、一轮里的调用、总用时（点开看这一段）」）、空闲（「⋯ 空闲 340ms」）、派生子进程（从父进程的第一条生命线指到子进程的第一条，两个进程在这个窗口里都有生命线才画）。
- **画不下 / 没东西**：服务端返回太密时给一个「看建议的窗口」按钮（codestrata/web/seq.js:113），说明分两种：整段折过了还放不下，写「折叠后还有 N 行」；窗口里的 span 多到服务端不肯整段折一遍（几十万条要好几秒），它只估计、行数给的是空，这时改写「有 N 次跨文件调用」，照行数写就成了「null 行」；窗口里没有跨节点的调用时，说明有多少次发生在同一个节点内部（在模块图上展开这个节点就能看到）、多少次落在 index 之外的文件上。
- **时间刷**（codestrata/web/seq.js:142）：整个 run 的时间轴，调用最多的至多 6 个进程各画一条密度折线，阶段分界画成虚线并标名字，当前窗口是一块浅色。按住拖出一段就看那一段，点一下（没拖开）就从那一刻开始让服务端自动收窄（codestrata/web/seq.js:294）。按下时拦住冒泡，否则图框会把它当成拖动平移；拖到刷子外面才松开时，随后那次 click 会落到公共祖先上、冒泡到图框触发「点空白取消选中」，所以在图框上用捕获阶段吞掉紧接着的一次 click（codestrata/web/seq.js:291）。
- **点开 loop**（codestrata/web/seq.js:248）：请求这个 loop 自己的那段时间、fold=0、上限 600 行。不关折叠的话，服务端会把同一段又折成同一行，点了等于没点。
- **下一屏**（codestrata/web/seq.js:261）：从服务端给的 next_t0 接着看，不按这一屏最后一行的结束时刻猜——loop 的结束时刻里可能包着挂起的时间，按它猜会跳过一段。在点开的 loop 里翻页时继续不折叠，翻出这个 loop 的范围后回到普通的自动收窄。
- **键盘和焦点**：消息行、loop 行可以 Tab 到、按 Enter 或空格触发；生命线头和按钮本来就是 button。选中一变整张图就重画，焦点会掉回 body，所以重画前记下焦点在哪（哪个节点、哪个导航按钮、第几行），画完放回去（codestrata/web/seq.js:103）。
- **点空白**：生命线头、消息、loop、表头的按钮都自己拦住冒泡；点时序图的空白处照样冒泡到图框、取消选中，和模块图一样。

### 过期文件
Ctrl+点击的行列号是 scan 时的快照。文件在 scan 之后改过（大小或修改时间变了，payload.py:469），链接会落在别的字上，所以宁可不给：全文窗口标一句「重新 scan 才能 Ctrl+点击」，引用列表里来自改过文件的行标「改过」。hot 图另有一套判断（和录制时记下的文件哈希比）：录制后有文件改过时，hot 标记和运行列表里标「⚠ 录制后改过」。但改过的文件不再整份当成不准：M6 起 `runs.load` 在建 hot 图之前先按录制时记下的函数名（qualname）把次数挪到函数现在的行号上（`runs.remap`），帮助里的横幅按这件事分三处说：
- 过期文件那句写「N 个文件改过或删掉了；改过的已按函数名把次数挪到函数现在的位置」（codestrata/web/app.js:766）。N 和悬停列出的文件都包括删掉的，但「挪过」只说改过的：删掉的文件现在没有函数可对，remap 不碰它们，横幅只是把它们列出来。
- 安装包那句：录制时跑的安装包和仓库有文件不一致时，写「其中 N 个与仓库内容不一致（已按函数名对到仓库里的位置）」（codestrata/web/app.js:762），不再说行号不可信——remap 对这些文件（mismatch）和改过的文件一样处理，行号已经按名字换成了仓库里的。
- 对不上的单独一句：hotMeta.unmatched 大于 0 就出「⚠ N 处按函数名对不上：这些调用只算到文件上，不算到函数上」（codestrata/web/app.js:767），不挂在过期文件那句下面。因为 mismatch 文件也会 remap，却不算进 stale_files——挂在下面的话，只有安装包不一致的 run 就看不到对不上的个数。后半句照实说 remap 怎么处理这些键：改成「文件:-1」，次数还算在这个文件（和它的模块）上，不落到任何函数上，因为原来那一行现在可能是别的函数的定义。悬停列出对不上的三种原因：lambda、生成器表达式没有名字；改了名、删了的函数找不到；老的 run 没存函数名。最后一种要写出来：老 run 改过的文件里每个键都对不上，N 会很大，不说原因，看的人会以为按名字挪这件事坏了。

这么分是因为挪过之后绝大多数叠加是准的：函数下移几行、加了注释都对得上，再笼统地说「可能偏」，看的人会把整张 hot 图都当成不可信、跑去重录；真正落不到函数上的只剩对不上的那几处，就把个数给出来。N 数的是计数的键（一个「文件:首行号」算一处），不是调用次数。

## 局限
导出版是固定的一个切面加一份有限的数据：
- 不能展开 / 收起（「＋ / −」不画）；排版宽度是导出时定的，窗口变宽只按比例放大（最多 1.25 倍），不像 serve 按图框宽度重排
- 能换的 run 只有导出时用 --hot 带上的那几个，每个就是导出时点名的那个阶段，不能换阶段。除了主 run，别的 run 只带图上的次数：没有逐函数的次数，边详情只列静态引用；只在它的 runtime 里出现、主 run（带了 --compare 的还有 B）里没有的边，点开只有「导出版里没有这条边的详情」——内嵌的边详情只给主 run 的图和它的 runtimeOnlyEdges 算过（payload.py:649）
- 对比只能是导出时 --compare 定下的主 run 对第二个 run，只在叠着主 run 时显示，不能在页面上另选 B
- **没有时序图**：时序事件一律不嵌入（M7 的多 run 导出也不嵌），工具栏上不出「模块图 | 时序图」，抽屉里也没有「在时序图里看」
- 搜索能用（名字索引内嵌了，payload.py:654），但点一个被收着的模块只能选中装着它的节点
- 整个文件控制在 14 MB 以内（`total_budget`，payload.py:592；单文件宿主上限 16 MB）：先算好其余部分（带上的别的 run 也算在里面，只有切面上的次数，占得不多），剩下的额度才给全文，这次跑到过的文件和解读里引用过的文件优先。xref 目标全文件共用一张表（payload.py:633），省下的额度能多带一两百个文件
- 没带全文的文件只能看顶层符号；Ctrl+点击跳向这种文件时只提示、留在原地；「谁引用了它」只在内嵌了全文的文件里找，会标明结果不全
- 不能写解读、不能跳编辑器；要这些用 serve

serve 里的时序图：
- 给搜索栏让的宽度只在重画时量一次，之后打开、收起或拖宽搜索栏，要等下一次重画才跟上
- 时间刷最多画 6 个进程；行不按时间比例排，两条消息隔多久只能看左边那列时刻和「空闲」行
- 进程之间只画派生；两个进程在当前窗口里有一个没有生命线，派生也不画

serve 里的对比：
- 只影响模块图和详情栏；时序图照旧只画 A
- 同一个 run 的两个阶段在对比列表里选不到（列表把 A 的整个 run 都排除了），虽然地址里写「cmp=A 的 id@别的阶段」前端和服务端都接受

## 不确定

- CS.seq.picked 现在只在选中换成别的节点 / 边（或取消选中）、换 run 时清掉，同一条边上换了时刻不清。于是：在时序图里点了某条边 5 秒处的一条消息 → 切回模块图（边还选着）→ 点「在时序图里看」跳到这条边第一次出现的 1 秒处，抽屉副标题写的仍是 5 秒那条。翻「下一屏」之后也一样，副标题描述的消息可能已经不在屏上。
- 对不上那句的悬停只说「老的 run 没存函数名」。用 Python 3.10 录的新 run 也没有函数名（3.10 的 code 对象没有 co_qualname，trace.py:215 就不记），改过的文件里同样每个键都对不上，但悬停列的三种原因里没有这一种，看的人会以为是 run 太老。
- 导出版地址里的 run= 如果是 case 名、或者是没带上的「id@阶段」，启动时按 id / case 名在列表里找得到，不提示；graph() 在 hotBy 里按完整键查不到就退回主 run，图回来后地址也被改写成主 run——等于悄悄换成了主 run。
- 「只有对比的 run（B）调到」一组只收 A 的明细里根本没有的符号（`edge_compare` 的做法）。代码里有静态引用、A 没调、B 调到的符号留在「引用了，但这次 case 没走到」一组，写「A 0 / B n」，也不算进那一组的个数；看个数会低估两个 run 在这条边上的分歧。
- 隐去有几处边界：名字像密钥的选项后面紧跟着 - 开头的参数时，当它是开关、下一个参数不隐去（runs.py:961），这样 `--no-auth --port 80` 里的 `--port 80` 不会被吃掉，代价是本身以 - 开头的密钥值会原样出现在复刻块、case 命令、进程表和时序图里。时序图上设了进程标题的，名字直接用标题（seq.py:432），标题不过隐去。复刻块里那句提示只看 rerun_redacted（codestrata/web/app.js:226），而它只比较复刻命令隐去前后是否不同（runs.py:792）：子进程的 argv 里有要隐去的、复刻命令本身（codestrata 那一段和 case 命令）没有时，进程表和时序图里出现 <已隐去>，页面上却没有那句说明。
