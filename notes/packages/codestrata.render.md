## 是什么
单文件导出：把 `codestrata/web/` 下的前端（`web/index.html` + `web/app.css` + 6 个 JS）和一份数据内联成一个 HTML，只读、离线、可以直接发给别人。只有一个函数 `export`，有两个调用方：`__main__` 的 `cmd_graph`（普通的单文件导出，__main__.py:164），和 M8.2 的 `site.export_site`（`graph --link github --out 目录`，site.py:337）。M5 给前端加过第 7 个文件 web/seq.js（时序图），导出版也带着它、却用不了；后来模块图上有了「时间顺序」，时序图整个去掉，它也从两份脚本清单里删了（render.py:17）。M7（对比两个 run、一次导出多个 run）没有加新的 JS 文件，`render.py` 本身也没改：多出来的数据（EMB.hotBy、EMB.cmp）由 `export_payload` 组装，这里照旧整份 JSON 塞进去；新的行为全在前端的 ds / app / graph / panel 里，下面主要讲它们。M8（复刻命令、阶段表）同样没动 `render.py` 和脚本清单：要显示的东西都在 run 的 meta 里（导出里别的 run 靠 `_meta_brief` 带上），前端改的是 app.js（帮助里的显示、运行按钮旁的「复刻」、阶段按钮的悬停），外加 index.html 里那个按钮和 app.css 里几条样式，见「复刻和阶段表」。M8.1（`graph --public`，放到公网上）也没动 `render.py`：去掉本机个人信息的是 `payload.publicize`，`cmd_graph` 在 `export_payload` 之后、调 `export` 之前做（__main__.py:163），这里拿到的已经是公开过的 JSON；前端只多了 ds.js 的一个标记和帮助里复刻块的一句说明，见「公开页」。

M8.2（源码从 GitHub 取的导出）是 M5 以来 `render.py` 第一次改：payload 里有 `link` 时，多带一个前端文件 `web/hl.js`（浏览器端的源码高亮），放在自己单独的 `<script>` 里（render.py:26）。后来边详情改成一对调用一张卡片、卡片里的 from / to 代码片段在浏览器里高亮（payload 只带纯文本，导出不会因为片段变大），hl.js 就改成所有导出都带、serve 的 index.html 里也单独加载。别的都不在这里：`site.export_site` 组 payload（`export_payload(code=False)`，不带片段、全文和共用的跳转目标表，payload.py:1228）、把边详情和搜索索引挪到 data/ 里、写 EMB.link（site.py:311），再调 `export` 拿 index.html。前端这边多了 ds.js 的 linkedDs（盖在 embedded 上的一层，不是第三种 mode，见「为什么这样切」「源码从 GitHub 取」），viewer.js 的 GitHub 链接和几种说明，panel.js 给 source 多传一个 where；ds.js 顺手把 embedded 的边详情和引用两段挪成了模块里的函数（edgeFrom、embeddedRefs），让链接模式能共用。

之后一批（仅类型的边、撞名的短名、边详情里找不到调用那一行时的说法、hot 横幅把定义和调用分开数）同样没动 `render.py` 和脚本清单：数据由 `payload`（typeOnlyEdges、alias、调用方的 how / form）和 `runs.load`（meta 的 defs）给，前端改的是 graph / panel / app 三个 JS 和 app.css 的一行样式，见下面同名的几节。模块图上的「时间顺序」（跑到的边按第一次被调用的先后上色、标序号）也没动 `render.py`，只是 `SCRIPTS` 里少了 seq.js：数据由 serve 的 /api/seq/edges（`seq.edge_times`）现算，前端改的是 ds / app / graph 三个 JS 和 app.css 的几个色标，导出版不出这个开关，见「时间顺序」。

时间轴（2026-09-29）把工具栏上的阶段按钮换成「阶段按钮 + 一条时间条」，加了一个前端文件 web/timebar.js（CS.timebar），app.js 的 runBar 改成调它，外加 index.html 里的一个 script 标签、`render.SCRIPTS` 里的一项和 app.css 里一段样式；数据是 `runs.load` 给的 meta（end_us、timeline、window），任意一段时间的次数由服务端按时序事件现算（`seq.window_counts`），见「换 run」里的「时间轴」。`SCRIPTS` 一开始漏了 timebar.js：app.js 在统计栏、横幅、换 run 的进度里都调 CS.timebar.label，导出页上当前叠的 run 只要带阶段或时间段就会抛错。补上的同时加了核对两份脚本清单的测试，见「为什么这样切」里脚本清单那段。

## 为什么这样切
和 `serve` 用的是**同一套前端文件**，唯一的差别是数据源：serve 时前端 fetch /api/*，导出时读内嵌的 window.CS_EMBEDDED。切换由 `web/ds.js` 完成，UI 代码本身不感知（render.py:1）。数据怎么组装是 `payload` 的事（`export_payload`），这里只管打包——所以它不依赖任何内部模块。两种模式在「能做什么」上的差别也都收在 `web/ds.js` 里，不给导出版另写一套 UI：
- M4：serve 能在页面里换叠在图上的 run，导出版原本固定叠导出时那一个（一个「能不能换」的开关 canSwitchRun）。M7 起导出时可以带多个 run（graph --hot A --hot B），导出版也能换，但只在带上的那几个之间换（codestrata/web/ds.js:50）。于是 canSwitchRun 不再等于「是不是 serve」：凡是要认出导出版的地方——时间轴（原来的阶段按钮）、对比按钮——改看 runs() 返回的 embedded 标记（codestrata/web/app.js:495、codestrata/web/app.js:395），「时间顺序」开关看 CS.ds.mode（codestrata/web/app.js:516），不再借 canSwitchRun。不改的话，带了多个 run 的导出会冒出指向没带上的阶段的阶段按钮（早先还会冒出「模块图 | 时序图」开关）；
- M5：时序图只在 serve 里有，后来整个去掉了（前端文件、ds 的三个入口、index.html 里的容器和「图」开关都删了；地址里残留的 view=seq 在下一次写 hash 时被丢掉，codestrata/web/app.js:313）。现在同样只在 serve 里有的是模块图的「时间顺序」：导出版的 ds 也有 seqEdges，一调就返回「导出版没有时序数据」的错误（codestrata/web/ds.js:64）；但 canTimeOrder 先看 CS.ds.mode 是不是 live，导出版里开关根本不出，这个错误走不到；
- M7：对比。serve 里能在页面上选另一个 run 来比；导出版的对比是导出时 --compare 定好的，只显示、不能换（见下面「对比」「多 run 导出」）。
- M8.2：源码从 GitHub 取。这不是第三套 ds，而是**在 embedded 上面盖一层**：EMB.link 存在时，`Object.assign(CS.ds, linkedDs(EMB.link))`（codestrata/web/ds.js:145）只换掉和源码、导出时算好的大表有关的几样——hasFile、file、source、outline、edge、searchIndex、refs，外加两个新成员 linked、blobUrl；图、run、对比、解读、输入包、「时间顺序」的报错都还是 embedded 那一份，mode 仍是 'embedded'。所以 app.js 一行没改，多 run 导出、对比、公开页在链接模式里照样成立；UI 里只有两处要知道是链接模式：viewer.js 看 CS.ds.linked（没带的文件怎么说）和 CS.ds.blobUrl（给不给「GitHub ↗」）。

代价是**脚本清单要手工维护两份**：`web/index.html` 末尾的一串 script 标签给 serve 用，`SCRIPTS` 给导出用（render.py:17）。去掉时序图时两边都删了 seq.js；时间轴加的 web/timebar.js 起先只进了 index.html（codestrata/web/index.html:108）、没进 `SCRIPTS`，导出版因此出错，才补上 `tests/test_package.py` 的 test_export_scripts_match_index：index.html 的 script 标签必须正好是 hl.js + `SCRIPTS`（顺序也一样），web/ 下每个 .js 都得被某个页面（index.html、主菜单的 home.html）引用。漏了的后果看是哪个文件：
- `web/search.js` 漏了不会报错——`web/app.js` 里是「有搜索模块才初始化」，搜索栏和右上角的「搜索」按钮在 HTML 里默认都是隐藏的，导出版就只是悄悄没有搜索。
- `web/timebar.js` 漏了会报错（补上之前就是这样）：时间条本身导出版不画（runBar 在内嵌的 run 列表下先返回，codestrata/web/app.js:495），可统计栏上的 hot 标记（codestrata/web/app.js:717）、对比横幅（codestrata/web/app.js:734）、时间段的横幅（codestrata/web/app.js:741）和换 run 时的进度（codestrata/web/app.js:369）都要 CS.timebar.label 把阶段 / 时间段写成给人看的样子。漏了时 `graph --hot 名字@阶段`（或 @t=起-止）导出的页面，启动时 header 在统计栏那一行抛 TypeError，boot 的 catch 把标题换成「加载失败」（codestrata/web/app.js:90），图不画；多 run 导出里切到带阶段的别的 run 时同样在 CS.timebar.label 上出错。

**hl.js 不在 `SCRIPTS` 里**：serve 下 index.html 单独用一个 script 标签加载它；导出时 `export` 总是把它读进来（render.py:30）——源码从 GitHub 取的导出靠它高亮全文，所有模式下边详情里的代码片段也靠它（早先只有 link 时才带，serve 和普通导出的源码是服务端 Pygments 高亮好的）。它单独占一个 `<script>`，排在内嵌数据之后、主脚本之前（render.py:36）。理由写在注释里（render.py:28）：hl.js 用了正则的后行断言（比如 codestrata/web/hl.js:262 那条正则字面量），Safari 16.4 之前的浏览器解析这段脚本时直接报语法错、整段不执行——和主脚本拼在同一个 `<script>` 里，整页就没了；分开之后只是 CS.hl 不存在，ds.js 取源码时看一眼，没有就按行转义成不带颜色的文本（codestrata/web/ds.js:258），其余照常。CS.hl 是 ds.js 每次高亮时现找的，不是加载时抓住的；两个文件开头都是 `window.CS = window.CS || {}`，不会互相冲掉对方挂上的成员。

## 读法
要读懂 `export`，得先知道它打包的前端长什么样（图上看不到，前端不是 Python）。整页是一个应用：上面一条（标题、统计、「?」；下一行是 运行 / 复刻 / 时间 / 对比 / 边 / 视图 开关），图铺满剩下的全部空间、在自己的框里上下左右滚；其余都**浮在图上、半透明**：右上角的搜索栏、图下沿的详情栏，两个都能收起、拖边框改大小（记在浏览器里）。「边」那一组里的「时间顺序」只在 serve 里、叠着一个录了时序事件的 run、不对比时出现。

- `web/ds.js` —— 数据源层，整个前端只通过它拿数据。live 走 /api/*；embedded 读内嵌 JSON，另外补了导出版才需要的：判断某个文件带没带全文、在内嵌文件里自己找引用、把共用目标表里的 xref 目标补回每个文件。**当前叠哪个 run 也放在这一层**：CS.ds.run 存「完整 id@阶段」（空 = 只看静态图），live 的图、边详情、引用、输入包四种请求都自动带上 run=（codestrata/web/ds.js:99）——叠加会影响的就这四样，其余模块照旧调 ds，不知道有 run 这回事。「时间顺序」的 seqEdges（codestrata/web/ds.js:107）也用这个 run。M7 加了 CS.ds.cmp（对比的 run，同样存「完整 id@阶段」），只在 run 非空时跟着图和边详情两种请求带上 cmp=（codestrata/web/ds.js:95）——引用、输入包、seqEdges 和对比无关，不带。请求失败时，错误信息优先用服务端返回体里的 error（「这个 run 没有录时序事件」「没有叫 X 的 run 或 case」），没有才退回「url → 状态码」（codestrata/web/ds.js:14）——「时间顺序」取不到时进度栏里写的就是这句话，所以它得是人话。embedded 这边：canSwitchRun 看导出时带没带别的 run（codestrata/web/ds.js:50），只带一个的导出 run 一直是空；runs() 用内嵌的 hotMeta 加上 hotBy 里各 run 的简要 meta 拼列表，每行多一个 ref（「id@阶段」），整份标上 embedded（codestrata/web/ds.js:51），让启动走同一条路；graph() 按 CS.ds.run 在主 run、hotBy 里别的 run、静态图三者之间换（codestrata/web/ds.js:32），edge() 在换到别的 run、或者选了静态图时把调用明细拿掉（M8.2 起这段是模块里的 edgeFrom，codestrata/web/ds.js:148），见下面「多 run 导出」。M8.1 起 embedded 这边还有一个 public 标记（codestrata/web/ds.js:28），见「公开页」。M8.2 起文件后半是链接模式的 linkedDs（codestrata/web/ds.js:189），见「源码从 GitHub 取」；embedded 的 edge / refs 在对象字面量里只剩一行，分别转给 edgeFrom（codestrata/web/ds.js:79）和 embeddedRefs（codestrata/web/ds.js:83）——行为和挪之前逐字一样（只是 this 换成参数 ds、两张种类表提成了模块级的 RANK / KNAME，codestrata/web/ds.js:160）。挪出来是为了共用：链接模式的 edge 拿 data/edges.json 喂同一个 edgeFrom，refs 用同一套 RANK 排序；embeddedRefs 本身链接模式不用（它有全仓的引用倒排，不必在内嵌文件里现搜）
- `web/graph.js` —— SVG 绘图：泳道、框、节点、边、「＋ / −」展开收起。泳道左边写 `layout` 给每条泳道的标签（codestrata/web/graph.js:88）：「第 N 层」，层太多被压过的泳道写「第 a–b 层」；纵轴是 `layout` 排出的依赖层次，不再是架构高度的区间。缩放：图左上角的 ＋ / － / 100%，或按住 Ctrl（Mac 上 ⌘）滚滚轮，以鼠标所在点为中心（触控板捏合在浏览器里也是 Ctrl+滚轮，顺带支持）；「✥」移动模式下按在哪都能拖图，拖完那次 click 在捕获阶段拦掉，不会误选节点。选中时只把看不见的节点滚到「可见区域」中间——详情栏盖住的那截不算可见。hidden()（codestrata/web/graph.js:380）在图藏着时让滚动、缩放、聚焦都不做：原来是给模块图被时序图盖住的时候用的，时序图去掉之后只剩「还没画出来」这一种。M7 加了对比的三种颜色（见「对比」）。后来又加了「仅类型」这种边（默认不画）、选中节点时只按看得见的边留亮，以及 draw 时把这个切面上的仅类型边存成 this.typeOnly（不管开关画没画，详情栏用它，codestrata/web/graph.js:181），见「仅类型的边」「选中时留亮的只算看得见的边」。再后来加了「时间顺序」：setTimes 收数据，paint 里排名、上色、画序号牌（见「时间顺序」）
- `web/viewer.js` —— 全文窗口（逐行高亮 + 大纲）。Ctrl+点击名字跳到定义，旁边打开一栏：定义在最上面，下面是所有引用（按文件分组，调用 / 引用 / import）；点定义本身只开这一栏。跳转有「← 返回」栈，和编辑器的「转到定义 / 返回」一样。名字指向哪由 scan 时的交叉引用给出，这里只把能点的名字包一层 span。M8.2 给链接模式加了抬头上的「GitHub ↗」、「本地版本」标记、「GitHub 上的这个文件和扫描时不一样」的说明、公开页没带的文件的整页说明，以及引用栏原文取回后的重画（见「源码从 GitHub 取」）
- `web/panel.js` —— 详情栏的左右两半：左边模块 / 边的机器事实（文件树、源码片段——片段里也能 Ctrl+点击），右边解读。搜索栏定位到某个文件 / 函数时，由它在文件树里展开并标出那一行。对比时次数写成「A n / B m」，边详情多出 B 的调用方和「只有 B 调到」一组（见「对比」）。M8.2 起取片段时把「这个符号在哪个文件第几行」（where）也交给 CS.ds.source（codestrata/web/panel.js:508）：链接模式靠它从文件大纲里找方法；live 和 embedded 的 source 只收一个参数，多给的不理。节点短名 short() 按 alias 给撞名的补父目录段，挂成 CS.panel.short 给抽屉标题共用；边详情卡片找不到调用那一行时由 via() 按 how / form 说原因，见「撞名的短名」「找不到调用那一行时怎么说」
- `web/search.js` —— 搜索栏：名字索引一次拿全，在前端打分排序，不来回请求。按**名字本身**找（函数看自己的名字、文件看文件名、模块看最后一段），词里带 `.` 或 `/` 才看路径——早先连路径一起匹配，搜目录名时出来的全是那个目录下的函数。点结果先在图上展开到所在模块并选中，再在详情栏里展开到它；`/` 或 Ctrl+K 随时回到搜索框；框里有字时图上包含命中的节点一直高亮，换切面后重新套
- `web/timebar.js`（时间轴）—— 工具栏上「时间」那一组：「全部」+ 各阶段的按钮，后面一条从 run 开头到结尾的时间条，阶段是条上的色段（meta 的 timeline，切走又切回来的阶段有几段；按钮上的色块和条上的色段按阶段的次序轮着用四种颜色）。对外只有 CS.timebar 的 render / parse / label / extent / snap / fit（codestrata/web/timebar.js:31）：app.js 的 runBar 把 end_us、timeline、window 和按钮的悬停交给 render，选了什么由 onSelect 交回 selectRun；label 在别处把「t=起-止」写成秒。它不取数、不碰 CS.ds。见下面「换 run」里的「时间轴」
- `web/app.js` —— 启动，串起上面六个：切面（展开 / 收起、连点时只认最后一次、重画后尽量保留选中）、叠哪个 run（运行按钮、时间轴、URL hash，见下面「换 run」）、和哪个 run 对比（对比按钮，见「对比」）、「时间顺序」开关的取数（见「时间顺序」）、详情栏、拖边框改大小的通用逻辑、「?」帮助。帮助里收着怎么读图、怎么操作，以及 hot 图的来历：复刻命令和各阶段怎么切的（M8，见「复刻和阶段表」）、case 命令、被 trace 的进程**按命令合并**（跑到仓库代码多的在前）、case 脚本的内容（录制时没存的标明是现在的内容）。统计那一行只留一个 hot 标记，点它打开帮助
- `web/hl.js`（M8.2，只进链接模式的导出）—— 浏览器端高亮：`highlight.py` 用的 Pygments 的 JS 移植，对外只有 CS.hl 的 detect / label / lines 三个（codestrata/web/hl.js:313）。ds.js 只调 lines，语言用的是 data/f/<序号>.json 里服务端 `highlight.detect` 定好的那个；detect / label 留着给 `tests/hl_parity.py` 和 Python 版对拍。读法见「hl.js：照抄 Pygments 的状态表」

`SCRIPTS` 的顺序就是依赖顺序：ds 被所有人用，viewer 定义了 panel 要用的 Ctrl+点击逻辑，app 必须最后——见下面的 fragment 模式，它可能一加载就同步启动。hl.js 不在这个顺序里：它排在主脚本之前的另一个 `<script>` 里，不依赖任何人，也没人在加载时用它。

M8.2 这一块按这个顺序读：先看 `codestrata/site.py` 的模块 docstring，知道 data/ 里每样东西是什么、为什么按序号命名、为什么按版本分目录（设计稿 `docs/design/runs.md` 的「M8.2」一节是同一件事的摘要）；再看 `export` 里 hl 那一段（render.py:26）；然后是 ds.js 里盖上去的那一行（codestrata/web/ds.js:145）和 linkedDs 本身（从 text → file → source → refs）；最后是 viewer.js 里用到 linked / blobUrl / mismatch / local / unpublished / r.more 的几处。hl.js 最后读，读之前最好开着 Pygments 的 PythonLexer / CFamilyLexer 源码对照。验收：Python 这一侧是 `tests/test_runs.py` 的 test_site_export、test_site_export_public_local_home、test_site_export_edges；hl.js 是手动跑的 `tests/hl_parity.py`；ds.js / viewer.js / panel.js 的这些改动没有自动测试（设计稿说前端的变异检查是在浏览器里做的）。

## 关键算法
### 拼装
读 `web/index.html`，把 stylesheet 链接换成内联的 `<style>`（render.py:33），用正则删掉所有外链 script 标签（render.py:34），再把「内嵌数据 + 按 `SCRIPTS` 顺序拼好的 JS」追加到末尾（render.py:36）。因为 script 标签是按正则整批删掉、再按 `SCRIPTS` 重拼的，index.html 里的顺序对导出版不起作用，两份清单各管各的。现在末尾总是三个 `<script>`：内嵌数据一个；hl.js 一个（render.py:30）；拼好的主脚本一个。hl.js 的正文原样塞进去、不做 `</` 转义——它和主脚本一样是仓库里自己的文件，里面没有 `</script`。

### `</` 要转义
内嵌数据里的源码片段可能含 `</script>`，原样塞进 `<script>` 会提前结束脚本。`json.dumps` 之后把 `</` 换成 `<\/`（render.py:31）——在 JS 字符串里两者等价。

### fragment 模式
`fragment=True` 去掉 doctype 和 meta 外壳（render.py:41），给自己会包外壳的宿主（比如 artifact 页面）用。也因为这种宿主会在 DOMContentLoaded 之后才执行内联脚本，`web/app.js` 的启动写成了「已经加载完就直接启动」。

### 换 run（M4，只在 serve 里）
目标是不重启 serve 就能在「静态图 ↔ 这次 run ↔ 那次 run」之间来回切。
- **先定 run 再取图**（codestrata/web/app.js:319）：URL hash 里的 `#run=<id>@<phase>` → /api/runs 返回的 default（也就是 `serve --hot` 给的）→ 只看静态图。按 id 或 case 名在列表里找；找不到、或者还不能加载（没有计数：还在录或中断了），就退回静态图并弹一个浮层提示，而不是整页加载失败。两种情况说法不同（「找不到了（删了？）」/「还没有计数，还在录或要 runs merge」），因为该做的事不一样。提示不写进工具栏的进度那一行：图画好后 refreshStatus 的解读统计一回来就把那一行盖掉，所以改成图画完后弹浮层（codestrata/web/app.js:77）。/api/runs 本身失败时也照样把「已知 run」集合设成空（codestrata/web/app.js:349）——否则之后刷新列表时查这个集合会抛错、被 catch 吞掉，run 列表就一直是空的。地址里的 cmp= 也在这一步核（见「对比」）。
- **hash 里存解析好的完整 id**（codestrata/web/app.js:728）：图回来后按 hotMeta 把「run_id@阶段」写回 CS.ds.run 和 hash。case 名会随着重录指到新的 run，存 case 名的话刷新一下看到的就换了一个 run。
- **运行按钮**：显示 case 和录制时间，弹出的列表第一行是「静态图」，下面按 case 分组。每行：时间（悬停看完整 id）、tags、git 短哈希、活跃进程数、各阶段的函数数、录了时序事件的加「时序」标记、「⚠ 录制后改过 N 个文件」和「录制时安装包和仓库有 N 个文件不一致」；status 不是 ok 的行变淡并列出 problems；没有计数的行不能点，悬停提示去 runs merge。按钮右边叠着 run 时多一个「复刻」（见「复刻和阶段表」）。
- **时间轴**（原来的阶段按钮，web/timebar.js）：「全部」+ 各阶段的按钮，后面一条时间条。当前 run 有两个以上阶段，或者录了时序事件（/api/runs 的 events）又知道多长（meta 的 end_us）时才出现（codestrata/web/app.js:495）；只有一个阶段的，按钮只剩「全部」、条上没有色段，只能拖时间段。从列表选一个 run 时，有 serving 阶段就先选它（codestrata/web/app.js:353）——启动阶段的初始化调用会淹没请求本身。M8 起按钮的悬停对 --phase 切出来的阶段多写一句从哪个函数开始（见「复刻和阶段表」）。
  - **选**：点按钮，或点条上的一段，就是选这个阶段。录了事件的 run 还能拖两头的把手、拖中间平移、在空白处拖出一段，选**任意一段时间**：交回去的是「t=起-止」（微秒），和阶段名走同一个 selectRun，于是 CS.ds.run 是「id@t=起-止」、写进地址，叠加相关的请求都带着它，服务端按这段时间里的时序事件现算次数。拖出来的两头都和整个 run、或者某个只有一段的能选的阶段差不到 4 像素，就当成它（snap，codestrata/web/timebar.js:49）：拖回原样不会凭空多出一个时间段。拖出来不到 3 像素宽的当成没拖（codestrata/web/timebar.js:144）；按下后移动不到 4 像素就是点击，点在哪一段就选哪个阶段，点把手不算。「能选的阶段」是 run 的阶段表（phases）里有的：derive 只把录到了计数的阶段写进去，phase_log 里切到过、却一次调用都没录到的阶段在条上照样占一段，画成灰的 nc 段（codestrata/web/timebar.js:94，样式 .tseg.nc），悬停说「这个阶段没录到调用，不能单独选」，点它不选（codestrata/web/timebar.js:196），snap 也不往它上面吸——选了也加载不了（`runs.resolve` 只认阶段表里的名字）。没录事件的 run 条上只能点，不能拖；老 run 连多长都不知道（end_us 为空）时只有按钮。
  - **缩放**：滚轮以鼠标处为中心缩放、最多放大到 1 ms 宽，Shift+滚轮（或触控板横向）平移（codestrata/web/timebar.js:153）。点阶段按钮时放大到这个阶段、前后各留它长度的 25%，至少 1 ms 宽、挪到 run 的范围里，放大后还占整个 run 六成以上的就直接看整个 run（fit，codestrata/web/timebar.js:62）；放大了才露出「全程」按钮，点它回到整个 run。看的范围按 run id 记在模块里的 views（codestrata/web/timebar.js:20）：换阶段、重画都保留，刷新页面就没了；记着的范围不成样子或超出了终点时，重画时按当前选中的重新放大（codestrata/web/timebar.js:80）。地址里的时间段超出 run 的终点时（手改的、run 重新整理过），条放长到能画出它（codestrata/web/timebar.js:76）。
  - **键盘**：两个把手能 Tab 到（role=slider，每次摆放都更新 aria-valuemin / max / now / text，codestrata/web/timebar.js:129），左右键挪条上看得到的范围的 1%（Shift 10%，codestrata/web/timebar.js:200）。按键挪的是另一份范围 kb，不动当前选中的 cur——提交不成还要画回它；把手挪到条的视野边上时，条跟着平移（follow）。停手半秒后才提交一次（codestrata/web/timebar.js:219），每次提交都是一次 selectRun、重取一次图。提交时不往阶段上吸（snap 的容差给 0，只有正好对上才当成阶段 / 整个 run）：按一下挪的 1% 可能比吸附的 4 像素还小，吸上去就像没按。提交后的重画把焦点还给原来那个把手（codestrata/web/timebar.js:149），可以接着按。等着提交的那一下，在任何一次重画、点选、按下鼠标时都作废（cancel，codestrata/web/timebar.js:24）：半秒后不会盖掉用户刚点的别的。
  - **选的是时间段时**：横幅写「时间段 起 s – 止 s」，并注明次数只有跨文件的调用（codestrata/web/app.js:741）；不写阶段的起点 / 终点（phaseBounds 返回空），图上只给第一次开始落在这段时间里的阶段标 ▶（codestrata/web/app.js:575）。hot 标记、横幅、进度里的时间段都经 CS.timebar.label 写成秒（codestrata/web/timebar.js:35），小数位跟着跨度走。
- **切换本身**（codestrata/web/app.js:357）：先改 CS.ds.run（对比的 run 跟着调，见「对比」）、写 hash，然后拿当前切面调 setCut。于是换 run 就是「同一个切面再取一次图」，分层也跟着新 run 的调用重排，节点可能换泳道：_cutSeq 丢掉晚回来的旧响应（codestrata/web/app.js:852），连着点几个 run 只认最后一个；keepSelection 让选中的节点 / 边换完还选着。换不过去（run 刚被删、还没有计数，setCut 返回 false）时把 CS.ds.run、CS.ds.cmp 和 hash 一起退回原来那个，并用浮层提示原因（codestrata/web/app.js:372），「时间顺序」也按退回去的 run 重取（codestrata/web/app.js:377）——不退的话，图还是旧的，之后取边详情、引用、输入包带的却是那个换不过去的 run。但如果这期间已经有更新的请求（_cutSeq 变了），就不退，免得盖掉后来的选择。设计里原本打算把 setCut 推广成 load({open, run, view})，run 放进 ds 之后就用不着了（view 是时序图那一套，已经去掉）。
- **新录的 run**：窗口重新获得焦点时刷新列表（codestrata/web/app.js:602），有新的只在按钮上加个点，不自动切过去——正在看的图不该自己变；打开列表时点就消了。
- **换回静态图**：「只看跑到的」自动关掉（codestrata/web/app.js:475），不然节点会被全藏起来；这个开关连同帮助里的 hot 横幅一起藏掉。

导出版走同一段代码。只带一个 run 的导出，按钮是灰的（悬停说明要换请用 serve），也不监听焦点；带了多个 run 的，按钮能点，列表里只有导出时带上的那几行（见「多 run 导出」），焦点监听也照样挂上，但内嵌的列表不会变，等于不起作用。两种都不出时间轴（codestrata/web/app.js:495）。

### 对比（M7）
目标：在同一张模块图上看两个 run 走的路哪里一样、哪里分开。A = 当前叠的 run，B = 对比的 run。数字是服务端现算的（`graph_payload` 的 cmp 块：节点、边上各带 [A, B] 两个次数；`edge_compare` 给边详情每项加 calls_b），前端只管选 B、上色、写数字。
- **选 B**（codestrata/web/app.js:385）：工具栏的「对比」按钮只在叠着一个 run、列表里不止一个 run 时出现（codestrata/web/app.js:395）——静态图上没有「A」可比。弹出的列表第一行「不对比」，下面是除 A 以外、能加载的 run（codestrata/web/app.js:433），A 自己的其它阶段也不列。每行写的阶段就是 B 会用的阶段：**跟着 A 走**，A 看全部就比全部；A 看某个阶段、B 也有同名阶段就比它，没有就比 B 的全部（codestrata/web/app.js:448）；A 选的是时间段时也比 B 的全部（codestrata/web/app.js:449），两次 run 的时刻对不上。两个 run 的阶段切法不一定一样，按名字对齐是唯一不用猜的办法；对不上时退到「全部」，而不是不让比。
- **两个下拉不同时开**：点对比按钮先关运行列表，打开运行列表也先关对比列表（codestrata/web/app.js:618）。Esc 关掉对比列表、焦点还给按钮，监听挂在捕获阶段并拦住传播（codestrata/web/app.js:420）——否则同一下 Esc 还会被当成「取消选中」。按钮每次重画工具栏都重建，所以「点外面关闭」和 Esc 这两个 document 级的监听只挂一次，每次按 id 现找元素，不抓旧按钮。
- **选中之后**（codestrata/web/app.js:453）：改 CS.ds.cmp、写 hash，然后同一个切面再取一次图——和换 run 同一条路，连着点几次只认最后一次。取不到（setCut 返回 false）而且期间没有更新的请求时，把 cmp 和 hash 退回去、按钮重画。
- **换 A 时 B 怎么办**（codestrata/web/app.js:361）：A 换成静态图、或者换成 B 那个 run 本身，就不再对比（不能和自己比）；否则 B 按上面的规则换成和新 A 同名的阶段。在时间轴上换 A 的阶段时 B 也跟着换——A 看 serving、B 看全部，比出来的差别大半是阶段不同造成的。换不过去时 cmp 跟着 run 一起退回（codestrata/web/app.js:374）。
- **hash**：cmp= 跟在 run= 后面写进地址，没有 run 就不写（codestrata/web/app.js:314）。启动时先核一遍（codestrata/web/app.js:338）：找不到、还没有计数、和 A 是同一个 run 的同一个阶段，都不带上，图画完后弹浮层说「不能用来对比」或「找不到了」，并把它从地址里去掉（codestrata/web/app.js:78）。服务端还有一道：cmp= 找不到或者就是 A 时不 404，只叠 A、在返回里带 cmpError，前端收到就清掉 cmp、弹这句话（codestrata/web/app.js:731）。两道都要：前端的列表可能是旧的、case 名最终怎么解析只有服务端说了算；前端这道则能在发请求之前就说清是哪种情况。
- **记完整 id**：图回来后用 cmp.ref_b 把 CS.ds.cmp 换成「完整 id@阶段」再写 hash（codestrata/web/app.js:730），理由和 run 一样：case 名重录之后会指到别的 run，甚至指到 A 自己。
- **三种颜色**：只有 A 跑到是橙色（沿用 --hot），只有 B 跑到是紫色（新 token --hotb、--hotb-bg，明暗两套，codestrata/web/app.css:5），两边都跑到是前景色（--ink），两边都没跑到照旧退到背景。画的时候每条边带 E.ab（[A, B]）和 E.side（a / b / both，codestrata/web/graph.js:187），paint 按 E.side 选类名 warm / warmb / both 和箭头（codestrata/web/graph.js:591）；箭头是独立的 marker、不跟着线变色，所以多备了 ahb、ahf 两个（codestrata/web/graph.js:104）。节点同理（codestrata/web/graph.js:232）。
- **粗细和「跑到了」取两边的较大值**（codestrata/web/graph.js:156）：线宽、「只看跑到的」都按 max(A, B)，和服务端按 A∪B 排的 graphHot 一致。「只看跑到的」原来直接查 hot.packages（只有 A），现在 graph 另存一份 hitPk（codestrata/web/graph.js:161）给 vis() 查（codestrata/web/graph.js:560），否则只有 B 跑到的节点会在按 A∪B 排好的图上被藏掉、留下空位。后来又加了 onPath（codestrata/web/graph.js:165）：runtime 边（含动态分派）的两端也算跑到的，调用方不一定有「被调用」的次数（一直在跑的外层函数、import 时执行的模块顶层），不加的话这类边在「只看跑到的」里没有起点；和 payload 排 graphHot 的节点同一个口径。
- **数字**：节点第二行写「A/B」（两边都没跑到就不写，codestrata/web/graph.js:239），边的悬停写「runtime 调用 A x / B y」。详情栏里，模块写「runtime A n / B m 次」（codestrata/web/panel.js:197）；依赖列表里每条边的小按钮按 E.ab 上色、动态边写「A/B 次」（codestrata/web/panel.js:183）——对比时 E.hits 是两边的较大值，拿它上色、写数，会把只有 B 跑到的说成 A 的。边详情是一对调用一张卡片（callCards，codestrata/web/panel.js:53）：抬头写「runtime A n 次 · 对比的 run B m 次」（codestrata/web/panel.js:615），每张卡片按「被调函数 × 调用方」把 A 的 runtime 和 B 的 runtime_b 合到一起（codestrata/web/panel.js:68），写「A n / B m」（codestrata/web/panel.js:77）。A 只引用、没调用的符号（status 是 static）照样收进来——只要 B 调到了它（codestrata/web/panel.js:57）：早先按 status 跳过，只有 B 调到的调用就从卡片里整个消失了；底下「引用了，这次没跑到」也只列两边都没调到的（codestrata/web/panel.js:610）。A 的明细里根本没有、只有 B 调到的符号（status 是 only_b）同样成一张卡片，只是 A 那边是 0。
- **图例**：帮助里的横幅上面多一条对比横幅（codestrata/web/app.js:734）：A、B 各是哪个 case@阶段（A 的经 CS.timebar.label 写，时间段写成秒），三种颜色各是什么意思；两个 run 一个录了时序事件、一个没录时加一句「录事件本身有开销，调用次数和时长不完全可比」。横幅收在帮助里，图上也得能看到颜色，所以边的开关那一行把「runtime」的说明换成三种颜色，后面跟一个三色小图例（codestrata/web/app.js:805）。
- **「动态分派」的开关照样出**（codestrata/web/app.js:782；原来叫「只在 runtime」，现在也管有 import、但跑到的调用全是动态分派的边，即 dynOnlyEdges）：条数、悬停说明按两个 run 任一跑到算——服务端对比时的 runtimeOnlyEdges 就是 A∪B 里静态图没有的边（payload.py:251）。早先对比这一支只放了「runtime」一个开关，可 graph 里控制这类边的 state.dyn 不会跟着重置：进对比之前把它关掉了的话，这类边在对比时一直藏着，页面上没有开关能再打开，条数也不显示。而只有 B 走到的动态分派边，正是对比要看的分歧。开关上画的线还是橙色虚线，只表示「虚线 = 动态分派」，边本身按 E.side 上三种颜色。
- **CSS 的顺序**：.e.warmb / .e.both 写在 .e.warm 之后、.e.dim / .e.hi 之前（codestrata/web/app.css:114）；.nd.warmb / .nd.both 写在 .nd.sel 之前（codestrata/web/app.css:134）。同优先级后者覆盖：写反了，选中别的节点时紫色、前景色的边不会淡化，选中的紫色节点也换不成蓝框——就是 warm 以前踩过的坑（那两处的注释写着）。其余对比用的样式（按钮、横幅、图例）放在文件末尾，和 dim / sel 不抢同一个属性。

### 多 run 导出（M7）
graph --hot A --hot B [--compare]：第一个是主 run，全量嵌入；其余放在 EMB.hotBy["id@阶段"] 里，只带导出切面上的节点、边次数和简要的 meta（`_meta_brief`）；--compare 再为前两个带上 cmp 块、边详情带 calls_b。排版（连同按调用分层）只按主 run（带 --compare 的加上 B）做一次，切到别的 run 或静态图时节点不挪。前端这边：
- **列表按 ref 认**：runs() 每行带 ref（codestrata/web/ds.js:54）。同一个 run 的两个阶段可以分别导出成两行，按 id 认就分不开，所以导出版的运行列表拿「id@阶段」当键、当前那一行也按它标（codestrata/web/app.js:637），时间后面写上阶段；点一行就换到它的 ref，不再按「有 serving 先选 serving」猜阶段（codestrata/web/app.js:674）——猜出来的组合多半没带。
- **静态图照样能选**（codestrata/web/ds.js:38）：选了「静态图」，graph() 把 hot、hotMeta、graphHot、runtimeOnlyEdges、cmp 都置空再返回。只带一个 run 的导出里 CS.ds.run 一直是空的（不能换），「run 空」在那里不等于静态图，所以这一支还要看 canSwitchRun，否则那种导出永远显示成静态图。边详情同样处理（codestrata/web/ds.js:150）：edge()（M8.2 起是 edgeFrom）按同一个条件认出「选了静态图」，走和下面「换到别的 run」同一段剥法——只留有静态引用的项、改成「静态」、次数清零，说明写「现在只看静态图，这里只列静态引用」（codestrata/web/ds.js:155）。内嵌的边详情是按主 run（带了 --compare 的还有 B）算好的，原样返回的话，图上不叠 runtime，点开边却写着调用次数，甚至「A n / B m」；serve 的静态图边详情本来就没有 runtime，这样两边说法一致。说明照样由面板写进抬头，不写成笼统的「没有 runtime 数据」。
- **换到别的 run**（codestrata/web/ds.js:41）：hot 换成 hotBy 里的次数（没有逐函数、逐文件的次数），graphHot 为空（「只看跑到的」在总图上隐藏，不另排版），cmp 丢掉——对比块是主 run 对 B 算的，叠到别的 run 上颜色全错。边详情（codestrata/web/ds.js:151）：内嵌的调用明细只有主 run 的，拿来当这个 run 的会说错，所以只留有静态引用的项、全部改成「静态」、次数清零，附一句说明（codestrata/web/ds.js:156）；面板在没有 runtime 数据时把这句写进抬头（codestrata/web/panel.js:573），而不是笼统的「没有 runtime 数据」，免得看的人以为这个 run 没跑到这条边。
- **对比只读**（codestrata/web/app.js:390）：叠着主 run、带了 cmp 时，工具栏上「对比」的位置是一个不能点的紫色标签（B 的 case · 时间），悬停说要换请用 serve；换到别的 run 上它就没了（cmp 已经丢掉）。启动时不核地址里的 cmp=，图回来也不把 cmp.ref_b 写回 CS.ds.cmp——导出版的对比是定死的，CS.ds.cmp 一直是空，地址里写什么都不起作用。
- 时间轴在导出版里一律不出：它会指向没带上的「id@阶段」组合，拖出来的时间段更是；「时间顺序」也不出（时序事件本来就不嵌）。

### 复刻和阶段表（M8，帮助里「这次跑了什么」）
目标：看着一张 hot 图，能原样再录一次，也看得出各阶段是从哪儿切开的。命令和这几项都是服务端拼好的（`runs.load` 的 meta：rerun、rerun_exact、rerun_redacted、rerun_env、env_inherited、phase_at、phase_log），前端只显示、复制，不自己拼。给网页和导出的 rerun 一律是隐去过的版本（runs.py:818）：新 run 整条原始命令过 `_redact_argv`（runs.py:1032）；老 run 按参数拼的，拼出来的 codestrata 那一段和 case 命令那一段也都过 `_redact_argv`（runs.py:1061），所以老 run 的 case 命令里的 `--api-key X` 同样隐去。帮助里的 case 命令（meta.cmd）和进程表每一行的 argv 也在 `runs.load` 里隐去过（runs.py:797、runs.py:809）。隐去的是 --env 里名字像密钥的值、--api-key X / --hf-token=X 这种名字像密钥的选项的值、URL 里的账号密码，都换成 <已隐去>；完整的在 `runs show` 里。导出里别的 run、对比的 B 用 `_meta_brief` 带上同样这几项（payload.py:143），所以在导出里换到别的 run，帮助里照样有它的复刻命令和阶段表。
- **复刻块**（codestrata/web/app.js:212）：排在「这次跑了什么」最上面，一条命令加「复制」。老 run 没存原始命令（rerun_exact 为假）时注明是按参数拼的、codestrata 按 PATH 找、仓库路径是现在这个仓库的、执行目录不是仓库根目录的写成 --cwd（codestrata/web/app.js:218，和 `runs.rerun_command` 的拼法一致，runs.py:1037）；公开页上接着写一句「这是公开页」（codestrata/web/app.js:219，见下面「公开页」）；隐去过东西（rerun_redacted）时写一句：命令里像密钥的值（--env 里的、--api-key 这类选项的）和 URL 里的账号密码已隐去、写成 <已隐去>，下面的 case 命令和进程表也一样，完整的用 `codestrata runs <repo> show <id>` 看（codestrata/web/app.js:222）。录制时继承的环境变量（env_inherited）放在一个默认收起的 details 里，逐行 K=V，有 rerun_env 时再给一个「连环境变量一起」的复制（codestrata/web/app.js:225）——这些变量不在命令里，但被 trace 的命令会继承它们，复刻时要一样。
- **复制**（codestrata/web/app.js:280）：帮助里 hot 这一段每次图回来都整块重写 innerHTML，所以不逐个给按钮挂监听，而是在 #hotbanner 上挂一次事件委托，按按钮的 data-copy（rerun / rerun_env）从最近一次 runHtml 存下的 meta（this._runMeta，codestrata/web/app.js:210）里取字符串——拷的是 meta 里的字符串本身（网页上也是隐去过的那版），不是 pre 里转义过的 HTML。copyText（codestrata/web/app.js:10）：安全上下文里有 Clipboard API 就用它，没有或被拒时退回「选中一个临时 textarea 再 execCommand('copy')」；结果写在按钮上（「已复制」/「复制不了，请手动选中」），1.6 秒后复原。
- **「复刻」按钮**（codestrata/web/app.js:482）：在运行按钮右边，叠着 run、meta 里有 rerun 时出现，静态图上藏着；不看 canSwitchRun，导出版也有。点它打开帮助、把复刻块滚进视野、边框闪一下（codestrata/web/app.js:295）：先摘掉 flash 类、读一次 offsetWidth 让浏览器重排再加回去，连着点也每次都闪（动画在 codestrata/web/app.css:561）。按钮带 data-help（codestrata/web/index.html:45），「点别处关掉帮助」的监听放过带这个属性的元素（codestrata/web/app.js:197），帮助开着时按下它不会先被关掉。
- **阶段表**（codestrata/web/app.js:255）：接在复刻块下面、case 命令上面（codestrata/web/app.js:232）。phase_log 不到两条、也没有 --phase 时不出（codestrata/web/app.js:261）。每行是 phase_log 的一条 [名字, t_us, 来源]，时刻写成秒，没有时刻的写「—」；来源决定第三列（codestrata/web/app.js:263）：start 写「录制开始」，hook 写「第一次进入 qualname 文件:行」（按名字到 phase_at 里找，找不到只写 --phase），sh 写「case 脚本写 PHASE」。老 run 的条目没有来源：名字是 start 的当 start，其余一律当脚本写的。sh 那行的名字在 phase_at 里也有、而且 phase_log 里没有这个名字的 hook 条目时，加一句「同名的 --phase 没起作用」（codestrata/web/app.js:270）——这一段是脚本切的，不是从那个函数开始的。hook 条目事先按名字收进 byHook（codestrata/web/app.js:260），所以这和录制时 cmd_trace 打的同一句警告（__main__.py:353）是同一个条件：按阶段名算，有 sh 条目、没有 hook 条目才算（__main__.py:351）。同一个名字先被 --phase 切过、后来脚本又写一次时，网页和 CLI 都不标，两边说法一致。phase_at 里有、phase_log 里一次都没出现的，补一行「没切到：qualname 这次没被调用」（codestrata/web/app.js:273；行带 idle 类，变淡的只有 qualname）。按名字查的三张表（at、fired、byHook）都用 Object.create(null)（codestrata/web/app.js:258）：阶段名可以叫 constructor，普通对象上 X['constructor'] 是 Object 的构造函数、永远为真——at 会以为有同名的 --phase，byHook 会以为有 hook 条目，fired 会以为已经切到，叫 constructor 的阶段在这几处就都判错了。
- **阶段按钮的悬停**（codestrata/web/app.js:499）：runBar 按阶段名拼好悬停（函数数，再加下面这一句），作为 tips 交给时间轴，由 timebar.js 转义后写进按钮的 title（codestrata/web/timebar.js:86）。这个阶段确实是 --phase 切出来的（phase_at 里有它、phase_log 里有它的 hook 条目）才多一句「；从第一次进入 qualname 开始」，被脚本同名抢先的不写。时间轴只在 serve 里出，导出版看阶段怎么切只能看帮助里的表。
- **图上的阶段起点 / 终点**：phaseBounds（codestrata/web/app.js:554）按 phase_log 的顺序定选中阶段的起点（它自己的触发函数；第一个阶段 start 没有，算程序开始）和终点（下一个阶段的触发函数，没有就是程序结束），节点来自 payload 的 `phaseMarks`。phaseMarks（codestrata/web/app.js:566）据此给出要标的节点：选了阶段标绿 ▶ 起点、红 ■ 终点；「全部」给每个阶段的起点标 ▶；选的是时间段时，只标第一次开始落在这段时间里的阶段（按 meta 的 timeline 找）。每次画图前放进 CS.graph.phaseMarks，graph.js 的 setPhaseMarks（codestrata/web/graph.js:423）把节点框描成绿 / 红、框上写一行字，同一节点有几个就往上叠，重画后再套一遍（codestrata/web/graph.js:261）。时间轴那一栏后面也用文字写出「▶ 起点 X ■ 终点 Y（切到 Z）」（codestrata/web/app.js:509，选的是时间段时不写）；颜色是 app.css 的 --pstart / --pend。

### 公开页（M8.1，`graph --public`）
目标：导出的页面要放到公网上（GitHub Pages），里面不能带本机的个人信息。做法是**在打包之前改数据，前端几乎不动**：`cmd_graph` 带 --public 时先收一份要保留的目录（仓库，加上每个 --hot 的 run 录制时所在的目录——PATH 里的 venv 往往在那下面，__main__.py:127），再调 `payload.publicize`（__main__.py:163），`render.export` 拿到的已经是改过的 JSON，照旧整份塞进去。除了这份 JSON，render 往 HTML 里放的只有前端文件和标题；标题用的是仓库的目录名（__main__.py:164），不是路径，所以只在 payload 上查主目录就够了。publicize 做的事（细节在 payload 的解读里）：
- 所有字符串里的主目录写成 ~（payload.py:1050，后面紧跟着字母、数字、_、-，或「. 再跟一个这样的字符」的不算，所以 /home/x.bak 不换、句末的 . 照换）；
- run 元数据——hotMeta、hotBy 里各 run 的 meta、cmp.meta_b（payload.py:1101、payload.py:1103、payload.py:1106），也就是帮助里「这次跑了什么」和对比横幅用的那几份——里的 PATH / LD_LIBRARY_PATH / PYTHONPATH 这种目录列表（复刻命令、case 命令、进程 argv 里整个参数是 PATH=… 或 --env=PATH=… 的，和 env_inherited 里这三个键），只留上面那些目录下面的段，其余连续几段合成一个 …；命令的其余部分只换主目录。要保留的目录里空的、/、主目录本身和它的上级都剔掉（payload.py:1054）：不剔的话主目录下面的段（~/.local/bin 这类）都算在要保留的目录下面、原样留下，给了 / 更是整条 PATH 都留下；
- 最后置 public 为真（payload.py:1151），再把整份 dump 成 JSON 查一遍，还有主目录就不写出（payload.py:1155）。

前端这边：
- **标记**（codestrata/web/ds.js:28）：CS.ds.public = !!EMB.public，只在 embedded 分支里有。live 分支没有这个字段，serve 里永远是假——serve 的数据不经过 publicize，给的是本机上的原样。
- **复刻块里的说明**（codestrata/web/app.js:219）：CS.ds.public 为真时多一句「这是公开页：路径里的主目录写成了 ~，PATH 这类目录列表里项目以外的部分省略成了 …，所以命令不能原样执行；原样的在录制的机器上用 `codestrata runs <repo> show <id>` 看」。排在「老 run 按参数拼的」之后、「已隐去」之前，几句可以同时出现。放在复刻块里，因为会被人拿去执行的就是这里的命令和环境变量；「复制」按钮拷的是 meta 里的字符串（见上面「复制」），在公开页上也就是带着 ~ 和 … 的那版，不是原命令。在导出里换到别的 run 时帮助整块按它的 meta 重写，那份 meta 在 hotBy 里同样公开过，这句照样出；换到「静态图」时帮助里 hot 这一段整个清空，这句也跟着没了。
- **Ctrl+点击的列号**：源码行（files / sources 的 lines）里的主目录也换成 ~，这一行上 xref.toks 的列号就对不上了。publicize 按 UTF-16 算出每处主目录的位置和长度（payload.py:1121），把这一行上排在它后面的名字往左挪，跨着主目录的名字直接去掉（payload.py:1130）。UTF-16 是因为 viewer.js 包名字时用的是文本节点里的下标（codestrata/web/viewer.js:27），JS 字符串按 UTF-16 数，scan 时 xref.toks 也就是按 UTF-16 记的（xref.py:871）；于是 viewer.js 不用知道有公开页这回事。
- **链接模式加 --public**（M8.2）：页面里的 JSON 照样过 publicize（site.py:241），前端这几条都不变。从 GitHub 现取的源码不经过它——那些文件本来就公开在 GitHub 上，页面拿到的是 GitHub 上的原样。随页面带上的本地版本在 site 里过一遍同样的换 ~ 和挪列号（site.py:295），写出后还逐个文件查一遍主目录；被 .gitignore 忽略的本地文件只带名字和大纲、不带源码，viewer 打开时整页说明（见「viewer 在链接模式下多出的几样」）。

### 源码从 GitHub 取（M8.2，`graph --link github`；ds.js 的 linkedDs）
目标：单文件导出要把源码塞进 HTML，受单文件宿主 16 MB 的限制（vllm-omni 1600 多个文件只装得下两百多个）；而扫的仓库基本都在 GitHub 上，源码不必自己带。链接模式的 index.html 只内嵌图、解读、run 这些小的（EMB 里没有 files、sources、xrefTargets、edges、search，test_site_export 断言了这一条），源码在页面上按**扫描时的提交号**现取，codestrata 自己算的放在旁边的 data/<提交号前缀>-<哈希>/ 里按需取。EMB.link（site.py:311）告诉前端这些：owner / name / sha / prefix（扫的是子目录时，它在 git 仓库里的相对路径）、code（取源码的地址模板，默认先 jsDelivr 再 raw.githubusercontent.com，site.py:47，`--code-base` 可换）、blob（github.com 上看文件的地址模板）、data（data 目录）、files（文件表，下标就是序号）、local / unpublished / stale（三组序号）、refBuckets / attrBuckets（桶数）。
- **取原文**（text()，codestrata/web/ds.js:227）：按序号分三种。unpublished（`--public` 时被 .gitignore 忽略的本地文件）直接拒绝并说明（codestrata/web/ds.js:230）；local（GitHub 上那个提交里没有、或内容不一样的）取随页面带上的 data/src/<序号>.txt（codestrata/web/ds.js:231）；其余按 K.code 的顺序一个个试（codestrata/web/ds.js:233），前一个失败才试下一个，每个的失败原因（超时单独写成「→ 超时」）攒起来，全失败时拼成一句「从 GitHub 取不到 f（…；…）」。地址里是提交号，不是分支名：行号、Ctrl+点击的列号都是扫描时的，只对得上那个提交。路径按段 encodeURIComponent，前面拼上 prefix（codestrata/web/ds.js:223）。
- **限流**（codestrata/web/ds.js:201）：取原文的请求排队，同时最多 6 个在等响应，每个等到响应头最多 20 秒、到时就 abort；响应头一到就让出名额、清掉计时（codestrata/web/ds.js:211），之后读正文既不占名额也不再计时。引用栏一次要取很多文件的原文，一个被一百多个文件用到的名字不能一下子打出去一百多个请求。只有原文（GitHub 和 src/）走这个队列；data/ 下的 JSON（dj，codestrata/web/ds.js:215）一次点击只取一两个，直接 fetch。两种都包在 once 里（codestrata/web/ds.js:197）：同一个请求只发一次、结果缓存；失败了把缓存删掉，下次再点会重试。file() 和引用栏填原文共用原文的缓存，引用栏取过的文件再打开不用重下。
- **data/ 取不到时怎么说**（codestrata/web/ds.js:218）：页面是 file:// 打开的，说要放到 http(s) 上看（浏览器不许 file:// 页面去取旁边的文件）；404 说「这个页面的数据已经换了一版（重新部署过）：刷新一下」。数据目录名里带着这次数据的哈希（site.py:310），重新部署之后旧目录没了，还开着的旧页面按旧文件表的序号去取只会 404，不会取到新数据里同一个序号的别的文件——按版本分目录就是为了这个。file() 取回 f/<序号>.json 后还核一遍里面记的路径和要的路径一样（codestrata/web/ds.js:280），对不上同样让刷新。
- **file()**（codestrata/web/ds.js:275）：先取 f/<序号>.json（语言、行数、大纲、跳转，和 serve 的 /api/file 同形，只少 lines）。unpublished 的不取原文，返回一个 lines 为空、带 unpublished 的对象（codestrata/web/ds.js:281）。其余取原文、hlLines 高亮，再拿行数和 f/<序号>.json 里的 n_lines 比（codestrata/web/ds.js:284）：对不上就记下 mismatch、行数改成取回来的、xref 换成 stale 的空表——行列号会指错地方，不如不给 Ctrl+点击。n_lines 按扫描器的口径数（site.py:174：\r\n 和单独的 \r 都算换行），浏览器只按 \n 切，所以有单独 \r 的文件一定判「不一样」（test_site_export_edges 拿一个 `x = 1\ry = 2\n…` 的文件断言 n_lines 是 5）；这是故意的，不然 \r 之后的行号全错一行。
- **符号片段**（source(k, where)，codestrata/web/ds.js:296）：没有导出时切好的片段了（EMB.sources 不在），任何符号都现切：整个文件高亮之后从定义那一行起切 40 行，和 serve 的 /api/symbol 一样（`payload.symbol_source` 也是整文件高亮再切，从中间切会让跨行字符串着色出错，payload.py:829）；跳转只留这 40 行里的 token（codestrata/web/ds.js:310）。符号在哪先查 EMB.pkgSyms，但它只有顶层的类和函数；方法、嵌套函数要靠 panel.js 传进来的 where（文件、行）去取那个文件的大纲、按 key 找（codestrata/web/ds.js:298），大纲里也没有就用 where 的行号、名字取 key 的最后一段。panel.js 改成 source(key, where) 就是为了这个。
- **边详情、搜索**：第一次点边时取 data/edges.json，交给和 embedded 同一个 edgeFrom（codestrata/web/ds.js:318），选了静态图、换了别的 run 时照样只留静态引用；搜索索引第一次搜时取 search.json（codestrata/web/ds.js:319）。
- **引用**（refs()，codestrata/web/ds.js:322）：和 serve 的 /api/refs 同一份数据（`xref.invert` 的倒排），所以是**全仓**的引用，不再是 embedded 那种「只在内嵌了全文的文件里找」，也不带 partial。倒排按目标串的 32 位 FNV-1a 分桶（codestrata/web/ds.js:243，和 `site.fnv1a` 同一个算法：UTF-8 字节、Math.imul 做 32 位乘法），一次点击只取一个桶。site 那边空桶也写（site.py:276）、没被引用的定义也放进倒排（site.py:272），所以按桶号取不会 404，引用栏也照样有「定义」那一行。同一行的几处合成一条、种类取「调用 > 引用 > import」里最靠前的，排序和 embedded 用同一张 RANK。「这次 runtime 调用 N 次」只在看的是主 run 时给（codestrata/web/ds.js:339）：选了静态图、换了导出时带上的别的 run 都不给，和边详情同一个道理——EMB.hot.symbols 只有主 run 的逐函数次数。成员（`s:` / `v:` 目标里带 `.` 的）另取 attrs/ 的桶，拼出「同名的 .xxx」一组（codestrata/web/ds.js:345），取不到只丢这一组。行落在扫描之后改过的文件里的标 stale，viewer 里写「改过」。
- **原文后到**：倒排里只有位置，没有那一行的原文，原文得从 GitHub 取所在的整个文件。refs() 先把列表交出去，行的 text 是空串；定义那行和前 200 行（TEXTS，codestrata/web/ds.js:270；「同名」一组另算它自己的前 200 行，codestrata/web/ds.js:356）各自去取所在文件（每个文件一次），取到就把那一行填进行对象（fill()，codestrata/web/ds.js:263，取不到的留空串）；全部有了结果（成功或失败）之后 r.more 兑现（codestrata/web/ds.js:360），viewer 收到就按同一个目标再画一次（codestrata/web/viewer.js:311）。于是列表马上就能点，原文晚一步出来。

### viewer 在链接模式下多出的几样
- **GitHub ↗**（codestrata/web/viewer.js:177）：有 CS.ds.blobUrl（只有链接模式有，codestrata/web/ds.js:274）、而且不是本地版本的文件，抬头多一个链接，指向 github.com 上扫描时那个提交的这个文件，带 #L 行号。href 在按下鼠标或获得焦点时按当前文件和 curLine 重算（codestrata/web/viewer.js:197）：curLine 是最后点过的那一行、或者从大纲 / 跳转定位到的那一行，所以新标签页里打开的是正在看的位置，而不是打开窗口时的那一行；只滚动、不点，它不变。本地版本不给这个链接：GitHub 上没有这个版本，链过去看到的和页面上的不一样。
- **本地版本**（codestrata/web/viewer.js:176）：f/<序号>.json 里带 local 的，抬头标「本地版本」，悬停说明扫描时本地改过或没进 git、是随页面带上的。哪些算本地版本由 site 按 blob 哈希和 HEAD 比出来（skip-worktree、软链接这种 git status 看不出的也算），见 site 的解读。
- **和扫描时不一样**（codestrata/web/viewer.js:172）：file() 标了 mismatch 的，抬头写「GitHub 上的这个文件和扫描时不一样：没给 Ctrl+点击」，悬停里给两个行数。它排在「文件在 scan 之后改过」前面：mismatch 时 xref 也是 stale 的，两句只出一句，出说得准的那句。
- **打不开的文件**：file() 返回 null 时，链接模式说「这个文件不在扫描范围里」，不再说「没有内嵌进导出版（体积上限）」（codestrata/web/viewer.js:124）——链接模式没有体积上限。公开页没带源码的（unpublished）单独一整页说明（codestrata/web/viewer.js:131）：它被 .gitignore 忽略（可能是本地配置），扫描时在本地、GitHub 上没有。
- **panel 的片段**：source 给了 null、退回去取整个文件的那次 file() 失败时，现在接住并写「读取失败：…」（codestrata/web/panel.js:512）；之前这条 promise 没人接，槽里一直停在「读取源码…」。

### hl.js：照抄 Pygments 的状态表
为什么文本要逐字符保真（颜色和 Pygments 差一点没关系）：Ctrl+点击的 token 是 scan 时按源码算的（行、UTF-16 列），viewer 包名字时数的是这一行高亮 HTML 里文本节点的下标（codestrata/web/viewer.js:27），所以高亮之后去掉标签的文本必须和源码那一行一字不差；行数还要和 n_lines 比，不能多切少切。颜色差一点只是难看，文本差一个字，这一行后面的跳转就全错位。
- **状态表**：py()（codestrata/web/hl.js:33）和 cf(cpp)（codestrata/web/hl.js:92）照抄 Pygments 的 Python、C / C++ 词法器的规则（Triton 用 Python 的，CUDA 用 C++ 的，codestrata/web/hl.js:186），每条是 [正则, 类名或 bygroups, 新状态]；正则里用反引号加一个字母的占位符代表 Pygments 的行首 ^、按 Unicode 算的词尾这类写法（codestrata/web/hl.js:12）。
- **一个状态一条大正则**（build()，codestrata/web/hl.js:167）：每条规则包一组、按顺序用 | 拼成一条，带 y（粘连：只在当前位置匹配）和 u（\p{…} 的 Unicode 类）（codestrata/web/hl.js:180）。Pygments 按顺序试规则、第一条匹配的胜出；JS 的交替在同一个起点上也是从左往右试、第一个成功的胜出，所以一次 exec 就等于逐条试一遍。每条规则的外包组号要记下来，组数用 `new RegExp('|' + s, 'u').exec('')` 数（codestrata/web/hl.js:178）：空串一定匹配前面那个空分支，返回数组的长度是 s 里的组数加一，正好是这条规则包上外层括号之后占的组数。
- **词法循环**（lex()，codestrata/web/hl.js:192）：照搬 RegexLexer.get_tokens_unprocessed。找到第一个有值的外包组，按类名或 bygroups 吐 token（bygroups 里写成状态栈的就是 using(this)，拿这一段递归再词法一遍，codestrata/web/hl.js:208；各组没盖满整段时整段无色），再推 / 弹状态。行尾没有规则能匹配时回 root；一个字符什么都匹配不上时原样吐一个码点（Pygments 的 Error token）。连续 64 次空匹配就当作没匹配，防死循环（codestrata/web/hl.js:197）。
- **重标**（retag()，codestrata/web/hl.js:238）：C 系的类型名（size_t、int32_t…）、CUDA 的关键字和向量类型、Triton 的 tl.xxx 和 @triton 装饰器，对应 Pygments 词法器自带的重标和 `highlight._tokens` 里的专属重标（highlight.py:100）。
- **切行**（lines()，codestrata/web/hl.js:275）：同 `highlight.to_lines`，跨行 token 在换行处闭合、下一行重开。和 Python 版不一样的地方都是为了文本保真：Pygments 预处理时去掉的 BOM 和 \r\n 里的 \r，这里原样补回（codestrata/web/hl.js:282、codestrata/web/hl.js:293）；相邻、类名相同的 token 合成一个 span（Python 版每个 token 一个）——HTML 不是逐字节一样，但合并只会让文本节点变长、不会把一个名字切开，viewer 照样包得上。
- **对拍**：`tests/hl_parity.py`（要 node，不在 pytest 里，手动跑）逐文件比 JS 版和 highlight.py：保真（去标签、反转义后和源码逐行一字不差，转义写法和 html.escape 一样）必须 100%，行数、detect / label 必须一致；类名按非空白字符比一致率，门槛是 Python / Triton 95%、C / C++ / CUDA 85%。设计稿 M8.2 记的是在 vllm_omni + codestrata 与 2.2 万个 C/C++/CUDA/Python 文件上逐字符、逐 token 类都与 Pygments 一致；对拍脚本的类名门槛却留了 5% / 15% 的余地，两种说法对不上，这里没重跑对拍，说不准现在的一致率。

### 找不到调用那一行时怎么说（panel.js 的 via）
边详情每张卡片的 from 是调用方里调它的那一行。按什么写法去找由服务端 `payload._call_form` 定，并在调用方上记下 how（怎么找的）和 form（页面上怎么称呼那种写法）。找过但没找到时（sites 是空数组），卡片拿调用方的签名当 from，下面一句由 via()（codestrata/web/panel.js:40）按 how 说原因（codestrata/web/panel.js:85）：
- call（按名字找 `名字(`、`'名字'`、`@名字`）：没直接写 名字(…)，是经由变量或别名（cls(…)）、__call__、装饰器、回调或仓库外的代码调到的；
- attr（property，按 `.名字` 找）：这个属性是经由 getattr、代理对象或仓库外的代码取的；
- implicit（__call__、__getattr__ 这类从写法上认不出的特殊方法）：「对象(…) 隐式调到它：看不出是调用方里的哪一行」——不是没找到，是本来就指不出；
- syntax（with、for、[]、运算符、if 对象 触发的特殊方法，服务端按语法树找记号）：只说「调用方里没找到 with … 这种写法」，原因两种都列、不下结论：可能是仓库外的代码触发的（contextlib、sorted 之类），也可能是没有记号的隐式触发（解包、当参数传进内置函数、容器里比较之类）。按语法只认得出写在明面上的记号，说不准是哪一种。

原来只有一句「没直接写 名字(…)：中间经过 __call__、回调或仓库外的代码」，对 __enter__、__bool__ 这种由语法触发的方法，名字本来就不会写出来，说「没直接写」等于什么也没说。没找过（sites 不存在）时不出这句。

### hot 横幅：调用和定义分开数
横幅上原来一个数「未归到命名符号的调用」，悬停把 lambda、闭包、生成器表达式和模块顶层执行说在一起。trace 现在把 import 时模块顶层的执行、class 语句跑类体当成定义，`runs.load` 的 meta 分成两个数：unmapped 只剩闭包 / lambda / 生成器表达式（runs.py:800），defs 是模块顶层和类体的帧数（runs.py:802）。横幅也分两处写（codestrata/web/app.js:751、codestrata/web/app.js:754）：「未归到命名符号的调用 N」，和「定义时的执行 N（不算调用）」，后者悬停说明只定义过的类、只被 import 过的模块不算「跑到了」。前者是真调用、只是落不到命名符号上，后者根本不是调用（runs.py:801 的注释），混在一个数里会把定义说成调用。导出里别的 run 也带 defs（`_meta_brief` 的字段表，payload.py:142）。

### 过期文件
Ctrl+点击的行列号是 scan 时的快照。文件在 scan 之后改过（大小或修改时间变了，payload.py:918），链接会落在别的字上，所以宁可不给：全文窗口标一句「重新 scan 才能 Ctrl+点击」，引用列表里来自改过文件的行标「改过」。hot 图另有一套判断（和录制时记下的文件哈希比）：录制后有文件改过时，hot 标记和运行列表里标「⚠ 录制后改过」。但改过的文件不再整份当成不准：M6 起 `runs.load` 在建 hot 图之前先按录制时记下的函数名（qualname）把次数挪到函数现在的行号上（`runs.remap`），帮助里的横幅按这件事分三处说：
- 过期文件那句写「N 个文件改过或删掉了；改过的已按函数名把次数挪到函数现在的位置」（codestrata/web/app.js:762）。N 和悬停列出的文件都包括删掉的，但「挪过」只说改过的：删掉的文件现在没有函数可对，remap 不碰它们，横幅只是把它们列出来。
- 安装包那句：录制时跑的安装包和仓库有文件不一致时，写「其中 N 个与仓库内容不一致（已按函数名对到仓库里的位置）」（codestrata/web/app.js:758），不再说行号不可信——remap 对这些文件（mismatch）和改过的文件一样处理，行号已经按名字换成了仓库里的。
- 对不上的单独一句：hotMeta.unmatched 大于 0 就出「⚠ N 处按函数名对不上：这些调用只算到文件上，不算到函数上」（codestrata/web/app.js:763），不挂在过期文件那句下面。因为 mismatch 文件也会 remap，却不算进 stale_files——挂在下面的话，只有安装包不一致的 run 就看不到对不上的个数。后半句照实说 remap 怎么处理这些键：改成「文件:-1」，次数还算在这个文件（和它的模块）上，不落到任何函数上，因为原来那一行现在可能是别的函数的定义。悬停列出对不上的三种原因：lambda、生成器表达式没有名字；改了名、删了的函数找不到；老的 run 没存函数名。最后一种要写出来：老 run 改过的文件里每个键都对不上，N 会很大，不说原因，看的人会以为按名字挪这件事坏了。

这么分是因为挪过之后绝大多数叠加是准的：函数下移几行、加了注释都对得上，再笼统地说「可能偏」，看的人会把整张 hot 图都当成不可信、跑去重录；真正落不到函数上的只剩对不上的那几处，就把个数给出来。N 数的是计数的键（一个「文件:首行号」算一处），不是调用次数。

## 局限
导出版是固定的一个切面加一份有限的数据：
- 不能展开 / 收起（「＋ / −」不画）；排版宽度是导出时定的，窗口变宽只按比例放大（最多 1.25 倍），不像 serve 按图框宽度重排
- 能换的 run 只有导出时用 --hot 带上的那几个，每个就是导出时点名的那个阶段，不能换阶段，也没有时间轴。除了主 run，别的 run 只带图上的次数：没有逐函数的次数，边详情只列静态引用；只在它的 runtime 里出现、主 run（带了 --compare 的还有 B）里没有的边，点开只有「导出版里没有这条边的详情」——内嵌的边详情只给主 run 的图、它的 runtimeOnlyEdges 和仅类型的边算过（payload.py:1222、payload.py:1224）
- 对比只能是导出时 --compare 定下的主 run 对第二个 run，只在叠着主 run 时显示，不能在页面上另选 B
- **没有「时间顺序」**：时序事件一律不嵌入（M7 的多 run 导出也不嵌），边的开关里不出这一项
- 搜索能用（名字索引内嵌了，payload.py:1227），但点一个被收着的模块只能选中装着它的节点
- 整个文件控制在 14 MB 以内（`total_budget`，payload.py:1161；单文件宿主上限 16 MB）：先算好其余部分（带上的别的 run 也算在里面，只有切面上的次数，占得不多），剩下的额度才给全文，这次跑到过的文件和解读里引用过的文件优先。xref 目标全文件共用一张表（payload.py:1206），省下的额度能多带一两百个文件。链接模式没有这个预算：`code=False` 在算全文之前就返回了（payload.py:1228）
- 没带全文的文件只能看顶层符号；Ctrl+点击跳向这种文件时只提示、留在原地；「谁引用了它」只在内嵌了全文的文件里找，会标明结果不全（这三条链接模式都没有：所有文件都能看、能跳，引用是全仓的；--public 时被 .gitignore 忽略的文件除外，只有大纲）
- 不能写解读、不能跳编辑器；要这些用 serve
- --public 导出的：复刻命令、case 命令、进程表、环境变量里带着 ~ 和 …，不能原样执行，要原样的得回录制的机器上 `runs show`；源码（全文和详情栏的片段）、解读正文里的主目录也写成了 ~，看到的不是文件的原样（链接模式从 GitHub 取的源码不换，是 GitHub 上的原样）；名字跨着主目录的那几处不能 Ctrl+点击。publicize 只管主目录和那三个目录列表：主目录以外的个人路径（比如 /mnt/data/用户名）、别的环境变量的值（除了其中的主目录）照原样出现在页面上

链接模式（`--link github`）另有这些：
- 要联网、要放在 http(s) 上：源码现取，data/ 按需取，file:// 打开时 data/ 一个都取不到（页面会这么说）。源码是匿名跨域取的，只对 GitHub 上公开的仓库有用
- GitHub 上的文件和扫描时行数对不上的（最常见的是有单独 \r 的文件）不给 Ctrl+点击；行数碰巧一样、内容不一样的查不出来，跳转会落在别的字上。按提交号钉住、本地改过的随页面带上，正常情况下遇不到
- 不支持后行断言的老浏览器（Safari 16.4 之前）上源码没有颜色
- 引用栏最多列 500 行，只有前 200 行（和定义那一行；「同名」一组也一样）去取原文，第 201 行起只有行号和种类（codestrata/web/ds.js:270）；原文要等这 200 行涉及的文件全部取完（或失败）才一起出来，其中一个文件卡住，就要等它的 20 秒超时、再试下一个地址

serve 里的时间顺序：
- 取回来之前图上不上色（大 run 第一次要解压整个 run，两秒多），只有开关上的「…」
- 序号牌只避让节点框和别的牌子，不避让边；七个位置都挡住时叠在中点上
- 对比时不出（开关只在叠着一个 run、不对比时有）

serve 里的时间轴：
- 选时间段要录了时序事件；次数只有跨文件的调用（服务端按时序事件现算），函数、文件、节点上的数和按阶段看的口径不同（横幅上写明）
- 看的范围（缩放）只在页面内存里，刷新后按选中的范围重新放大

serve 里的对比：
- 只影响模块图和详情栏；「时间顺序」在对比时不出
- 同一个 run 的两个阶段在对比列表里选不到（列表把 A 的整个 run 都排除了），虽然地址里写「cmp=A 的 id@别的阶段」前端和服务端都接受

## 不确定
- render.py:35 把 `</div>\n\n` 替换成同样的字符串，是个空操作，看起来是早先改动留下的。
- 对不上那句的悬停只说「老的 run 没存函数名」。用 Python 3.10 录的新 run 也没有函数名（3.10 的 code 对象没有 co_qualname，trace.py:257 就不记），改过的文件里同样每个键都对不上，但悬停列的三种原因里没有这一种，看的人会以为是 run 太老。
- 导出版地址里的 run= 如果是 case 名、或者是没带上的「id@阶段」，启动时按 id / case 名在列表里找得到，不提示；graph() 在 hotBy 里按完整键查不到就退回主 run，图回来后地址也被改写成主 run——等于悄悄换成了主 run。
- 「只有对比的 run（B）调到」一组只收 A 的明细里根本没有的符号（`edge_compare` 的做法）。代码里有静态引用、A 没调、B 调到的符号留在「引用了，但这次 case 没走到」一组，写「A 0 / B n」，也不算进那一组的个数；看个数会低估两个 run 在这条边上的分歧。
- 隐去有几处边界：名字像密钥的选项后面紧跟着 - 开头的参数时，当它是开关、下一个参数不隐去（runs.py:993），这样 `--no-auth --port 80` 里的 `--port 80` 不会被吃掉，代价是本身以 - 开头的密钥值会原样出现在复刻块、case 命令和进程表里。复刻块里那句提示只看 rerun_redacted（codestrata/web/app.js:222），而它只比较复刻命令隐去前后是否不同（runs.py:820）：子进程的 argv 里有要隐去的、复刻命令本身（codestrata 那一段和 case 命令）没有时，进程表里出现 <已隐去>，页面上却没有那句说明。
- 公开页的说明（codestrata/web/app.js:219）说「PATH 这类目录列表里项目以外的部分」省略成了 …，ds.js 那行注释（codestrata/web/ds.js:27）说「PATH 里项目以外的目录」，实际留下的还有各 run 录制时所在的目录（__main__.py:127）；--public 的帮助（__main__.py:651）说的「仓库和录制目录以外」才对得上。run 在仓库外的目录里录时，PATH 里那个目录下面的段（比如那边的 venv）原样留着，说法比做法窄。
- 链接模式里详情栏的片段取不到时不说原因。panel.js 新加的 catch（codestrata/web/panel.js:512）只管「source 给了 null、再取整个文件失败」这一条路；可链接模式里片段取不到，最常见的是 GitHub 取不到原文，这时是 source 自己失败（它里面调的 file() 失败了），走的是原来外层的 catch（codestrata/web/panel.js:546），只把槽清空：「读取源码…」显示到失败为止，然后槽就空了。「整个文件」按钮在片段的抬头里，槽清空了也就没有；要从文件树那一行的「全文」（codestrata/web/panel.js:347）打开全文窗口，才看得到「从 GitHub 取不到…」。
- panel.js 退回全文窗口时的两句说明没按链接模式改：file() 给 null 时仍说「导出版的体积有上限，没带上这个文件」（codestrata/web/panel.js:519），而 viewer 那边已改成「不在扫描范围里」；公开页没带源码的文件，source 给 null、file() 给的却是带 unpublished 的对象，于是说「导出版里没有这个符号的片段，在全文里看」，点过去才看到「公开页没带这个文件的源码」。
- ds.js 里 refs 的注释（codestrata/web/ds.js:321）说原文「取到一批更新一次」，设计稿也说「陆续填」；实际只有一个 r.more，要等前 200 行涉及的文件全部有了结果才兑现，viewer 只重画这一次（viewer.js 那行注释「取齐了再画一次」才是准的）。中途要是别的原因重画了引用栏（比如跳到另一个文件），已经填进行对象的原文会先出来一部分。
- 「GitHub 上的这个文件和扫描时不一样」对本地版本说错了来源：随页面带上的 src/<序号>.txt 里 \r 原样留着（site.py:259），有单独 \r 的本地文件照样按 \n 切出更少的行、判成 mismatch，抬头于是同时出「本地版本」和「GitHub 上的这个文件和扫描时不一样」（codestrata/web/viewer.js:172），悬停里还说是从 GitHub 取的。不给 Ctrl+点击这一点是对的，只是说法不对。
- `--link github` 时 `--fragment` 不起作用：`site.export_site` 调 `export` 时不传 fragment（site.py:337），`cmd_graph` 的链接分支也在用到 a.fragment 之前就返回了，不报错也不提示。
- 页面上说「这是公开页」的只有复刻块这一处，它在帮助里（要点开「?」或「复刻」才看得到），只在叠着 run 时出。--public 却没带 --hot 的导出、或者在多 run 导出里选了「静态图」时，页面上没有任何地方说明源码、路径、解读里的 ~ 是改过的。
