## 这个仓库做什么
codestrata 给一个 Python 仓库（论文代码、vLLM 这类开源框架）画**共用坐标**的图。模块图有两种底：总图来自静态分析（`ast`），hot 图是在它上面叠一个真实 case 跑起来时录下的 runtime 调用。M5 之后多了一张时序图：同一次录制里跨模块的调用按时间先后排开，生命线就是模块图上当前显示的那些节点。三者共用同一个切面（图上显示到目录树的哪一层）和同一份选中，在模块图上展开一个目录，时序图也跟着细到它下面的子模块。图下面接着就能读代码：点节点看文件树和源码，全文窗口里 Ctrl+点击跳到定义、列出引用，搜索栏按名字找模块 / 文件 / 函数。再留出一层给人或 LLM agent 写「为什么这样切、算法为什么这么写、该按什么顺序读」。

两种数据的份数不对称：静态分析只有一份（当前工作区的快照，scan 时整份替换）；runtime 可以有很多份。每次 trace 都存成一个新的 **run**，同名 case 重录也不覆盖：今天录 MiniCPM、明天录 Qwen，两份都留着，录一次就能反复叠到图上，网页上随时在静态图和各个 run 之间切换，不用重启。这样做是因为 run 重建不了，一次录制往往要几分钟 GPU（`docs/design/runs.md` 第 1 节）。留着多份，最直接的用处是比：M7 起可以再挑一个 run（B）和当前叠着的（A）放在同一张模块图上，只有 A 跑到的画橙色、只有 B 跑到的画紫色、两边都跑到的画前景色，节点上写「A/B」两个次数。比如 MiniCPM@serving 对比 Qwen@serving，一眼看出两个模型各走了哪些代码。对比只有两路，而且只在模块图上，时序图仍只画 A。

录的时候还可以顺带记**时序事件**（trace --events）：每一次跨文件调用在什么时刻开始、什么时刻返回、中间挂起过几次。收尾时整理成 span 存进 run，时序图每次打开时再按当前切面现画。

输入是一个仓库目录和其中要扫的几个目录，加上可选的 case 命令。这两样选择都交给用户：扫哪些目录（包、src/ 下的包、tests/、放零散脚本的目录、仓库根目录直接放着的脚本「.」都能选）决定了图上有什么；命令默认在仓库根目录执行，trace --cwd 可以换。产出分三类：`.codestrata/` 下可重建的事实（index / symbols / xref），`.codestrata/runs/` 下**不能重建**的录制（原始数据永久保留，计数和 span 是从它们派生、能重算的），仓库 `notes/` 下**不能重建**的解读。此外还有一个本地网页（serve）或一个单文件 HTML（graph）。扫的仓库在 GitHub 上时，graph --link github 还能导出成一个静态站点目录（M8.2）：源码不内嵌，页面按导出时 HEAD 的提交号从 GitHub 取，所以没有单文件 16 MB 的上限，能放 GitHub Pages。两种导出都可以带上几个 run、在它们之间切换，也可以带上导出时定好的一对对比；时序图只在 serve 里有，导出版不带。以上都是命令行子命令；不想敲命令的，`codestrata app` 在浏览器里给一个主菜单：挑仓库，点按钮替人跑 scan（先在对话框里勾要扫的目录）/ trace、打开图。它不产出新的一类数据，只在用户配置目录里记一份打开过哪些仓库的清单（外加口令和每个仓库一份图服务日志），仓库里的东西仍由那几条命令写（见「主干」第 6 步）。

## 主干
一次典型使用里，数据这样流过各模块：
1. `scan` 读选定目录里的 .py，写出 index.json（文件级的模块、边、高度、目录树、默认切面；`if TYPE_CHECKING:` 里的 import 另记成 `type_edges`，见下面「依赖和调用」）和 symbols.json（符号、边上的引用明细、每个文件的内容哈希）。扫哪些目录：给了 --roots 就照单全收，不给才由 `detect_roots` 猜；主菜单里由用户勾，候选由 `scan.candidate_roots` 列，只列不挑。早先 `scan` 会替用户去掉 tests/、examples/，用户勾了 tests/ 也扫不进来；图上有什么该由看图的人定，猜只是没人给时的退路。--roots 的写法在 `main` 解析完参数时由 `clean_roots` 归一一次（结尾的 /、开头的 ./、重复的，__main__.py:761）。最后一段同名的两个目录（src/foo 和 tests/foo）模块名会撞在一起、互相覆盖，一个套在另一个里面的（src 和 src/pkg）里面的文件会按两个模块名各扫一遍，`check_roots` 两样都挡（同名那一样是 `root_clashes`），一次只能扫其中一个。默认切面就是图上默认显示哪一层，由 `cut` 按规模算出。同一条命令紧接着用同一份 index 调 `xref.build`，写出 xref.json（每个名字指向哪个定义）。这一步由 `cmd_scan` 串起来（__main__.py:85），不放进 `scan`：放在同一条命令里，两份产物才是同一时刻的快照、行号对得上；放在 `scan` 外面，`scan` 就只产出总图事实。
2. （可选）录一次 case，由 `cmd_trace` 缝起来。`runs.new_run` 先建 .codestrata/runs/<id>/（id = 录制时刻 + case 名），`trace.run` 再在 hook 下跑命令。命令默认在仓库根目录执行（case 脚本、复刻命令都按它写），--cwd 可以换，run.json 的 cwd 记的是实际执行的目录；没给 --cwd、命令里的相对路径只在敲命令的目录下有时，`trace.misplaced_paths` 在开录之前就拦下（__main__.py:275；敲命令的目录已经被删了就不查），显式给的 --roots 也在建 run 之前过一遍 `check_roots`（__main__.py:281），不留一个命令起不来的失败 run。把安装包映射回仓库用的 roots 默认取上次 scan 选的（__main__.py:309），录制和图对的是同一批代码。每个 Python 进程（包括子进程和 setsid 出去的服务）往 run 的 parts/ 写分片；停的时候按 SIGINT → SIGTERM → SIGKILL 分三级，再清掉残留进程，最后 `trace.merge` 合并。录不录时序事件只看一个环境变量：CLI 每次都把 CODESTRATA_EVENTS 明确写给命令，--events 时是 1、否则是 0（__main__.py:323）。写 0 是为了 shell 里 export 过的值不会悄悄生效，否则录出来的 run 和它的重录命令对不上。行数上限 CODESTRATA_EV_MAX 的处理正相反：不盖 shell 的值，而是在 `runs.new_run` 写出 run.json **之前**把它抄进 run 的 env（__main__.py:312），run.json 里记着、重录命令里也带着同一个上限（test_events_cap 有从 shell 继承的用例）。hook 看到 1，就给每个有跨文件调用的进程映像另写一份 ev-<pid>-<t0ns>.log，也落在 parts/。收尾经 `after` 回调交给 `runs.finalize`（__main__.py:329）：先存下 case 脚本和配置文件的副本、记下环境和 git，再打包原始数据（分片进 parts.tar.gz，事件日志单独进 events/raw.tar.gz，runs.py:446），然后由 `events.build` 把事件日志配成 span、写进 events/spans/（runs.py:447），最后算出各阶段的计数，定出状态 ok / partial / failed。事后用 runs 子命令（`cmd_runs`）列出、查看、打标签、重算、删除，runs rm --events-only 只删时序事件。
3. `payload` 把这些拼成模块图要的数据。先由 `cut` 把文件级的数据汇总到当前切面的节点上，并给出每个节点直接被哪个展开着的目录套着（展开的目录在图上画成框，前端每次展开 / 收起都会带着新的切面再要一次），再交给 `layout` 算节点和框的坐标。一个 run 的引用（完整 run id 或 case 名，可加 @阶段）由 `runs.resolve` 解析成某一次 run，`runs.load` 用 `trace.to_package_graph` 按**当前** index 现算叠加，并标出录制之后改过的文件（改过的文件先由 `runs.remap` 按录制时记下的函数名把次数挪到函数现在的行号上，M6）；`payload.load_hot` 只是转调它（payload.py:61）。切面上短名撞了的节点（flask.app 和 flask.sansio.app 都叫 app）由 `cut.disambiguate` 补上父目录段（payload.py:174），同一份 alias 交给 `layout` 和前端，图上、详情栏、抽屉标题写的是同一个名字。叠加按切面汇总的那一步抽成了 `_hot_on_cut`（payload.py:84）：对比时 A、B 各调一次，`graph_payload` 在返回里多一个 cmp 块（节点、边上各带 [A, B] 两个次数），只在 runtime 出现的边和「只看跑到的」都取两边的并集。源码交给 `highlight`，解读从 `notes` 取；点开一条边时，由 `edge_detail` 把静态引用和 runtime 调用交叉成五类，对比时换成 `edge_compare`（payload.py:689）：两个 run 各算一遍 `edge_detail` 再按符号合，每项多一个 B 的次数，只有 B 调到的符号单独成一组。每个跑到的函数还配上调用方里调它的那一行，按被调函数在调用处的写法找（`_call_form`，payload.py:446）：普通函数按名字，property 按「.名字」，特殊方法按会触发它的语法（with、for、[]、运算符、真值判断……，`_code_facts` 按语法树认，跳过 docstring、签名和标注，payload.py:336）。面板写明是按哪种写法找的，找不到时说为什么，语法触发的只列可能、不下断言。被用到的名字不在符号表里的（模块级变量、`__init__` 里再导出的类和函数），「to」那一格按 xref 追到的定义给出，和 Ctrl+点击落在同一处。读代码用的三样也在这里：`search_index`（搜索栏一次拿全的名字索引）、`reveal`（让某个模块在**当前**切面上露出来要展开哪些目录）、`xref_for` / `refs`（Ctrl+点击的链接和引用列表）。
4. 交付三选一：`serve` 按请求提供 /api/* 和前端静态文件。叠哪个 run 随请求带着（run=），`Handler._hot`（serve.py:173）解析后按 (run id, 阶段, 计数文件和 run.json 的修改时间) 缓存最近 8 个：计数只在 runs merge 时变；run.json 进键是后补的，因为叠加带着的 tags / 备注在它里面，改了要跟着换。对比的 B 在图和边详情两种请求里随 cmp= 带着，也由 `Handler._hot` 解析，只是换一个参数名（serve.py:320），缓存、失效规则都和 A 一样。B 找不到、或者和 A 是同一个 run 的同一个阶段时，不让请求失败，只叠 A、在返回里说明原因：A 是这张图的内容，B 只是附加的一层，地址里留着一个删掉的 B 不该让整页出不来。--hot 只决定页面打开时先选哪个，启动时仍先加载一遍（serve.py:473），写错了当场报出来。`render` 把同一套前端和 `export_payload` 给的整份数据（固定为默认切面，控制在体积预算内）内联成一个 HTML。导出时可以给几个 --hot（`cmd_graph`）：第一个是主 run，全量嵌入；其余的只带它们在导出切面上的节点、边次数和简要的 meta（EMB.hotBy），页面上能切过去，但边详情里的调用明细只有主 run 的；加 --compare 时前两个另嵌一份对比。别的 run 不全量嵌是为了体积：整个 HTML 要装进 16 MB，`export_payload` 先算图、边详情、源码片段，剩下的额度才给全文，每多嵌一份完整的 run，能带上全文的文件就少一截。第三种是 `site`（M8.2，graph --link github --out 目录），专为绕开这个上限：`cmd_graph` 查过给了 --out、而且不是 .html 文件名，才在函数里 import 它（__main__.py:141）；--out 已经存在、不空又没有 `.codestrata-site` 标记的，`site` 在开算之前就拒绝，免得清掉别人的目录。`site.export_site` 照样调 `export_payload`，只是传 code=False（site.py:209），不带符号片段和全文；codestrata 自己算的东西改写成 data/<提交号前缀>-<哈希>/ 下按需取的小文件（每个文件的大纲和跳转、按 FNV-1a 分桶的引用倒排、边详情、搜索索引），index.html 仍由 `render.export` 拼（site.py:337）。浏览器端高亮 `web/hl.js` 由 render 另用一个 `<script>` 带上（render.py:30；现在所有导出都带，边详情的代码片段也用它）。页面上 `ds.js` 的 linkedDs 替掉取源码、大纲、边、搜索、引用这几样（codestrata/web/ds.js:155）：源码按提交号先从 jsDelivr、不行再从 raw.githubusercontent.com 取（site.py:47），由 hl.js 高亮。GitHub 上那个提交里没有、或内容不一样的文件随站点带上本地版本。除了没跟踪的和 git status 列出的，还有 git status 看不出的两种：软链接一律算（GitHub 上给的是它指向的路径），其余已跟踪的逐个算 blob 哈希、和 git 索引里记的比，抓 skip-worktree 这类本地改动（site.py:113）。--public 时其中被 .gitignore 忽略的不带源码，但文件表、大纲和跳转数据照带，页面上说明没带。细节见 site.py 的模块说明和设计稿 M8.2。
5. 时序图（M5，只在 serve 里）接在第 2 步写下的 events/spans/ 后面：keys.json（「文件:首行号」键表）、index.json（每块的进程和时间范围）、按进程、按开始时刻分好块的 p<pid>-NNN.jsonl.gz。页面发来的 /api/seq、/api/seq/overview、/api/seq/find 都进 `Handler._seq`（serve.py:204）：它用 `runs.resolve` 找到 run 的目录，切面先过 `payload._norm_open`（serve.py:218），和模块图走的是同一道，两张图的节点才对得上；参数解析好后交给 `seq`。`seq.build` 只读和时间窗重叠的块，把每个 span 两端的「文件:首行号」经 rel → 单元 → 当前切面的节点（`cut.view`，seq.py:125）映射成生命线 (进程, 节点) 之间的消息。两端落在同一节点的、定义时的执行（import 触发的模块顶层、类体，和模块图同一个 `trace.defining`）、落在 index 之外的（包括 case 自己的代码）都不画，只计数。画不下时才把重复的片段折成 loop 行，没给窗口时从当前阶段的起点自动收窄到一屏（默认 300 行）。`seq.overview` 给时间刷算每个进程的调用密度；`seq.find` 给模块图抽屉里的「在时序图里看」找一条边第一次被调用的时刻，先在 run 选的阶段里找。最后 `codestrata/web/seq.js` 只管画，并把点击翻译成新的请求。
6. 主菜单（`codestrata app`）是另起的一个进程，站在上面五步外面，不改它们的走法：它不在自己进程里调 scan / trace / serve 的函数，而是替人去敲那几条命令。按副作用分成四块（分法和理由见 projects 的解读）：`projects` 只查数据（项目清单、每个仓库的卡片、挑文件夹、--phase 的函数名补全、扫描对话框的候选目录），.codestrata/ 里的东西一律经 `payload`（`index_summary`、`index_lag`、`load_index`）和 `runs`（`has_runs`、`catalog`）读，看状态不往仓库里写（没录过的仓库不会因此多出 .codestrata/runs，projects.py:105）；候选目录由 `projects.scan_choices` 从 `scan.candidate_roots` 取，再并进上一次选的，重新扫描时预先勾好、命令行给过的更深的目录也不会在对话框里丢掉。`jobs` 把「扫描」「录制运行」两个按钮变成 `python -u -m codestrata scan|trace …` 子进程（`_cli`，jobs.py:29），和在终端里敲的只差一个让输出不缓冲的 `-u`，run 里记的复刻命令就是终端里那条：扫描带着勾选的 --roots（`scan_argv`），录制表单的「执行目录」变成 --cwd（相对路径按仓库根目录算，和命令行一致）。`app` 收到扫描请求时再查一遍：至少勾一个、都在候选里、没有同名或一个套一个的（app.py:294 起，最后一道是 `check_roots`，app.py:299），页面上的勾选框挡不住手改的请求；`viewers` 给每个打开的仓库起一个 `codestrata serve <repo> --port N --home <主菜单地址>` 子进程（viewers.py:107）。这两处和 `__main__._prog` 的退路都用包里的 `self_command`（codestrata/__init__.py:5）拼「用当前这个 Python 跑 codestrata」，这个前缀只写在一处。`app` 只做 HTTP（路由、鉴权、JSON）和装配，「扫描成功就在原端口重启这个仓库的 serve」这根线是它在 `make_app` 里用 `on_done` 回调接上的（app.py:353），`jobs` 和 `viewers` 互相不认识。回调在任务标成结束之前跑（jobs.py:256），重启算在扫描任务里：页面看到扫描「完成」时图服务已经换好，重启失败的原因写进这个任务的输出（app.py:111）。打开的图还是第 4 步那个一个进程服务一个仓库的 serve，只多了 --home 和 /api/app：页面经 ds.js 的 home() 取到主菜单地址（codestrata/web/ds.js:107），在标题前放一个「← 主菜单」。「打开图」给的地址是 /v/<端口>/：主菜单把这个前缀下的请求转发给自己起的图服务（`AppHandler._view`，app.py:155，只认 `Viewers.serves` 说是自己的端口），远程时 ssh 只转主菜单一个端口；前端的接口地址因此都写成相对的。

events/spans/ 只有 `seq` 读（经 serve），`payload` 不读它。导出版也不带：`export_payload` 不算时序，导出版的数据源对时序图请求直接报错（codestrata/web/ds.js:64），站点版的 linkedDs 不替换这几样，同样报错。

`__main__` 大体只做分派，自己串的只有两段：scan 之后接着建交叉引用；trace 时把 `runs` 和 `trace` 缝在一起（--events 也只是在这里定一个环境变量，再记进 run 的录制参数，重录命令据此带上它；执行目录、默认的 roots 同样在这里定好，再交给两边）。`cmd_runs` 里放的是参数校验、删除前确认这类 CLI 的事，run 的规则都在 `runs` 里；`cmd_graph` 同理，只查 --hot 有没有空值（脚本里的变量没设）、去掉写了两遍的、--compare 有没有第二个 run，嵌哪些、怎么嵌都在 `export_payload` 里；--link 时再查给了 --out、不是 .html 文件名，其余交给 `site.export_site`，只打印它返回的摘要。时序图这一路是 `serve` 在缝：它经 `runs` 找 run、再把目录交给 `seq`，`seq` 自己不认识 `runs`。

## 为什么分成这几层
依据是真实的 import 图：默认切面上 20 个节点、48 条依赖（函数里的 import 也算，`if TYPE_CHECKING:` 里的不算：运行时不执行，index 另记成 `type_edges`，不进高度；codestrata 自己没有这种 import），空的包初始化文件不画（codestrata/__init__.py 现在放着 `self_command`，不空了，所以画出来）。高度是 `(出 − 入) / (出 + 入)`，出、入按 import 语句条数加权：
- **入口**（+1）：`__main__`，一层薄 CLI，出边 12 条（主菜单加了 `app`，`_prog` 的退路又加了指向包初始化文件的一条）。
- **中间**（+0.75 / +0.5 / +0.43 / +0.17 / 0）：`app`、`jobs` / `site` / `projects` / `seq`、`serve`、`payload`、`viewers`。`payload` 是模块图的汇合点，唯一同时认识事实、runtime、坐标、源码、交叉引用、解读的模块，依赖 `cut`、`highlight`、`layout`、`notes`、`runs`、`xref`；它不直接读 `trace` 的产物，runtime 一律经 `runs` 取。两个 run 的对比也算在这里（M7 没有新增模块，也没有新增依赖）。它有 `serve`、`site`、`projects`、`app`、`__main__` 五个上游（主菜单的两个只为读 index 的摘要、落后几个文件和符号表），M8.1 的 `publicize` 又在函数里 import 了 `runs._q`（payload.py:1034），`payload` → `runs` 这条边记 2，所以只有 +0.17。`serve` 管 HTTP 协议、安全边界和进程内缓存，出边 5 条（`cut`、`notes`、`payload`、`runs`、`seq`）：换 run 的下拉列表要 `runs.catalog`，每个请求要 `runs.resolve` 和 `runs.load`，时序图经它交给 `seq`；上游是 `__main__` 和借它 `BaseHandler` 的 `app`（app.py:51）。`site`（M8.2）出边 3 条（`payload`、`render`、`highlight`），只被 `__main__` 在 `cmd_graph` 里 import。它不另算图、边详情和交叉引用，全从 `payload` 取（引用倒排用 `payload._inverted`，和 serve 的 /api/refs 是同一份），HTML 仍由 `render` 拼；`highlight` 只用来认语言、给非 Python 文件出大纲（site.py:168），高亮本身挪到了浏览器里。`seq` 出边 3 条：`cut`（文件落在切面的哪个节点上、节点的高度）、M8 在函数里 import 的 `runs`（见下面「`seq` 和 `events` 之间只隔一个文件格式」），以及 `trace`：「文件:首行 → 符号」的对照表 `sym_locs` 和模块图的叠加共用一份（seq.py:129），装饰器行、property 的 setter 这类同名的另几个 def 两张图才认成同一个函数；哪些帧是定义、不是调用，也用模块图那一个 `defining`（seq.py:134）。主菜单的四个模块都在这一层：`app` 出边 7 条，三个服务 `projects`、`jobs`、`viewers`，外加 `payload`（读符号表给 --phase 检查）、`runs`（复刻时找 run）、`scan`（起扫描任务前查同名和嵌套，`check_roots`）、`serve`；`jobs`、`projects`、`viewers` 都只被 `app` 用。`jobs` 依赖 `runs`（case 名规则、秒数写进命令行的写法 `fmt_seconds`）和 `trace`（阶段规则 `resolve_phase_at`），表单检查不另写一套规则，再加上包里的 `self_command`。`projects` 依赖 `payload`、`runs` 和 `scan`，.codestrata/ 里的文件一个都不自己解析，能扫哪些目录也照 `scan` 的规则列。`viewers` 在这一层的最底下（0）：它 import 的只有 `self_command` 这一个函数，一进一出，见下面叶子里包初始化文件那一条。
- **中间偏下**：`notes`（−0.5）、`scan` / `trace` / `runs`（−0.6）。`scan`、`seq`、`notes` 都有一条出边指向 `cut`：问目录树怎么切。`scan` 有 4 个上游：`__main__`、`trace`（`trace --phase` 的「文件路径:qualname」写法要和 scan 下潜同一批语句去找函数，在函数里 import 了 `scan._STMT_CONTAINERS`，trace.py:1127），以及主菜单的 `projects`、`app`（候选目录、同名和嵌套检查）。`trace` 唯一的出边就是指向 `scan` 的那一条，上游也是 4 个：`runs`、`__main__`、`jobs`、`seq`。`runs` 依赖 `trace`（合并分片、折算叠加）和 `events`（整理 span），被 `payload`、`serve`、`seq`、`__main__`、`app`、`jobs`、`projects` 使用，一共 7 个上游。
- **叶子**（−1）：`cut`、`events`、`layout`、`highlight`、`render`、`xref`，外加包初始化文件 `codestrata/__init__.py`，每个只做一件事，彼此不 import。「叶子」的意思是被依赖、不依赖别人，不是「不重要」：数据的生产者 `events`、`xref`，决定图上显示哪一层的 `cut` 都在这一层。`cut` 被 6 个模块依赖，叶子里最多（全仓最多的是上面的 `runs`）。`xref` 近 1400 行，仅次于 `trace`，它只吃 scan 给的 index 这个 dict，不 import `scan`，所以也是叶子；`events` 同理，只吃一串日志文件、run 的起点时刻和一个输出目录，不 import `trace` 也不 import `runs`。`highlight` 和 `render` 现在各有两个上游（`payload` / `__main__`，外加 `site`）。包初始化文件是主菜单带来的叶子：里面只有 `self_command`（codestrata/__init__.py:5），拼「用当前这个 Python 跑 codestrata」的命令行，codestrata 装在哪个环境里，子进程就在哪个环境里跑。它有 `__main__`、`jobs`、`viewers` 三个上游，以前是三处各写一份。三个用户分属入口、任务、图服务，彼此不 import，放在包本身，谁都不用为这一行去认识别人。`viewers` 因此不再是叶子，但和 serve 之间仍只隔一条命令行（`serve <repo> --port N --home URL`）。

最值得注意的几条边界：
- **录 vs 存。** `trace` 不 import `runs`（它唯一的出边是 M8 指向 `scan` 的那一条）。`trace.run` 只接收一个 parts 目录和一个 `after` 回调，不知道 run.json 长什么样。之所以用回调，而不是返回之后再收尾，是因为 driver 的信号处理器要一直装到收尾做完：`after` 在 `run` 的 try 里面调用（trace.py:1046），打包中途按 Ctrl+C 才不会留下半截的 run。反过来，写 run、删 run 的代码全在 `runs` 里（`events` 只往 `runs` 交给它的 events/spans/ 里写派生的 span）：除了 `runs.remove` 和 `runs.remove_events`，没有代码会删 run 里的原始数据，审这一个文件就能确认。`seq` 只读不写。
- **可重建 vs 不可重建。** 以前整个 `.codestrata/` 都是缓存；M1 之后分成两半，index / symbols / xref 随时删了重建，runs/ 删了就没了。误删有几道防线：`_outdir` 往 .codestrata/ 里写一份 README.txt（`_README`，__main__.py:37），写明除 runs/ 以外都能删；runs/ 可以是指到别的盘的软链，rm -rf .codestrata 只删链接本身；scan 跳过以点开头的目录（`scan._skip_dir`，scan.py:135），不碰 runs/。解读放在 notes/，进版本库，靠 `code_sha`（整份是否过期）和引用指纹（哪一处 file:line 漂了）和代码绑在一起。
- **原始 vs 派生**（run 内部）。合并逻辑还不成熟，以后还会改，所以原始分片（parts.tar.gz）永久保留，计数（counts.json.gz）只算派生数据，runs merge 能重算。时序事件照同一个办法：原始日志（events/raw.tar.gz）永久保留，span 是派生的。收尾时先落包、再整理（runs.py:446 在 runs.py:447 之前），整理抛了异常只在 run.json 的 events 摘要里记一个 error；事件到了行数上限也只标 truncated。两种情况都不改 status，因为计数是完整的，拿 case 名解析时不该因此跳到更早的一次。录制时才拿得到的东西（执行时的文件哈希、脚本和配置的副本、GPU、git 改动）只写一次，重算时不拿「现在的样子」去盖。
- **录制时只记 → 收尾时整理一次 → 看的时候现算**（时序事件分三段）。hook 跑在被 trace 的程序里，每次跨文件调用都要付它的开销，所以它只做最少的事：调用时给一个 span 号，返回、挂起、恢复时按帧找回同一个号写出去。配对、深度、父子关系、第一级折叠都放在 `events` 里事后做（落盘被打断时 hook 只保证不丢，重试写重的行也由 `events.pair` 跳过），算法改了不用重录，runs merge 从原始日志重建即可（`events.build` 的输出是确定的，重建结果和收尾时一样）。按 span 号而不是按栈配对，是因为同一线程上交错执行的 asyncio 协程，先开始的不一定先结束。这一段的产出和切面无关，所以只做一次、写盘。映射到节点、画不画、折不折循环都和切面有关（展开一个包，同一个 span 可能从「节点内部」变成一条消息），所以放在 `seq` 里每次请求现算、不写盘，只在内存里缓存和切面无关的解压块、概览，以及 (index, 切面) → 映射表。
- **`seq` 和 `events` 之间只隔一个文件格式。** `seq` 不 import `events`；对 `runs` 只有 M8 加的一处函数里的 import，借 `_redact_argv` 把时序图上进程命令行里的密钥隐去（seq.py:425，和 `runs.load` 同一套规则）；对 `trace` 只借「文件:首行 → 符号」的对照表 `sym_locs` 和定义帧的判断 `defining`，不碰录制。run 的目录、run.json、detail.json 仍由 `serve` 经 `runs.resolve` 找好交给它，span 直接从 spans/ 的文件读。这样 `events` 仍是叶子，`seq` 不碰 run 的存取，测试能直接调 `seq.build`、不用起 HTTP。代价是 spans/ 的格式两边各认一份：`events.read_spans`（events.py:230）一次读回全部块，现在只有测试在用；`seq` 另写了按时间窗挑块、解压过的块进 LRU 的 `spans_in`（seq.py:86）。格式要改时两边都得跟着改，兜底的是 test_seq_* 用真录出来的 span 跑（test_seq_build 还核对「画出的消息 + 三类不画的」次数等于全部 span 的次数）。
- **数据 vs 呈现。** `payload` 和 `seq` 都不知道 HTTP 和 HTML；`serve` 只解析参数、把阶段换算成时间窗。模块图这边，`serve`、`render` 和 `site` 共用同一个 `payload`，所以 live 模式和两种导出版不会各长各的。链接导出把几件服务端的事挪进了浏览器。源码高亮由 `web/hl.js` 做（Pygments 词法状态表的移植），不各长各的靠 `tests/hl_parity.py` 拿它和 `highlight` 对拍：每行文本逐字符一致，token 类按字符比，一致率 Python ≥ 95%、C/C++/CUDA ≥ 85%。引用列表的合并和排序、符号片段从定义那一行起切 40 行，也在 linkedDs 里照 `payload.refs` 和 /api/symbol 另写了一份，这两样没有对拍。仅类型的边、撞名节点的别名、调用处是按哪种写法找的，同样由 `payload` 给好，前端只管画和写字。对比也守这一条：[A, B] 两个次数、边详情里 B 的次数都由 `payload` 算好，serve 和导出版拿到的是同一份，前端只管选 B、上色、写数字。对比时不重新排版，节点还在原来的位置上，眼睛只需要看颜色；「只看跑到的」那张单独排版的图放两边任一跑到的节点。搜索放在前端做、名字索引一次给全，也是为了这一条：导出版没有服务端，照样能搜。时序图是例外：它只在 serve 里有，导出版不嵌时序事件（设计稿第 8 节）。
- **记录的粒度 vs 显示的层级。** `scan` 只记最细的一层（每个文件一个模块），图上显示哪一层由 `cut` 在目录树上取切面决定。所以展开 / 收起不用重扫，解读的过期判定、run 的叠加和时序事件（键是「文件:首行号」）也都和图上怎么切无关。时序图的生命线同样是现映射出来的，所以在时序图的目录生命线上点 ＋，和在模块图上展开是同一个动作，两张图一起细到子模块。展开的目录画成框，但纵轴仍是架构高度，框只能在横向上占一段列（见 `layout` 的解读），不能为了把子模块归到一起让纵轴说谎。
- **依赖和调用。** 图上的实线要说「运行时真的依赖」，橙色要说「真的调到了」，所以两侧各有几样看着像、却要分出去的东西。静态一侧，`if TYPE_CHECKING:` 里的 import 运行时不执行：早先它和普通 import 一样算边，`from __future__ import annotations` 下标注里的名字又被当成「用到了」，图上凭空多一条实线回边、高度也被带偏。现在 `scan` 把它记进 `type_edges`，不进高度；切面上两端之间没有运行时 import 的，`payload` 单独给出，前端画成「仅类型」，默认关着、不画也不占接点，点开时边详情直接展开那几条 import。runtime 一侧，import 时的模块顶层、class 语句执行的类体、3.12 泛型定义时的 `<generic parameters of …>` 帧都是定义，不是调用（模块级的 `defining`，trace.py:1435，`to_package_graph` 和时序图的 `seq` 共用）：不计入符号的次数，不把 import 边染成橙色，只被 import 过的模块、只定义过的类不算「跑到了」。它按行号认（类体的帧正好落在类符号那一行），已经录好的老 run 加载时一样分得出来。case 自己的代码是第三种：仓库外、入口脚本那一层目录里的 .py（执行目录在仓库外时，还有经 CODESTRATA_CASE_DIRS 传进来的那一层；仓库里的 examples/ 本来就是仓库帧）不在 index 里、不计数、从不当被调方，但在栈上当调用方，记成「<外部代码>/文件:行」（`_case_rel`，trace.py:99）。否则 case 里定义、被仓库回调的函数（Flask 的视图）再调仓库函数时，调用方会落到最近的仓库帧上，画出 dispatch_request → jsonify 这种并不存在的动态分派边。标准库、site-packages 这类别的仓库外代码仍然透明。
- **快照 vs 现在的文件。** 事实都是某一刻的快照，源码却随时在改，所以每份快照都自带指纹，对不上时宁可少给、不给错。xref 记下每个文件的大小和修改时间，scan 之后改过的文件不给 Ctrl+点击（`payload._stale`）。run 只存原始键（文件:首行号）和 hook 在执行时取的文件哈希，加载时现映射到当前 index；`runs.file_state` 拿哈希和 index 的 `file_sha` 比，不和工作区比，因为叠加用的行号来自 index。它逐个标出改过、删掉、不在 index 里的文件，而不是让整个 run 作废。改过的文件也不只是标一句「可能偏」：hook 录制时还给每个键记了函数的 qualname，加载时 `runs.remap` 按名字把次数挪到函数现在的行号上（M6），对不上名字的只算到文件上、不算到任何函数上，横幅上报个数。行号是会随编辑变的位置，名字是只有录制时才拿得到的身份，两样都存，读的一侧才有退路。解读有 `code_sha` 和引用指纹。链接导出也守这一条：源码地址钉在提交号上而不是分支名。index 不记提交号，钉的是导出时的 HEAD；和 HEAD 内容不一样的文件随站点带本地版本，所以页面上的源码就是导出时工作区里的样子（--public 没带的除外），scan 之后改过的文件照旧不给 Ctrl+点击。页面取回源码后再按行数核对（导出时按扫描器的口径数好），对不上也不给 Ctrl+点击并说明；data/ 的目录名带着这次数据的哈希，重新部署之后还开着的旧页面取到 404、提示刷新，不会拿新数据的序号去对旧页面的文件表。时序图是这一条里最弱的一环，见「局限」。
- **主菜单在外面，不在里面。** 要在一个页面上管多个仓库，做法不是把 serve 改成多仓库，而是另起一个枢纽进程：`app` 在 `projects` / `jobs` / `viewers` 三个服务上面只做 HTTP，已有的命令一条不改、当子进程跑。依赖因此只朝下：除了 `__main__` 分派到 `app`，没有哪个已有模块 import 这四个，serve 认识的只是一个 --home 字符串。理由各在下游的解读里：serve 的状态挂在 `Handler` 的类属性上（serve.py:467），一个进程只服务一个仓库，index 也只在启动时读一次，所以「读到新 index」就是在原端口重启一次，原样复用比改成多仓库、能热加载省事，一个图服务崩了也不会带倒主菜单（见 viewers 的解读）；任务不在主菜单进程里调函数，是因为 trace 的 driver 要在主线程装信号处理器，而主菜单的请求都在工作线程里，顺带页面上显示的、run 里记的、终端里敲的是同一条命令（页面上的只多一个 `-u`，见 jobs 的解读）。serve 这一侧因此只多了 `--home` 和 /api/app，挑端口、等到能连上、重启、退出清场这些进程管理的活全落在 `viewers` 里。
- **主菜单的安全边界。** 主菜单是整个 codestrata 里唯一能在本机执行任意命令的网络入口（录制表单里的命令原样放到 trace 的 `--` 后面），所以只听 127.0.0.1、查 Host 头防 DNS rebinding，/api/ 要带口令 cookie（SameSite=Strict、HttpOnly；口令存在配置目录下 0600 的文件里，用启动时打印的 /?t= 链接设一次）和必带的 X-Codestrata 头（不回 CORS，跨源页面过不了预检），扫描、录制、打开图只认清单里的项目（app.py:22 起的 docstring，每道检查挡哪一类来源见 app 的解读）。其中 Host 检查是和 serve 共用的 `BaseHandler._host_ok`（serve.py:129），serve 不管是谁起的都查。自定义头现在也是 serve 定义、两边共用的（`HEADER`，serve.py:57）：光查 Host 挡不住别的网页用 `<img src>` 发来的简单 GET（写解读的 PUT 跨源要过预检，本来就发不过来），所以 serve 上会起编辑器的 GET /api/open 也要带它（serve.py:416），/code 页面上的「在编辑器打开」照样带上。口令 cookie 只护着主菜单自己，它起的 serve 和命令行起的一样没有口令（见 serve 的解读）。Host 检查按「主机:端口」整串比，--port 80 时浏览器发的 Host 不带端口号，请求会被一律挡成 403。

图上看不到的一块是前端，在 `codestrata/web/`（七个 JS 文件，外加只在链接导出里带上的 hl.js，零构建；主菜单是另一页，有自己的 home.html / home.css / home.js，只借用 app.css，不用图页面的脚本，三个对话框分别挑文件夹、勾要扫的目录、填录制表单），不是 Python，所以不在图里。整页是一个应用：上面一条标题和开关，图铺满其余空间，搜索栏（右上）和详情栏（下沿）半透明地浮在图上，全文窗口负责 Ctrl+点击。边的图例里「仅类型」默认没按下，打开它整张图重画（关着时这类边不占节点上的接点）；选中节点时只留亮经看得见的边连着的节点。工具栏的「运行」在静态图和录下的各个 run（及其阶段）之间切换，选中的 run 以完整 id 写进地址栏的 #run=，刷新后还是同一次录制；serve 开着时新录的 run，回到页面就在按钮上加个点，不自动切过去。叠了 run 时，统计那一行多一个 hot 标记，点开「?」写明用的是哪个 run，录得不完整时列出原因；工具栏还多一组「模块图 | 时序图」，这个 run 没录事件时「时序图」是灰的；列表里不止一个 run 时还有「对比」，选中的 B 同样以完整 id 写进地址栏的 cmp=。B 的阶段跟着 A 走：A 看某个阶段、B 也有同名阶段就比它，没有就比 B 的全部，否则比出来的差别大半是阶段不同造成的。对比时帮助里多一条横幅说明 A、B 各是哪次录制，边的开关那一行换成三色图例；两个 run 一个录了时序事件、一个没录时提醒一句次数不完全可比（录事件本身有开销）。导出版里「运行」只列导出时带上的那几个，对比是 --compare 定好的，只显示、不能换；链接导出的全文窗口里，GitHub 上有的文件多一个「GitHub ↗」，本地版本、取回来行数对不上的文件各有一句提示，--public 没带源码的文件说明为什么没带。两张图共用一个图框、同一时刻只显示一张，时序图不另存状态：切面借模块图的 open，选中借模块图的 sel / selEdge。点生命线头就是选中这个模块，点一条消息就是选中这条边，抽屉、搜索、地址栏（多一个 view=seq）都不用知道有第二张图。结构见 render 的解读。

## 阅读顺序
1. **scan**：先弄清「事实」是什么。读完能回答：图上每个框、每个箭头、每条虚线从哪来；扫的是哪些目录、由谁定，为什么同名的两个目录不能一起扫。
2. **cut**：文件级的事实怎么变成图上的节点。读完能回答：为什么默认拆开的是这几个目录，点「＋」时发生了什么，一个节点被哪个框套着。
3. **layout**：节点和框怎么变成坐标。读完能回答：为什么这个节点在这条泳道、这个位置，为什么展开一个无关的目录时别的框不会换位置。
4. **payload**，重点看 `edge_detail`：点开一个箭头看到的每一项从哪来，调用方里调它的那一行是按哪种写法找到的（名字、.属性、语法）；再看 `edge_compare` 和 cmp 块，对比时每个数是哪个 run 的。顺带看搜索索引和交叉引用的缓存。
5. **serve**，以及 render 解读里的前端结构：数据怎么送进浏览器，换 run 时哪些请求带上它、缓存怎么失效，对比的 run 出问题时为什么只叠 A，搜索和「露出某个模块」怎么走，导出版少了什么、多带的几个 run 能切到什么程度。再看 **site**（链接导出，对照它的模块说明和设计稿 M8.2）：读完能回答 data/ 里每样东西是什么、页面什么时候取，源码从哪取、取回来行数对不上怎么办，哪些文件随站点带上本地版本。
6. **trace**：runtime 那一半的录制，也是最难的一块（多进程、exec、调用栈、落盘串行、三级停和残留进程，以及时序事件的记录）。读完能回答：橙色是怎么来的，可信到什么程度，哪些情况下会丢数据；哪些帧是定义不是调用，case 自己的代码为什么在栈上、却不上图；命令在哪个目录跑。行为对照 `tests/test_runs.py` 看，它在 CPU 假服务上跑。
7. **runs**，配合 `__main__` 的 `cmd_trace` 和 `cmd_runs`：录下的东西怎么存、怎么再叠回图上。读完能回答：一个 run 里哪些是原始数据、哪些能重算；--hot 某个case名 解析到哪一次录制；代码改了以后哪些文件上的叠加要按函数名挪（`runs.remap`）、挪不动的算到哪里；老的 trace-<case>.json 怎么迁进来。
8. **events**：时序事件从原始日志到 span，对着 `tests/trace_cases/fake_repo/fakesvc/truth.py` 的场景读。读完能回答：一次跨文件调用在时序数据里是哪一行，交错执行的协程为什么配得对，rep 合并的是什么、为什么按 (父 span, 段) 认兄弟。
9. **seq**，配合 `serve` 的 `Handler._seq` 和 render 解读里「两张图共用一个图框」「时序图的画法」两节：span 怎么变成当前切面上的一屏时序图。读完能回答：一条 span 为什么没画成消息（节点内部 / 定义时的执行 / index 之外），切面一变同一段时间的图为什么跟着变，一屏为什么停在那里（300 行、同一微秒不拆到两屏、too_dense 和建议窗口），loop 行是怎么折出来的，「在时序图里看」跳到的是哪一次。对照 test_seq_* 读。
10. **xref**：Ctrl+点击背后的静态解析，包括再导出、作用域、C3 MRO。量大（函数最多），但和图本身无关，跳过它不影响读懂图。读完能回答：一个名字为什么能跳或不能跳，「同名的 .xxx」那一组是什么。
11. **notes**：解读层自己怎么运作，包括过期、派活顺序、机器核对。
12. **主菜单**：先读 projects 解读的「为什么这样切」弄清四块怎么分，再按 `jobs` → `viewers` → `app` 读，前面几步读过的 serve、trace、runs 在这里只作为子进程和被调的函数出现。读完能回答：点一个按钮之后起的是哪条命令、输出怎么一行行到页面上；扫描对话框里的候选目录和预先勾上的从哪来；为什么扫描完图服务要重启、开着的图标签为什么刷新一下就行；一个请求要过哪几道检查才起得了任务。行为对照 `tests/test_app.py` 看。
13. **highlight** 和 `__main__` 的其余部分，需要时再看。

## 局限
- `docs/design/runs.md` 的 M1–M8.2 都做完了（M2 随 M1 一起），但都是在 CPU 数据上验收的：CPU 假服务、codestrata 自己的 case，M5 另加合成的 vllm 规模数据（44 万次调用、5 个进程、180 s）。要用 GPU 录的几件都还在等用户同意：M1 的 GPU 终验（录一次真的 minicpmo，第一个字段齐全的 run）、M3 的事件开销实测（所以现在默认不录，要加 --events）、M5 在真 vllm 录制上的表现、M7 的 MiniCPM@serving 对比 Qwen@serving（Qwen 还没录）。被 trace 的解释器还得是 3.12+ 才录得到事件（要 `sys.monitoring`）。
- 自动测试只覆盖服务端：test_seq_* 直接调 `seq`，其中 test_seq_find_and_api 走真的 serve；test_remap_moved_functions 测按函数名挪行号；test_compare_and_multi_export 直接调 `graph_payload` 和 `edge_compare` 核对 [A, B] 次数，跑一遍多 run 导出，再经真的 serve 核对对比的 run 找不到、就是 A 自己时只叠 A。最近这一批（--cwd、trace 沿用 scan 的 roots、定义帧、case 代码当调用方、按语法找调用处、变量和再导出的「to」、仅类型、撞名）在 `tests/test_runs.py` 里各有一个到两个测试，从 test_trace_cwd 到 test_duplicate_short_labels。主菜单由 `tests/test_app.py` 的 9 个测试覆盖：test_registry、test_status_browse_symbols、test_scan_roots、test_candidate_roots_layouts、test_trace_spec、test_job_manager 直接调服务层（看状态不在仓库里建目录、runs/ 悬空时卡片报错不出错、symbols.json 写了一半时补全给空、候选目录只列不挑并带上上次的选择、嵌套工程和环境目录、同名的根被拒、复刻带上 tags / roots / stop_grace / 执行目录、回调在任务结束之前跑并能往输出里写一行）；test_app_http 起真的主菜单走 HTTP，核对几种 403（包括非 ASCII 口令、排在前面的格式古怪的别家 cookie）、扫描没勾目录或勾了候选之外的 400、同一个仓库第二个任务的 409（有任务在跑时先回 409，不读索引），以及它起的 serve（打开图、Host 不对 403、扫描后在原端口读到新 index、移除后端口不再有人监听）；test_serve_guard_and_home 直接起 serve，查 Host、`/api/app`、PUT 的请求体，以及不带自定义头的 /api/open 被挡、/code 页面带着这个头；test_cli_app 起真的 `codestrata app` 进程，核对口令文件只有自己能读、SIGTERM 时正常退出并收掉它起的 serve。前端没有自动测试：M4 的换 run 靠设计稿里记的浏览器验收，M5 的视图切换、两张图之间的选中和切面同步，M7 的对比按钮、三种颜色、地址里的 cmp=、导出版里切换 run，也一样没有测试（M7 的配色是在 codestrata 自己的两次录制上，按明暗两种主题人工核对的）；主菜单的页面（home.js，包括扫描的勾选框）、图页面上的「← 主菜单」链接、「仅类型」开关和面板上「按哪种写法找的 / 为什么没找到」的说法同样没有。
- M6 只改了模块图的叠加，时序图没跟着改：录制之后挪过行的函数，时序图里消息落在哪两条生命线上不受影响（那只看文件），但名字仍按旧行号现查（`seq` 不调 `runs.remap`）：旧行号正好是别的函数的首行，就显示成那个函数；否则显示成包住那一行的外层符号「外层名.<L行号>」。时序图自己也不标哪些文件在录制之后改过（`seq` 不看文件哈希），只能靠统计那一行的 hot 标记和运行列表里的提示。
- 链接导出只认 origin 在 github.com 上、提交已经推上去的仓库（导出时试取一个文件，全 404 就拒绝）；页面要放在 http(s) 上看，file:// 下浏览器不许按需取 data/；看的时候要连得上 jsDelivr 或 raw.githubusercontent.com。Python 一侧有 test_site_export* 三个测试，hl.js 和 Pygments 的一致由 tests/hl_parity.py 对拍（要 node，不在测试集里）；页面上的取数、退路和各种提示同样没有自动测试，设计稿 M8.2 记的是浏览器里做的变异检查。
- 最近这一批的几条判定都只看写法和目录，不做推断：调用处按语法找时不知道是哪个对象的特殊方法（一行上有 `x[i]`，调到的 `__getitem__` 未必是 x 的），也只认得出写在明面上的记号；写法里根本没有记号的（对象(…) 调 `__call__`、取不存在的属性调 `__getattr__`）只找显式写了名字的那几行；case 的代码只认入口脚本（或 --cwd 在仓库外时的执行目录）那一层里的 .py，子目录里的辅助模块仍然透明；主菜单的扫描对话框只列子目录，直接放在仓库根目录下的 .py 选不到（页面上照实说）。
- 对比只有两路（设计稿第 10 节：不做 N 路对比），只在模块图上；时序图、引用列表、输入包都只看 A。
- 导出版（graph，单文件和 --link 站点都是）是固定切面，没有时序图。带了几个 run 时能在它们之间切，但只有第一个（主 run）带着边详情里的调用明细，切到别的 run 时边详情只剩静态引用；对比是导出时 --compare 定好的前两个，页面上不能换。serve 的 index 只在启动时读一次，重新 scan 之后图、搜索栏和时序图的映射都要重启才更新（xref 按修改时间自动换新，所以这时 Ctrl+点击已经是新的）；index 落后于代码时只在启动横幅里提示一句，serve 开着时再改就没有提示。新录的 run 则不用重启。从主菜单扫描的，主菜单会在原端口替人重启（重启失败的原因写在这次扫描任务的输出里，见 viewers 的解读）；主菜单的项目卡片每次刷新也数一遍落后了几个文件，和启动横幅用的是同一个 `payload.index_lag`（payload.py:895）。
- 主菜单的已知缺口记在各模块的解读里，这里只点名：口令会出现在启动浏览器的命令行里、Host 检查要带端口号所以 --port 80 用不了（app）；主菜单退出时给还在跑的录制 120 秒收尾（jobs.py:275），录制设了更长的 --stop-grace 或者收尾特别慢时，仍可能留下还在跑的服务和不完整的 run（jobs）；主菜单被 SIGKILL 时 `stop_all` 不会跑，它起的任务和 serve 都没人收（jobs、viewers）。

## 不确定
- 设计稿 M5a 的验收是接口在 300 ms 内返回；记下的冷启动是 450 ms、热的 20 ms，都是在合成数据上测的。真 GPU 数据上自动收窄够不够快、贪心折叠折得好不好，要等真的 vllm 录制出来才知道（细节见 seq 的解读）。
- 事件开销没实测，所以还不知道 --events 能不能默认打开（设计稿 M3 的「开销实测」和第 11 节）。
- 三种颜色在两个真模型的 run 上够不够用还不知道：MiniCPM 和 Qwen 共用 vllm 的主干，图上可能大片是前景色、差别只落在少数几个节点上，这时颜色只说明「两边都跑到」，次数差多少要看节点上的「A/B」和边详情。要等 Qwen 录好，按设计稿 M7 的验收实际比一次。
